# pitchlog ハーネス運用評価台帳 — 開発ハーネスを実際に回して分かったこと

| 版 | 日付 | 変更内容 | 状態 |

| 1.0 | 2026-08-12 | **新設(起案)**: 様式の確定(`H-*` 連番・記載要素 8 点・分類 3 種・`追跡優先度` の 3 分割)+ 運用規則 + 追記導線。起票内容は本タスクのステップ 2〜5 で記入する。計画: `../features/harness-evaluation/plan.md` | draft |

> **目的**: 本プロジェクトで開発ハーネス(`dev-harness-design-2026-08-07.md`)を実際に回して分かった**摩擦点と、機能した点**を蓄積する台帳。**1 タスクの worklog には詳細が残るが、横断的な傾向は残らない** — どのゲートが空振りし、どこで周回が伸び、どの機構が実際に効いたかは複数タスクを並べないと見えない。
> **改善台帳(`../improvements-from-baseball-scoring.md`)との違い**: あちらは**プロダクト**が旧システムから何を改善するかの台帳(I-1〜I-27 のすべてがプロダクト事項)。本書は**ハーネス自身**を対象とする(7.1-1「1 テーマ 1 正本」)。
> **項番 `H-*`**: harness evaluation の項番。レビュー重大度の `P0/P1/P2` や非機能要件の `P-1`・`A-1` 等とは無関係の別体系。
> **番号は追記のみ** — 振り直さない。**欠番も再利用しない**。他文書に `H-1〜H-N` の上限を書かない(追記で腐るため。設計書 v1.4 で `decision-tracer` の番号上限を撤去したのと同じ規律)。
> **版は「様式の版」**: 本書の版は**記載要素・運用規則・分類の版**を表す。**`H-*` の追記では版を上げず**、変更履歴表に 1 行追記する(**7.6-3 前段 = PR レビューで足りる**)。**記載要素・運用規則・分類そのものを変えるときだけ版を繰り上げ、7.3 の確定ゲートを通す**。※ 同一版に複数行が並ぶこと自体は要件書 v1.8(`../requirements/requirements-pitchlog-2026-07-22.md`)に先例があるが、**あの先例は「版列が一意キーでない」ことの例に限る** — v1.8 の 2 行目は「frontmatter 追加・本文の内容変更なし」であり、`H-*` 追記(実質的な内容追加)とは性質が異なる。
> **追記導線(2 経路)**:
> - **主経路 = `/pr` のクローズ処理**。**PR 作成者**が、クローズ処理の**最終コミットを作る前**に追記の有無を判断する。該当するなら同一 PR で **① 計画書 3 節へ宣言を先に追記 → ② 本書へ `H-*` を追記 ③ 本書の変更履歴表に 1 行 ④ 索引の最終更新日を現行化**(②〜④ は同一コミット)。**該当しないなら「台帳への追記なし」と理由を worklog に残す**(忘れたのか判断したのかを区別できるようにする)。
> - **`/task-done` では本書を編集しない**。`/task-done` は PR マージ後に develop 上で走るため、そこから正本を編集すると絶対規則 1(main/develop へ直接コミットしない)に反する。**マージ後に気づいた知見は follow-up タスクを起票**し、次の `/task-start` で別 feature/PR として追記する。
> **記載要素**(8 点・全項目必須): `分類` / `検出日`(出典を括弧で併記) / `事象`(**典拠必須** — `ファイル:行`) / `再発`(横断で数えられるもののみ・単発は 1 件) / `なぜ問題か`(**機能した点は「観測事実・根拠・限界」を併記**し「有効性の証明」と書かない) / `追跡優先度` / `対応案` / `状態`。
> **`追跡優先度`**: **高 / 通常**の 2 値。**高** は `対応案` に **follow-up の F-ID + worklog への相対リンク、または日付つき PO 見送り裁定が必須**(「未対応」と書くだけで放流しない)。判定条件が評価できないもの(**制御目的の典拠が示せないもの**)は `H-*` を与えず末尾の `## 候補` へ置く。**判定条件の正は `../features/harness-evaluation/design.md` 1 節**。
> **`対応案` に Notion URL を書かない**(設計書 7.4「正本は Notion を参照しない — Git 単独で完結」)。**URL は非正本の worklog 側**に記録し、本書からは **F-ID と worklog への相対リンク**だけを張る。
> **`状態`**: 未対応 / 対応中 / 対応済み / **見送り**(見送りは**理由と裁定日**を必須)。
