# 製品 RLS の実スキーマ適用と再実行の運用

## 位置づけ

[`data-model.md`](../design/data-model.md) **12-4 節**の越境テスト再実行ゲートを実行するときの、**実環境側の運用手順**である。
ゲートの定義・通過条件・判定の記録様式は同節が正であり、本書は**複製しない**。

本書が定めるのは**誰が・どの対象に対して・どの順で操作し、失敗したらどうするか**だけである。

### 12-4 の判定との関係(未確定の間の扱い)

**12-4 の「実スキーマ」の正本上の意味は確定していない**(確定は別タスクの射程 — 下記)。
そのあいだ、本手順の実行結果は次のように扱う。

| 扱う | 扱わない |
| --- | --- |
| **本手順が対象とした対象に対する実測**として、何を・どの対象に対して・いつ実行し、結果がどうだったかを記録する | **その実測をもって 12-4 の通過条件①②を満たしたと判定すること** |

**判定記録には「どの対象に対する実測か」を書く。** その対象が 12-4 の「実スキーマ」に当たるかどうかは
**12-4 側の判断**であり、本書では決めない。**実行結果の記録と、ゲート通過の判定は別である。**

### 射程宣言

**本書で確定する範囲**:

1. **適用主体**の要件(何を満たす主体が適用してよいか)
2. **対象の識別**(何を対象と認めるか)と**撤去・作り直し**の順序
3. **破壊の前に他の利用者がいないことを確かめる**検査と、0 件でなかったときの扱い
4. **失敗時の扱い**(再開のしかた)

> **射程縮小 2026-10-03(PO 裁定・山田正輝)**: 3 は当初「**遮断の始期・終期**」を、4 は「**serving へ戻さない**扱い」を含んでいた。
> **どちらも削った** — 対象は専用クラスタで本手順以外に利用者がおらず、**守るべき serving が存在しない**ため(3 節冒頭に理由)。

**本書で確定しない範囲**(**決定先ごとに分ける**):

| 群 | 事項 | 決定先 |
| --- | --- | --- |
| **① 実装時に確定する** | 自動化の構造(実行器の分割・観測の手段)/ 識別値の具体的な書式 / 検査の実行コマンド | 本手順を実装するタスク |
| **② 別の正本が確定する** | **12-4 の「実スキーマ」の正本上の意味** / 最低要求 ④ の現時点での満たし方 | 前者は TSK-382、後者は ④ の注記タスク。**本書は先取りしない** |
| **③ 対象が増えたら本書を改訂する** | 本番配備への適用 / 災害復旧 / 複数対象の運用 / 既存データを保持したままの適用 | 本書(改訂) |

**どの群にも入らないもの**: 接続情報は**本書に書かない**(下記「**接続情報と識別子の扱い**」)。

## 接続情報と識別子の扱い

**[NFR-014](../requirements/requirements-pitchlog-2026-07-22.md)** が **DB接続情報の置き場**を定める。
**本節は同条の運用上の帰結だけを書き、条文を複製しない**(**最終全文確認周 P1 の是正** — 7.1-1)。

**帰結**: **接続情報は、秘密かどうかを問わずリポジトリに置かない**(**5 周目 P1 の是正** — 旧文は
「識別子はリポジトリ内の設定資産・資格情報は環境変数」と切り分けていたが、**ホスト・ポート・データベース名も接続情報である**)。

| 種別 | 置き場 | 本書での扱い |
| --- | --- | --- |
| **接続情報**(ホスト・ポート・データベース名・利用者名・パスワード・DSN 全体) | **環境変数** | **書かない。** 本書は**環境変数の役割**だけを定める |
| **環境変数の名前** | リポジトリ | 既存の資産が持つ名前を使う。**新しい名前を足す場合は実装時に決める**(射程宣言の群 ①) |
| **ロール名を DDL の識別子として置く**(`CREATE ROLE` の対象・`GRANT` の相手) | リポジトリ(`contracts/authz/product/` の DDL 資産) | **接続情報ではない。** 既存資産から読む |
| **同じ名前を接続設定の利用者名として置く** | **環境変数** | **接続情報である**(**6 周目 P1 の是正** — `pitchlog_owner` は DDL の対象でもあり接続の `user` 値でもある。**後者をリポジトリに置かない**) |

**「承認された対象データベース名」も環境変数から来る。** 承認の実体は、**人がその環境変数へ値を置いたこと**である。

**記録へ書いてよいもの**: 実行時刻・結果・判定・ロール名・移行の版・資産の digest・実行の採番。
**記録へ書かないもの**: **接続情報そのもの**(とくに利用者名とパスワード)。
対象を指し示すときは、**対象の要約値**(2-3)を**必ず**書く。環境変数の名前とクラスタ実体の識別値だけでは、
**同じクラスタ・同じ変数名で対象だけを変えた 2 つの実行を区別できない**。

## 1. 適用主体

**適用してよい主体の要件**:

| # | 要件 | 誰が検査するか |
| --- | --- | --- |
| 1 | **superuser であること** | **適用器が接続時の通知から機械で検査する** |
| 2 | **アプリケーション用ロールでないこと** | 同上 |
| 3 | **対象データベースの所有者ロールが、適用の開始時点で存在していること** | **適用器は検査しない。本手順の 2-2 で作る** |

要件 1・2 を満たさない主体で適用しようとすると**適用器が拒否する**ので、人が確認する必要はない。

要件 3 は所有者ロールの資産が作成を含まず変更だけを行うため、**存在しなければ適用が失敗する**。
**2-2 の作り直しに所有者ロールの作成を含める。**

## 2. 対象の識別と撤去・作り直し

### 2-1. 対象と認める条件

次をすべて満たすものだけを対象とする。**1 つでも判定できなければ中止する**(判定不能を成功にしない)。

| # | 条件 | 確かめ方 |
| --- | --- | --- |
| 1 | **専用のデータベースクラスタであること** | **クラスタ実体の識別値**(サーバー自身が持つ、配備ごとに異なる識別子)を読み、**共有の開発用クラスタのそれと一致しないこと**を確かめる。**名前とポートの一致ではクラスタの分離を示せない** — 別の名前・別のポートでも同一クラスタへ到達しうる |
| 2 | 接続したサーバーが**配備定義の実体と一致する**こと | クラスタ実体の識別値を、**配備定義から起動した実体のそれと独立に突き合わせる**。環境変数の値どうしの自己照合にしない |
| 3 | 対象データベース名が**承認された名前と完全に一致する**こと | 部分一致・前方一致で通さない |
| 4 | **共有の開発用データベースでないこと** | **条件 1(クラスタ実体の識別値の不一致)が満たされていれば充足する。** 名前とポートの不一致は**補助の目安であって必須条件ではない**(**8 周目 P1 の是正** — 必須にすると、**別クラスタで DB 名だけが同じ場合に不合格**になり、計画書側の条件と合否が分かれた) |

**条件 1 が最も重い。** ロールはデータベース単位ではなく**クラスタ単位**で存在するため、
**クラスタを取り違えると、別の用途のロールを撤去してしまう。**

### 2-2. 撤去・作り直しの順序

**毎回この順で行う。途中から再開しない。**

| 順 | 行うこと |
| --- | --- |
| 1 | **対象と認める条件(2-1)をすべて確かめ、同じ読み取りから対象識別値を確定する**(2-3) — 通らなければ**ここで中止し、以降を一切実行しない**。**この時点では何も撤去していない** |
| 2 | **他の利用者がいないことを確かめる**(3 節)。**この手順は検査だけで、撤去も作り直しもしない**(4 周目 P1 の是正 — 旧文は 3 節全体を参照しており、3 節の中で撤去・作り直しまで行うと手順 3・4 と二重になった) |
| 3 | **撤去**(2-4) |
| 4 | **作り直し** — 所有者ロールを作り、対象データベースを作り、スキーマ移行を適用する |
| 5 | **適用** — 製品 authz DDL を適用する |
| 6 | **検査と再実行** — カタログ検査と越境テストを実行する |
| 7 | **記録** — 実測を記録する(様式は [`data-model.md`](../design/data-model.md) 12-4 が正。判定の扱いは「位置づけ」節) |

**1 から 7 までを 1 回の連続した実行として行う。** 分けて実行すると、5 で適用した対象が
次の実行の 3 で消えるため、6 が「5 で適用した対象を検査した」ことにならない。

**手順 1 の確認と識別値の確定は、同じ読み取りから行う。**
先に確認して後から別に識別値を採ると、そのあいだに接続先が変わりうる。

**手順 2 以降は、各操作の直前に照合する。一方でも一致しなければ中止する。**

**照合するものは操作の打ち方で変わる**(**3 周目 P0 の是正** — 撤去は対象データベースの中からは打てない)。

| 操作の打ち方 | 照合するもの |
| --- | --- |
| **対象データベースへ接続して行う操作**(移行の適用・製品 authz DDL の適用・検査・越境テスト) | ① **クラスタ実体の識別値** ② **接続中のデータベース名** |
| **管理接続から対象を名指しして行う操作**(対象データベースの撤去・作成、ロールの撤去・作成) | ① **クラスタ実体の識別値** ② **操作に渡す対象の名前**(オペランド)。**接続中のデータベース名ではない** |

**撤去は対象データベースの外から打つ。** 対象へ接続したままでは落とせないし、落とした後は接続できない。
**したがって撤去・作成の照合は、接続先ではなく「何を名指ししたか」に対して行う。**

**両方に当たる操作がある**(**4 周目 P1 の是正**): 越境テストは**対象データベースへ接続したまま一時ロールを作り、撤去する**。
この場合は**両方を照合する** — ① クラスタ実体の識別値 ② 接続中のデータベース名 ③ **ロール名が手順の扱うロール名の集合に含まれること**。
**集合の外のロールを名指しする操作は行わない。**

| 照合に失敗すると起きること | |
| --- | --- |
| クラスタ実体の識別値が違う | 別のクラスタのロールを撤去する |
| 接続中のデータベース名が違う | 別のデータベースへ DDL を適用する |
| **オペランドの名前が違う** | **同じクラスタ内の別のデータベースを撤去する** |

### 2-3. 対象識別値

| 要素 | 取り方 |
| --- | --- |
| **クラスタ実体の識別値** | サーバー自身から読む(配備ごとに異なる識別子) |
| **対象データベース名** | **環境変数から読む**(承認の実体は人がその値を置いたこと) |
| **手順が扱うロール名の集合** | **3 つの経路の和集合**(**6 周目 P0 の是正** — DDL 資産だけだと越境テストが作る一時ロールが落ち、集合外の操作を禁じる規定により**そのテストを実行できなくなる**)。**ロールを名指しする操作のオペランド照合に使う** |
| **実行の採番** | 実行のたびに新しく採る(時刻と乱数) |
| **対象の要約値** | **クラスタ実体の識別値と対象データベース名から導く一方向の要約**。**接続情報の実値を含まない**が、**同じクラスタ・同じ環境変数名で対象だけを変えた 2 つの実行を区別できる**(**6 周目 P1 の是正**) |

**ロール名の集合の 3 つの経路**:

| 経路 | 得られるもの |
| --- | --- |
| `contracts/authz/product/` の DDL 資産 | 製品 authz が作る固定ロール(所有者 / アプリケーション用 / 関数所有用) |
| **越境テストが定義する固定名** | **一時ロール**(テストのソースが定数として持つ) |
| **環境変数の利用者名** | **被検査ロール** |

**この 3 経路の和集合の外にあるロールを名指しする操作は行わない。**

**適用・検査・再実行・記録の 4 者が、同じ実行の採番を指していることを確かめる。**
同名の対象を作り直す前後は、この採番で区別する。

### 2-4. 撤去する範囲と順序

**撤去は次の順で行う。いずれも「存在すれば取り除く」扱いとし、存在しないことを失敗にしない。**

| 順 | 対象 | 理由 |
| --- | --- | --- |
| 1 | **対象データベース** | 先に落とさないと、データベースに依存するロールを落とせない |
| 2 | **前回の所有者ロール** | 所有者ロールの資産は**作成を含まず変更だけを行う**ので、残っていると 2-2 の**手順 4**(作り直し)で作り直せない |
| 3 | **手順が作る権限ロール**(アプリケーション用・関数所有用) | 同上。クラスタ単位で残る |
| 4 | **中断した実行が残した被検査ロール・一時ロール** | 越境テストは**固定名の一時ロール**を作る。前回が中断して残っていると、次回の実行が**事前存在で失敗する** |

**所有物を持つロールは、所有物を取り除いてからロールを取り除く。**

### 2-5. 作り直しが前提であることの明示

本手順は**状態を保持しない**。対象は毎回まっさらになる。

**したがって、既存のデータを持つ対象への適用は本手順では検証していない。**
この限界を**記録へ明記する**。

## 3. 破壊の前に他の利用者がいないことを確かめる

> **【射程縮小 2026-10-03・PO 裁定(山田正輝)】** 本節は当初「**遮断の機構**」を定めようとしていた
> (新規接続を止める / 終期まで解除しない / 区間を維持する)。**これを「検査」へ落とす。**
>
> **理由**: 遮断は 12-4 の non-serving 区間の概念であり、**実運用のデータベースを守るためのもの**である。
> **本手順の対象は専用のクラスタで、本手順以外に利用者がいない。守るべき serving が存在しない。**
> 遮断すべき相手が存在しないものに遮断機構を書こうとして、確定ゲートが 3 周した
> (2・3・4 周目の P0 はほぼすべて本節から出ている)。
>
> **削る**: 新規接続の遮断 / 解除の時点 / 区間の始期・終期の維持 / 許可する接続の列挙 /
> 資格情報の入れ替えを遮断の実体とする扱い。
> **残す**: **撤去の直前に、他の利用者がいないことを確かめる**こと。

### 3-1. 確かめること

**撤去(2-2 の手順 3)の直前に**、対象データベースへ到達できる接続のうち、
**本手順の実行が用いている接続を除いたものが 0 件**であることを確かめる。

**観測点は撤去の直前に置く**(**5 周目 P1 の是正** — 手順 2 で一度見るだけだと、
そこから撤去までのあいだに現れた接続を検出できない)。**確認と撤去のあいだに他の操作を挟まない。**

### 3-2. 0 件でなかったときの扱い

**0 件でないこと自体が、前提の崩れである。**
対象は専用で、本手順以外に利用者がいないはずだからである。

| 扱い | 内容 |
| --- | --- |
| **既定** | **中止する。** 何も撤去しない。**人が、誰が繋いでいるのかを調べる** |
| **例外** | 接続元が特定でき、安全に終了できると**人が判断した場合に限り**、終了させる |
| **例外を採ったとき** | **終了させたのち、3-1 を最初からやり直す**(**5 周目 P0 の是正**)。**やり直した 3-1 が 0 件なら撤去へ進んでよい。0 件でなければ再び本節へ戻る**(**6 周目 P1 の是正** — 旧文の「中止するまで撤去へ進まない」は、中止した後なら進めるとも読めた)。**本節を離れて撤去へ進める唯一の条件は、3-1 が 0 件になったことである** |
| **繰り返しの上限** | **例外は無制限に繰り返さない。** 2 度目の例外で 0 件にならなければ**中止する**(中止は終了であって、撤去へ進む経路ではない) |
| **記録** | **終了させたときは、何を終了させたかを記録へ書く** |

**自動で強制切断して押し切らない。** 対象が専用であるという前提が崩れている以上、
**何が起きているかを知らないまま破壊してはならない。**

### 3-3. 本節が遮断を持たないことの帰結

**本手順の実行中、対象へ新たに接続することを機構では妨げない。**

- **対象が専用である**という運用上の前提に依存している
- **前提が崩れたら(他の利用者が現れたら)、3-2 により中止する**
- **3-1 の確認と撤去のあいだには、原理的に窓が残る**(遮断を持たない以上、確認の直後に接続されうる)。
  **この窓は、対象が専用であるという前提で受け入れている。** 窓を塞ぐには遮断機構が要り、それは本書の射程外である
- **窓を受け入れられない対象(他の利用者がありうる対象)へ本手順を使ってはならない**
- **対象が専用でなくなった場合は、本書を改訂する**(射程宣言の群 ③)

## 4. 失敗時の扱い

> **【射程縮小 2026-10-03】** 旧 4 節は「**serving へ戻さない**」を軸に、遮断の維持・解除を規律していた。
> 3 節が遮断を持たなくなったので、**維持・解除の規律は無くなる**。残るのは**再開のしかた**である。

### 4-0. 本節が適用される範囲

**本節は、2-2 の手順 1(対象の確認と識別値の確定)を通過した後の失敗にだけ適用される。**

| 失敗した場所 | 扱い |
| --- | --- |
| **手順 1(対象の確認)** | **何も撤去していない。そのまま中止する。** 本節の (a)(b) はいずれも選べない。**初回実行でも再実行でも同じ**(遮断を持たないので、両者で状態が変わらない) |
| **手順 2(他の利用者の確認)** | 3-2 に従う。**何も撤去していない** |
| **手順 3 以降** | 4-1 の規律に従う |
| **手順 3 以降の照合で不一致を検出した** | **その時点で中止する。** 不一致の相手には何もしない |

**対象と認められなかったものを撤去してはならない。** 確認に失敗した相手は、何であるか分かっていない。

### 4-1. 規律

| 規律 | 内容 |
| --- | --- |
| **部分的に再開しない** | 失敗後は 2-2 の 1 からやり直し、**新しい採番を採る** |
| **弱化した状態を次回へ持ち越さない** | 復元ではなく**再構築**で回復する |
| **中断したまま放置しない** | 次のいずれかにする — **(a)** 2-2 を手順 1 からやり直し、**手順 7(記録)まで到達させる** / **(b)** **対象の確認(2-1)と他の利用者がいないことの確認(3-1)を両方取り直したうえで**、対象データベースと手順が作るロールを撤去(2-4)し、**落としたままにする**(**5 周目 P0 の是正** — 旧文は対象確認だけを求めており、**確認後に他の利用者が接続した対象も撤去経路に入った**) |
| **(b) を選んだら記録する** | 落としたままにした事実と、再構築の予定を記録へ書く |
| **(b) は 2 つの確認を通った対象にだけ行える** | **2-1 と 3-1 のどちらかでも通らなければ (b) を行わない**(**P1 の是正** — (a) の「終期まで到達」は終期の定義を削ったので「手順 7 まで到達」へ言い換えた) |

**繰り返し失敗する場合は、自動の再試行で押し切らない。** 人が対象を調べて判断する。

本手順は**維持用の錠(maintenance latch)を置かない**。錠は「弱化した状態のまま serving へ戻さない」ための
機構だが、**本手順には戻すべき serving が無い**。

## 付記: 本書が扱わない対象が増えたとき

射程宣言の**群 ③** に挙げたもの(本番配備への適用・災害復旧・複数対象の運用・既存データを保持したままの適用)が
必要になったら、**本書を改訂する**。現行の 4 節は**対象が 1 つで、毎回まっさらにする**前提でのみ成立する。
