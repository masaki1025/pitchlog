# 実装計画書: 比較元への完全復元を同一コミット規則の対象外にする

## 0. 利益相反の明示(レビュー前提)

**本計画の起案者(Claude / U-A1 δ 担当)は、この規則に現に止められている当事者である。**
PR #119 が `core-guard` の本規則で red のままマージできない。

**したがって本件は「検査に止められた側が検査を緩める」形を取りうる。**
レビューはこの前提で読むこと。**独立の敵対レビューと人間の逐行確認を必ず通す。**
**δ 側の都合を根拠にした主張は 1 つも置かない** — 下の根拠はすべて実測である。

## 1. 背景

`scripts/core_guard.py:376-390`(`verify_area_path_baseline`)は、PR の比較元から HEAD まで
**全コミットを 1 本ずつ**走査し、次を満たすコミットを違反とする。

```python
if (CORE_AREAS_RELATIVE_PATH in changed        # .claude/core-areas.json
    and changed_definitions                     # scripts/core_guard.py / tests/test_core_guard.py
    and _parent_has_area_path_additions(root, revision)):
    raise GuardError(...)
```

**規則の趣旨**: 宣言(`core-areas.json`)と基線定義を同一コミットで動かせると、
**守る範囲を広げながら守り方の定義も同時に書き換える**ことができる。段を分けさせる。

## 2. 問題 — 比較元への完全復元まで違反になる

develop の取り込みでマージの自動解消が `core-areas.json` の並びを崩したとき、
**3 ファイルすべてを比較元(develop)の内容へ戻す**のが正しい対処になる場合がある。
これを 1 コミットで行うと本規則に当たる。

**その復元は定義上 weaken しえない** — 生成される内容が**比較元と同一**だからである。

### 実測した事実(根拠)

| # | 事実 | 典拠 |
| --- | --- | --- |
| 1 | **マージコミットは本規則の検査を受けない** | `_changed_paths_in_commit` が `-m` 無しの `git diff-tree` を使うため、マージでは出力が空になる。実際のマージ履歴でも確認 |
| 2 | **2 コミットに分ければ通る** | 規則は「同一コミット」しか見ない |
| 3 | PR #119 の `7b51a8c0` は 3 ファイルを当時の develop(`ef5c8711`)と**完全一致**させた。**PR の最終差分も 3 ファイルについて 0 行** | 独立検証で確認済み |

**1 と 2 は、本規則が見かけの保証を提供していないことを示す。**
本計画はその穴を広げも狭めもしない — **3 の形だけを対象外にする。**

## 3. 変更しない範囲(明示)

- **規則そのもの**(宣言と基線定義を同一コミットで動かすことの禁止)は撤回しない
- **最終状態の二層契約検査**(`validate_area_path_layers`)は 1 行も触らない
- **`_parent_has_area_path_additions` の条件**は変えない
- **`.claude/core-areas.json`** は 1 行も変えない
- **PR の最終差分を根拠にした免除は入れない**(下記 4 の危険な形)

## 4. 採る条件と、採らない条件

**似て非なる 2 つがあり、片方は危険である。**

| 条件 | 採否 |
| --- | --- |
| **PR の最終差分が 0 行なら当該コミットを免除する** | **採らない。** 弱めるコミットの後ろに戻すコミットを置けば、**弱めた側が免除される** |
| **そのコミットが生成した 3 ファイルの内容が、比較元の内容と 3 本とも byte 単位で一致するなら免除する** | **採る** |

### 採る条件(厳密形)

> 比較元 commit(`merge_base_revision` が返す OID)における
> `.claude/core-areas.json`・`scripts/core_guard.py`・`tests/test_core_guard.py` の blob と、
> **当該コミットが生成した同 3 ファイルの blob が、3 本とも一致する**とき、
> そのコミットを同一コミット規則の対象外とする。

- 判定は**そのコミット単体**で閉じる。**PR の最終状態を参照しない**
- 比較対象は**既に develop にある、レビュー済みの内容**に限る
  (任意の過去コミットとの一致では免除しない)
- **3 本のうち 1 本でも違えば免除しない**(部分復元を認めない)
- 3 ファイルが比較元に存在しない場合は免除しない

**弱めるコミットは、その時点の内容が比較元と異なるため捕まり続ける。**
