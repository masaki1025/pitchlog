# 調査メモ: 敵対レビューの回数上限 — 実測・P0 の出現位置・決定経緯・要件突合

調査基点: develop = `27ff94eb`(2026-10-07)。調査サブエージェント = decision-tracer(決定経緯)/ spec-checker(要件突合)/ Explore(2026-09 以降のレビュー系列の集計 — 子エージェントの集計 13 本を含む)。各報告の典拠は Claude が原文で抜き取り確認した(確認できなかったものは「未確認」と書く)。パス略称: **設計書** = `docs/development/dev-harness-design-2026-08-07.md` / **台帳** = `docs/development/harness-evaluation.md` / **GCR** = `docs/features/gate-convergence-rules/`。

## 問い

1. 敵対レビューの消費は、どのゲートのどの周で生じているか(回数・トークン)
2. P0 は何回目に出るか(確定ゲート / 計画レビュー / コア領域 PR の別に)。上限 2 回 + P0 例外で取りこぼす P0 はどの型か
3. 要件書は正本の確定・レビューの回数や収束条件を規定しているか
4. 周回上限は過去に検討・否決されたか。「最終全文確認周」の再実施ループを置いた理由は何か
5. 改訂で触る箇所はどこか(規範 / 写像 / 機構)。既存タスク・ADR との射程の重なりはあるか

## 結論(要約)

- **消費の主因は全文レビューの再実施ループ**。直近ゲート(設計書 v1.18 + ADR-001 v1.1)は 18 回・約 4.70M トークンのうち全文 6 回が約 3.25M(69%)。1 回あたり全文 310〜530K・差分 72〜181K。2 回目終了時点の累計は約 0.62M(§1)
- **確定ゲートの非起因 P0 は初周に集中する**。3 回目以降の P0 は (a) 前周の反映が生んだ起因 P0(v1.17 の 7 周目・TSK-474 の 2 周目)と (b) 射程変更直後の全文周の非起因 P0(data-model v0.1 の 3 周目 2 件・v0.4 の 4 周目 1 件)に分かれる。**計画レビューとコア領域 PR では事情が違い、P0 が 5〜8 周続く系列が複数ある**(TSK-317 計画 8 周で P0 4→2・U-T1 PR 7〜8 周で P0 4→1 等)。上限 2 回 + P0 例外で捕まらない非起因 P0 の実例は、計画レビュー 1 件(frozen-baseline-ledger 4 周目)・コア領域 PR 1 件(U-T1 8 周目)(§2)
- 要件書はレビューの回数・収束条件を規定しておらず(本文に「敵対」「逐行」の語なし)、提案と矛盾する要件条文もない。コア領域に要件が求めるのはテスト種別と CI 強制だけで、敵対レビュー + 逐行確認は 2026-08-07 の PO 決定(自己規定)。矛盾は設計書 7.3 の自己規定側にのみある(§3)
- **周回上限は v1.12 計画(A2)で「固定上限を主にしない」形で修正採用され、否決記録はない**。A2 の根拠の 1 つ「固定周回閾値は canonical で判別力を失った」は原文と合わない(判別力を失ったのは比率の基準)。「最終全文確認周の再実施」は v1.12 ゲート 1 周目の P1① で後から足された。**per-gate の PO 裁定で「再確認周を回さず人間承認・逐行確認で代える」とした先例が 2 件ある**(ADR-003 v0.2・data-model v0.5)。7.3-8 が予告した「3 ゲート分の運用評価」は未記録で、本メモがその代替になる(§4)
- 規範は設計書 6.1 / 6.3 / 7.3-2〜7.3-6 / 7.3-8 / 8.4。写像は finalize-doc・plan・pr の 3 スキルと CLAUDE.md。機構(`feature_status.py`・`codex_run.py`)に上限の概念はなく変更不要。**TSK-340(計画レビューの終端条件・未着手)と射程が重なる**。ADR-001 の実測期間(記録項目に実行回数・周回数)と規則変更が重なる(§5)
