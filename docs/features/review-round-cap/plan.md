## 4. 実装方針

- **重さ分類 = 通常** の根拠: 変更対象はハーネスの正本(設計書)・スキル本文・CLAUDE.md の文書のみで、コード変更はない。コア領域 5 領域(設計書 6.3)の `paths` には該当しない。`finalize-doc`・`pr` スキルは `guard_paths` に該当するが ADR-001 の重さ分類上のコア領域ではなく(harness-model-refresh の計画と同じ判定)、guard_paths の手続(人間の逐行確認・PR の実施記録行・SHA 拘束マージ)を PR で適用する。軽微でもない(正本の版繰り上げを伴う)。本計画のステップはすべて文書であり **Codex への `implement` 委任は行わない**(設計書 3 章: ドキュメント = Claude。Codex は計画レビューと確定ゲートのレビュアとしてのみ関与)
- **詳細設計は [design.md](design.md)**(D-1 共通規則〔基本枠 2 回・P0 例外・PO 裁定による追加〔範囲は差分 or 全文〕・包括的な続行指示・上限到達時の終端と人間承認での追加裁定〕/ D-2 終端遷移表 / D-3 レビュー範囲 / D-4 依頼文 / D-5 エスカレーションの縮約 / D-6 計画レビュー・コア PR への適用 / D-7 残余リスク / D-8 本ゲートの運用)。**確定ゲート開始時点で正は条文へ移る**(design.md は経緯資料に降格 — 台帳 H-44 の二重管理防止)
- **順序**: ステップ 1(v1.19 起案を単一コミットで in-review 化 + 索引 + 適用版の worklog 暫定記録)→ **/finalize-doc(適用版 = 7.3 v1.18。上限なし・最終全文確認周あり)** → approved 化(版確定・README)→ ステップ 2(スキル 3 本 + CLAUDE.md の追随)→ /sync-docs の突合 → /pr。**確定ゲートの反映周コミットにはステップ記法を付けない**(設計書 6.1)
- **本ゲートのコスト統制(D-8)**: 変更範囲を 6.3 / 7.3(+ 6.1・8.4・流れ図の参照行)に絞り、2 回目以降の母集団を小さくする。起因の反復が見えた時点で作成者は 7.3-6 の即時裁定(続行指示 / 射程縮小)を PO に求める。見込み = 全文 1 回(約 450〜550K)+ 差分数回(各 100〜180K)+ 最終全文確認周(約 500K)≈ 1.0〜2.0M トークン。**上限は本ゲートに適用しない**(7.3-1)。各回のトークン(`tokens used`)を worklog に記録する(ADR-001 の記録項目)
- **確定ゲート中の安全分類器の遮断**(台帳 H-75): 判定行のない応答は周に算入せず同一周を再依頼する(7.3-5)。再依頼は依頼文を「所在・理由・修正案の 3 点」形式の安全語彙へ切り替える
- **旧記述の残存検査**(ステップ 1・2 の合格条件で使う。変更履歴表の過去行と worklog は除外): 設計書本文(7.3-2〜7.3-6・流れ図)とスキル本文に `最終全文確認周`・`6 周警告`・`6 に達したら`・`起因件数 × 2 > 母集団`・`収束するまで`・`収束規則に従い反復` が残らない / 6.3 に「レビュー回数の上限」段落が 1 箇所だけある / 7.3-2 の表に「3 回目(P0 例外)」行がある / `finalize-doc/SKILL.md` に「最終反映の差分」の確認手順がある
- **差し戻し経路**: 確定ゲート中にスキル・CLAUDE.md へ触れない(approved 化の前に写像を変えない)。ゲートが PO 裁定で取り下げになった場合は in-review 行を取り下げ記録に改め、設計書 frontmatter を approved(v1.18)へ戻す独立コミット(ステップ記法なし)で閉じる

### PO 判断事項(**確定 2026-10-07・徳光 尋弥: ① 含める ② 吸収して取り下げ** — 以下は判断材料として保存)

- **① 計画レビューの「受理範囲の限定」を 6.1 に含めるか**(推奨 = **含める**): TSK-340 の材料(TSK-271・TSK-269・TSK-317 で、受理する指摘を 3 種〔正本違反・ステップが緑にできない・DoD と成果物の不対応〕に限定して初めて指摘が局所化した — research.md §5)。含める場合の条文 = 「計画レビューの依頼文は受理範囲 3 種を明示し、範囲外の指摘は不採用理由『受理範囲外』で処理する」の 1 文(design.md D-6)。含めない場合は TSK-340 の DoD ①のうち「受理範囲の限定」だけが残る
- **② TSK-340 の扱い**(推奨 = **本タスクで吸収し、PR で TSK-340 へ参照をコメント → PO が取り下げ**): **①が「含める」なら** TSK-340 の DoD ①〜③ は本タスクの D-6 + 確定ゲートで満たされ、吸収して取り下げを推奨する。**①が「含めない」なら** TSK-340 の DoD ①のうち「受理範囲の限定」だけが残るため、TSK-340 は取り下げず「周回上限・終端・申し送りは TSK-496 で条文化済み。残り = 受理範囲の限定」とコメントして存続させる。DoD ④(台帳候補の `H-*` 採番判定)は本タスクの /pr クローズ処理で判断する。本計画 5 節の DoD 2 項目目はこの選択結果に連動する
