# 詳細設計: 敵対レビューの回数上限(設計書 v1.19 の起草入力)

本書は [plan.md](plan.md) 4 節から参照される起草入力(補助資料)である。**確定ゲート開始時点で正は設計書 6.3 / 7.3 の条文へ移り、本書は経緯資料に降格する**(gate-convergence-rules の design.md と同じ扱い — 台帳 H-44 の二重管理防止)。以後の照合先は常に正本の条文。機構が読む状態と実装ステップ表は plan.md のみに置く。

PO 判断(2026-10-07・徳光 尋弥)= ① 上限の形 = レビュー実行 2 回(全文 1 + 差分 1)+ P0 例外 ② 適用範囲 = 正本確定ゲート・計画レビュー・コア領域 PR の敵対レビュー ③ v1.19 の確定経路 = 現行 v1.18 の規則で最後の確定ゲートを 1 回回す。以下はこの 3 点を条文に落とす設計で、PO 判断そのものを変えない。

## D-1. 共通規則の置き場所と射程(設計書 6.3 に新設する「レビュー回数の上限」)

- **置き場所**: 設計書 **6.3(レビュー体制)** に段落「レビュー回数の上限(全レビュー経路共通)」を新設し、7.3-2(確定ゲート)・6.1(計画レビュー)・6.3 表のコア領域 PR 行はこれを参照する。規則を 1 箇所に置く理由 = 7.1-1(1 テーマ 1 正本・複製禁止)と 7.6 冒頭(同じ規則を別文書で再定義しない)。
- **対象 = Codex へ委任するレビューの実行回数**: `codex_run.py review adversarial`(確定ゲート・コア領域の計画レビュー・コア領域 PR)と `review normal`(通常の計画レビュー)。Claude 一次レビュー(6.3 表の「コード(通常 PR)」行)と人間の逐行確認は対象外(回数の概念がない)。
- **基本枠 = 2 回**: 1 回目 = **全文**(対象全体)/ 2 回目 = **1 回目の反映差分と影響節**。
- **P0 例外 = 自動で 1 回**: 2 回目の判定に P0 が 1 件以上あれば、その反映後に **P0 限定の差分レビュー**を 1 回追加する(3 回目)。P0 限定 = 「前周の P0 反映が P0 を解消しているか・新たな P0 を生んでいないか」だけを判定し、P1/P2 は報告しない(依頼文で明示)。
- **PO 裁定による追加 = 裁定 1 回につきレビュー 1 回**: 3 回目でも P0 が残る場合、または PO 裁定(7.3-6)で射程が変わった場合は、**PO 裁定 1 回につきレビュー 1 回**を追加できる。**範囲は裁定で指定する — 差分(P0 限定 / 変更範囲 + 影響節)または全文**。全文を選べるのは、射程変更直後の全文周で非起因の P0 が見つかった実例(data-model v0.1 の 3 周目 P0 2 件・data-model v0.4 の 4 周目 P0 1 件 — research.md §2)を受けるため。基本枠・P0 例外の外で回数が増える経路は**これだけ**(人間の判断に 1 対 1 で紐づく。自動で増える全文周は存在しない)。
- **包括的な続行指示**: P0 が 3 回目でも残る系列(コア領域の計画レビュー・コア領域 PR で P0 が 5〜8 周続いた実例が複数ある — research.md §2)では、PO は **1 回の裁定で「P0 がゼロになるまで P0 限定の差分レビューを続ける(最大 N 回)」と包括的に指示できる**。周ごとに PO を呼ばない(認知負荷を増やさない)が、N は裁定で明示し worklog に残す。N 回で P0 が残れば再び PO 裁定(射程縮小・取り下げを含む)。
- **上限到達時の終端**: 最後のレビューの指摘を全件採否裁定し、採用分を反映(反映周コミット 1 件)・不採用分は理由を採否記録に明示し、**人間承認へ上げる**。最後の反映は Codex の再レビューを受けない(D-7 の残余リスク)。**人間承認の場で PO は、承認の代わりに追加レビュー(差分 or 全文)を裁定できる**(上記「PO 裁定による追加」と同じ 1 裁定 1 回の規律)。追加全文を検討すべき型 = **新設の大型コア正本**(data-model v0.1 の確定ゲートは 2 回目が P0 ゼロなのに 3・4・5・8 回目で P0 計 7 件が出た — research.md §2)。改訂(差分が小さい版繰り上げ)では追加を既定にしない。
- **上限は「回数を使い切ること」を求めない**: 1 回目で指摘ゼロなら 2 回目は不要(そのまま人間承認へ)。回数を稼ぐことが目的ではない(finalize-doc 旧記述の趣旨を保つ)。

## D-2. 確定ゲートの終端遷移表(7.3-2 の置換)

「周」= レビュー実行 1 回(不変)。**カウンタ(`確定ゲート周回`)と `反映<r>周目` コミットは「採用反映を伴う周」のみに発生する**(6.1 の規約は変更しない。上限により `確定ゲート周回` は基本 2 以下・P0 例外で 3・PO 裁定ごとに +1 が上限値になる)。

| 周 | 対象(7.3-4) | 周の結果 | 処理 | カウンタ / コミット | 次の状態 |
| --- | --- | --- | --- | --- | --- |
| 1 回目 | 全文 | 指摘ゼロ | — | カウントしない | **収束**(人間承認へ) |
| 1 回目 | 全文 | 指摘あり | 全件を採否裁定し、採用分を反映。不採用分は理由を採否記録に明示 | 採用ありなら 周回 +1・`反映1周目` | 2 回目へ(全件不採用で反映なしなら 2 回目は不採用一覧の維持/取り下げ確認を兼ねる差分周) |
| 2 回目 | 1 回目の反映差分 + 影響節 | P0 ゼロ | 全件(P1/P2)を採否裁定し、採用分を反映。不採用分は理由を明示 | 採用ありなら 周回 +1・`反映2周目` | **上限到達 → 収束**(人間承認へ。最終反映の差分と採否一覧を提示) |
| 2 回目 | 同上 | P0 あり | 全件を採否裁定し、採用分(P0 を含む)を反映 | 周回 +1・`反映2周目` | **3 回目(P0 限定)へ** |
| 3 回目(P0 例外) | 2 回目の P0 反映差分のみ | P0 ゼロ | P0 以外の報告は受け取らない(依頼文で P1/P2 の報告を禁じる。混入した場合は採否記録に残し反映しない) | カウントしない | **収束**(人間承認へ) |
| 3 回目(P0 例外) | 同上 | P0 あり | 採用分を反映 | 周回 +1・`反映3周目` | **PO 裁定へ**(7.3-6: 射程縮小 / 範囲確定 / 続行指示 = P0 限定差分をもう 1 回 / 取り下げ)。裁定 1 回につき差分 1 回を追加し、P0 ゼロで収束 |

- **(B) の扱い(不変)**: (B) 分類(P2 のみ)は送り先(実装タスク or 申し送り)を採否記録に記録した時点で解決扱い。周の遷移・カウンタは (B) を除いた残りに本表を適用する。
- **採否記録の定義と永続化(不変)**: worklog に周ごとに追記し、各周の反映コミット(反映のない周は採否記録の追記コミット)に含める。
- **全件不採用の扱い**: 作成者判断のみの不採用は終結ではない。**不採用は人間承認の場で PO が一括判断する**(支持 = 終結 / 採用指示 = 反映して承認。採用指示分の反映は再レビューしない — D-7)。旧表の「全件不採用 2 周連続で PO へ」は、上限により 2 回目が最終周になるため PO 判断に自然に吸収される(独立規則としては廃止)。
- **廃止するもの**: 「最終全文確認周」とその再実施ループ(旧表の下 3 行)・P2 のみ周の一括裁定行(2 回目の P0 ゼロ行に吸収)。
- **7.6-1(黙殺禁止)との両立(不変)**: P2 も必ず「反映」または「不採用理由の明示」のどちらかで処理する。採否一覧の人間提示は維持する。

## D-3. レビュー範囲(7.3-4 の置換)

- 1 回目 = **全文**。2 回目 = **1 回目の反映差分と影響節**。3 回目(P0 例外)= **2 回目の P0 反映差分のみ**。PO 裁定後の追加 = **裁定で指定した範囲**(差分 = 変更範囲 + 影響節 / P0 限定、または全文)。
- 射程変更直後の周を**自動で**全文レビューにする旧規則は廃止する(自動の全文は 1 回目のみ)。射程変更は PO 裁定でしか起こらないので、全文が要るかはその裁定で PO が選ぶ(D-1)。差分外の欠陥クラス(approved 正本間の矛盾等)は 1 回目の全文レビューが受け持つ。

## D-4. 依頼文規約(7.3-5 の調整 — 骨格は維持)

- 冒頭の命令文(「実際にレビューを実施し、次周の依頼文を作らず、判定を返すこと」)・7.3-3 の重大度定義の毎回組み込み・応答様式(`P0|P1|P2` + `起因|非起因` + `(A)|(B)|(-)` + 判定行)・判定行のない応答は周に算入せず同一周を再依頼 — **すべて不変**。
- **回数の明示を追加**: 依頼文に「本周は N 回目 / 上限 M 回」と「本周の対象範囲(全文 / 反映差分 + 影響節 / P0 限定)」を必ず書く。3 回目(P0 例外)は「P0 のみを判定し P1/P2 を報告しないこと」を命令文に含める。
- **2 回目への添付(不変・簡素化)**: 終結済み一覧と未終結の不採用一覧を添付し、レビュアに「維持 / 取り下げ」を明示させる。**維持は PO 判断(人間承認時)へ回る**(旧 7.3-5 の「不採用 2 周目として扱う → PO 判断を並行」は、2 回目が最終周になるため人間承認の場に統合)。
- **終結の定義(不変)**: ① PO が不採用を支持したもの ② (B) として送り先記録済み。

## D-5. エスカレーションと警告(7.3-6 の縮約)

- **維持**: 「発火条件によらず、作成者または PO はいつでも PO スコープ裁定を起動できる」(即時裁定)/ PO 裁定の選択肢(射程縮小・範囲確定・続行指示)と文書への編集・記録の規定 / 射程変更は変更履歴と worklog に記録(7.3-7)。
- **置換**: 「裁定後の次周 = 全文レビュー」→ **「裁定後の次周 = 差分レビュー 1 回(範囲は裁定で指定)」**。
- **廃止**: `起因件数 × 2 > 母集団` の 2 周連続エスカレーション算式(上限 2 回では 2 周連続が成立し得ない)/ `確定ゲート周回` 6 の警告(上限により到達不能)。**上限そのものがエスカレーション**になる(上限到達で人間承認へ上がる)。
- **追加**: 3 回目(P0 例外)で P0 が残る場合は PO 裁定へ(D-2 最終行)。

## D-6. 計画レビューとコア領域 PR への適用(6.1・6.3)

- **計画レビュー(6.1・/plan)**: 6.1 の「計画レビューの水準は 6.3 の表のとおり」に「**回数は 6.3 の上限(全文 1 + 差分 1 + P0 例外)に従う**」を追記。これは **TSK-340**(計画レビューの終端条件 — 6.1 改訂で 7.3 の収束規則を準用する起票・未着手)の射程を吸収する(/pr で TSK-340 へ本タスクの参照をコメントし、PO が取り下げ or 統合を判断)。**TSK-340 の材料「受理範囲の限定」**(計画レビューで受理する指摘を 3 種 = 正本違反・ステップが緑にできない・DoD と成果物の不対応 に限定すると指摘が局所化した — TSK-271・TSK-269・TSK-317 の実測)は、**PO 判断で含めるかを決める**: 含める場合は 6.1 に「計画レビューの依頼文は受理範囲 3 種を明示し、範囲外の指摘は不採用理由『受理範囲外』で処理する」を 1 文追加する(推奨 = 含める。上限 2 回の 2 回目の母集団を小さくし、不採用理由を定型化できる)。1 回目 = 計画書全文、2 回目 = 反映差分。上限到達時の残指摘は worklog の採否記録 + 人間承認(`承認: 済`)で閉じる。`計画レビュー周回` カウンタの意味(指摘反映を伴う周ごとに +1)は不変。
- **コア領域 PR の敵対レビュー(6.3 表)**: 「上記に加え敵対レビュー + 人間の逐行確認(必須)」に「**敵対レビューの回数は本節の上限に従う**(1 回目 = PR 差分全体 / 2 回目 = 指摘反映の差分 / P0 例外)」を追記。上限到達時の残指摘は PR 本文(または worklog)の採否記録 + 人間の逐行確認で閉じる。PR テンプレの必須チェック文言(`core_guard.py` の `REQUIRED_CHECK_TEXT`)は変更しない。
- **写像の追随(実装時に確定)**: `.claude/skills/finalize-doc/SKILL.md` 手順 2〜4(回数・P0 例外・終端)/ `.claude/skills/plan/SKILL.md` レビューと承認 2(回数上限)/ `.claude/skills/pr/SKILL.md` レビュー導線の案内(コア領域の敵対レビューの回数)/ `CLAUDE.md` コア領域の行(「敵対レビュー必須」に回数上限の参照を添える)。`finalize-doc`・`pr` は guard_paths(人間の逐行確認 + 実施記録行)。

## D-7. 残余リスク(7.3-8 への追記)

- **最後の反映は Codex の再レビューを受けない**: 上限到達時の反映(2 回目または 3 回目の採用分)は差分レビューされないまま approved になる。実例: 設計書 v1.17 ゲートの 7 周目 P0(6 周目の反映が生んだ)・TSK-474 ゲートの 2 周目 P0(1 周目の反映が生んだ)はいずれも**反映作業自身が生んだ起因 P0**(台帳 H-42 の P0 版)。受け方 = **人間承認時に最終反映の差分(`反映<r>周目` の最終コミット)を採否一覧とともに確認する**ことを /finalize-doc 手順に置く(運用規律・機械検証なし)。
- **上限の遵守は運用規律**: 回数・P0 例外・PO 裁定の紐づけは機械検証されない(欠けても CI は green になり得る)。`確定ゲート周回` が 3 を超える plan は PO 裁定の記録を伴うはずなので、`feature_status.py` に「周回 > 3 で注記」を足す機構化は候補として台帳へ送る(本改訂では実装しない — 7.3-8 の「運用実績で評価してから」を踏襲)。
- **P0 を見逃す経路(実例あり — 上限で失うものを明示する)**: 2 回目で P0 が出なければ 3 回目はない。非起因 P0 は初周に集中する実測に依拠するが保証ではなく、**3 回目以降に非起因の P0 が出た実例が v1.12 以後に 5 件ある**(research.md §2: data-model v0.1 の 3 周目〔射程変更直後の全文〕2 件と 5 周目〔全文〕1 件 / data-model v0.4 の 4 周目〔射程拡大直後の全文〕1 件 / コア領域の計画レビュー frozen-baseline-ledger の 4 周目 1 件〔ステップ順序で実装が成立しない〕/ コア領域 PR U-T1 の敵対レビュー 8 周目 1 件〔`continue-on-error` で検査を殺しても必須チェックが緑〕)。うち 3 件は射程変更直後の全文周(PO 裁定で全文を選べる経路 D-1 で受ける)。**残り 2 件は本上限では捕まらない**。受け方 = 計画レビューの見逃しは確定ゲート 1 回目の全文(H-30 の実例: 計画 6 周で見えなかった P0 3 件をゲート 1 周目が検出)と実装後の検証、コア領域 PR の見逃しは必須の人間逐行確認と CI。ゲート通過後に別工程が P0 を特定した実例は ADR-001 帰結の巻き戻し条件 (c) と同じ扱いで台帳に記録し、上限の再調整(例: コア領域 PR は基本枠 3 回)を次版で判断する。
- **最終全文確認周の廃止で失うもの**(decision-tracer の実測): 全文周でだけ見つかる非起因の P1(公式仕様との不一致・別節の同族インスタンス・既存矛盾 — v1.18 ゲートの全文周 5 回すべてで非起因 P1 が出た)と、approved になる版を機械が全文確認する保証。**先例**: ADR-003 v0.2(2026-09-03)・data-model v0.5(2026-10-05)の PO 裁定は「再確認周を回さず人間承認・逐行確認で代える」としており、本改訂はその per-gate 裁定を一般規則にするもの。
- **ADR-001 の実測期間との関係**: ADR-001 v1.1 の実測期間(開始 = TSK-463 の PR マージ日・終了 = 3 ゲート完了かつ 4 週間)は記録項目に実行回数・周回数を含む。本改訂で規則が変わると、モデル差と規則差が混ざる。受け方 = 各ゲートの worklog に**適用版(7.3 の版数)**を既に記録している(7.3-1)ので、集計者は v1.18 適用と v1.19 適用を分けて集計する(ADR-001 の記録項目は変更しない — 本計画の射程外。台帳候補として申し送る)。

## D-8. 本ゲート(v1.19 自身)の運用

- **適用版 = 7.3 v1.18**(7.3-1: 初回敵対レビュー実行時点で approved の版。本改訂は in-review なので直前 approved 版が適用される)。条文コミット SHA = in-review 化コミットの第一親。worklog に暫定記録し、初回レビュー実行時点で確認する。
- **v1.18 の規則で回す**ため、上限は本ゲートには適用されない(未確定条文の先取り適用の排除)。見込み: 1 回目全文(約 450〜550K トークン)→ 差分数回(各 100〜180K)→ 指摘ゼロ → 最終全文確認周(約 500K)。差分を 6.3 / 7.3 に絞ることで 2 回目以降の母集団を小さくする。**作成者は 7.3-6 の即時裁定を PO に求めてよい**(起因の反復が見えた時点で)。
- **射程宣言(7.3-7)** は変更履歴の in-review 行に置く(D-1〜D-7 の範囲 = 本書で確定 / スキル・CLAUDE.md・テンプレ・台帳候補 = 実装時に確定)。

## 未解決・検討メモ

- 2 回目で「全件不採用・反映なし」のとき、3 回目(P0 例外)の判定材料がない。D-2 では「2 回目に P0 がなければ上限到達」で閉じるので矛盾しない(P0 を不採用にする経路は PO 判断の対象)。
- `review normal`(計画レビュー)で 2 回目に P0 が出た場合も P0 例外を同じく適用する(モデル・effort はラッパー固定で変えない)。
