## 判定の根拠と限界

要件書の実表はA-2 12行/A-2b 5行/A-3 8行/A-4 7行/A-5 8行で合計40行。ADR-003 D-14-g(iv)も同じ母集団を規範化する。A-3のRBI-01〜09は打点1行の分岐、A-3bは分解軸で新指標ではない。対象はNFR-018(β)①〜⑤・⑦のMust/Should/Could受入基準すべて。区分の「・」は全演算が必要、「/」は両方式が部分集合で可能でなければならない。全行に、ゴミ箱除外、期間/区分/大会絞り、左右、JST年度、0分母null、FR-041のテナント/在籍条件が掛かる。

現行の承認済みTSK-538計画はSQL生成を「枠」までと明記し、(iv)判定を後段へ渡す。実装された frontend/scripts/domain-sql/generate.mjs の SQL_SUBSET は固定Rowの bigint/boolean/string、加減乗、比較・論理・条件式、関数なし、aggregateではグローバルな count と sum を必ず対で返すか、classifyで行単位の値を返す。除算、AVG/MAX、GROUP BY、JOIN、日付軸、入れ子集計、行リスト、状態計算は宣言されない。SQLは渡されたJSON配列を走査する。ADRのRはSQL内の除算そのものを必須とせず、分子/分母の構造化値をSQLが返し、丸めをSQL外へ置く。このためcount/sumの2列を分子/分母に対応づけられる可能性を、除算演算子がないだけで否定しない。「現行の承認済み部分集合」は計画承認とコードの実在までは確認できるが、40行を覆う最終部分集合の承認宣言は見つからない。後者を既成事実としない。

以下の**不適合**は、ADRの必要演算の少なくとも1つがこの生成器の閉じた部分集合に無いという、現行候補に対する確定した否定。**原典不足**は必要演算が表面上許可されても、正本入力のRow投影・共通条件・集計結果との結線が未定義で完全な適合を証明できないもの。**適合**は全条件と出力まで実証した行だけに使う。本時点で適合と実証した行は0であり、原典不足を適合へ繰り上げない。

## D-2(iv)の結論・受取先

現行生成器だけでは40行の包含を証明できない。ADR-003 D-14-g(iv)は、否定結果の後に(a)部分集合拡張、(b)集計区分変更、(c)要件再定義のいずれかを**正本改訂で**選ぶことを要求し、手書きSQLを禁じる。今回いずれも選択しない。D-2は発効日のPO記録が無く、現行はD-1である。TSK-237完了、段階①完了、(iv)充足、D-2発効、U-X1解凍はそれぞれ別判定とする。

(iv)専用カードは正式カードの検索で見つからなかった。管理上の最小案は「ADR-003 D-2(iv) 40指標の包含判定と不足演算の裁定」という後続カードを1枚設け、受取担当をTSK-538のSQL所有者またはPO指定の担当に確定すること。DoDは①40行のSQL入力/出力投影と共通条件の対応、②各行の生成・拒否試験、③不適合の(a)(b)(c)の正式裁定、④人間確認済み全件判定、⑤発効とは別記録。TSK-237へこの作業を混ぜない。

## レビュー分担と未決

TSK-538は原典所在を引き渡したため、その読取行の照合を単独の独立レビューと表示しない。こちらで作成した行別判定と原典不足の境界について、候補作成に関与していない査読者へ反対側レビューを依頼する。TSK-538には生成器の現行宣言と後続受取担当の確認を依頼する。POには、(1)現行SQL_SUBSETを(iv)の「段階2が定めた部分集合」の比較基準として扱うか、(2)専用カードの起票と受取担当、(3)不適合が残る場合の正本改訂経路を判断いただく。判断前に正本・凍結値・検査器・製品コードを変更しない。

独立Codex査読（2026-10-16、候補未編集）はP1×1、P2×1。P1「R単独6行は除算演算子の欠落だけで不適合と断定できない」は採用し、6行を原典不足へ移してSQLの分子/分母・nullable受け口の未確定を記した。P2「#36は行内差のsumでも実現可能」は採用し、欠落論点をRow投影・共通条件・出力結線へ限定した。他の30行と母集団・非発効の結論への異議は無かった。この査読はTSK-538の受理やPO判定の代替ではない。
