## 4. 実装方針

### 重さ分類の根拠 — **コア領域**

`docs/design/data-model.md` は **`.claude/core-areas.json` の 5 領域すべての `paths`** に
登録済み。**機械検知が発火し、人間の逐行確認が必須**(設計書 6.3)。
`contracts/authz/*` と `contracts/db/schema-manifest.json`・受入シートの生成器も同様。

### 設計上の要 — **ADR に規範を置かない**

`data-model.md` 12-8 節が「越境テスト再実行ゲートの**定義**(12-4 節)」を
**本書の確定範囲**と宣言している。**ADR-004 に規範を置くと、TSK-378 が案⑥を
「射程侵犯」として却下した論拠が形式的に自分へ返る。**

**ADR-003 の先例にならって切る**:

| | 置くもの |
| --- | --- |
| **ADR-004** | **争点・決定・理由・却下した案**。規範は置かない |
| **`data-model.md` 12-4** | **規範**(適用単位・測定経路の充足条件) |
| **要件書 `NFR-019(b)`** | **発効条項**(`F-3`) |

**「規範を置かない」の検証可能な境界**(`P1-5` の是正 — これが無いと `D-n` に適用条件を
再掲した場合との区別が付かない):

> **ADR-004 の `D-n` は、12-4 / `NFR-019(b)` で採択された条項を
> 「**過去形 + 条項参照**」で記録する。**独立した適用条件・合格述語・量化子を持たない。**

**検証**: ADR-004 の本文から**条項参照を外すと規範として読めなくなる**こと。
読めてしまうなら規範を持っている。

ADR-003 は per-target のマージ条件を「**要件書 `NFR-018` の既存条項の言い換え**」として
位置づけており、**新しい規範を単独で作っていない**([research.md](research.md) 2-4)。

### 条文の書き方 — **先例の型を借りる**

**適用単位で切った条文の最も近い先例は要件書 `NFR-021 :954`**:
「**範囲は〈組〉に限る**」+「**組の識別子を定義**」+「**組の外は〈別の呼び名〉とし、
〜とは呼ばない**」+「**持ち越さない**」。

**`NFR-021` は「判定」と「正式受入の成立」の混同で `P0` を 2 回踏んでいる**(台帳 `H-79`)。
**本タスクも「判定」と「成立」を最初から分けて書く。**

### 周回を伸ばさないための規律(TSK-348 の 2 つの PO 裁定)

| 規律 | 内容 |
| --- | --- |
| **worklog は遷移規則を再掲しない** | 遷移の正は設計書 7.3-2 と `/finalize-doc` スキル。worklog は参照する |
| **worklog は派生値を持たない** | 周回・指摘件数・`P0` の連続・反映コミット本数の正は `plan.md` frontmatter・採否記録・`git log`・`feature_status.py`。worklog は**所在だけ**を書く |

**TSK-348 はレビュー 10 回のうち 6 周がこの型で消えた。** `docs/worklog/2026-09-09-data-model-v0-2.md`
の「現在地」節(**知りたいこと → 正の所在**の表)を型としてそのまま使う。
