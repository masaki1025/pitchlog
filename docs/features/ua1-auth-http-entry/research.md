# 調査メモ: U-A1 δ 認証の HTTP の入口(TSK-470)

base = develop `8164c87a`。調査は spec-checker(要件突合)・decision-tracer(決定経緯)・
Explore(実装の現況)の 3 並列。**エージェント間の食い違いと、こちらの事前の見立ての誤りは、
原典に当たって裁定した**(下の「6. 原典で裁定したこと」)。

## 問い

1. レート制限について**要件書はどこまで決めていて、何を決めていないか**
2. **暫定設計で入口を開いてよい**という道は、正本のどこに・どういう形であるか
3. δ の射程は起票時から**動いていないか**
4. β は計数の器を**どこまで作ったか**。δ はどこから書き始めるのか
5. `core-areas.json` の**新規登録が要るか**

## 結論(要約)

- **要件書が定めているのは FR-033 の不変条件だけ**(締め出しに使えない・既存セッションはロック中も有効)。
  **閾値・ロック時間・カウント単位・ロックの効き方は、要件書のどこにも値がない**。10 章は未決のまま
- **暫定設計の道は正本の条文そのものにある** — `data-model.md:1787`。「待ち合わせ」と「射程」は矛盾していない
- **δ の射程は 2 回縮んでいる**。とくに **2026-10-07 の裁定で Cookie の読み取りと CSRF の検査が U-M1 へ移った**。
  **この裁定は develop に着地していない**(U-M1 のブランチにしかない)
- **β はロックを適用していない**(`p_apply_lock = false` が固定)。**ロックの判定は δ が作る**。器は揃っている
- **閾値の実値はどこにも入っていない**。不変条件 ⑤ が「未設定ならログインを拒否」なので、
  **値が入るまでログインは 1 件も通らない**
- **`core-areas.json` の新規登録が 2 行要る** — `backend/src/pitchlog/api/*` 系。どの area の paths にも無い

### 1. 要件側が決めていること・いないこと

**FR-033(`docs/requirements/requirements-pitchlog-2026-07-22.md:590-597`・Must)**

> 既存セッションはロック中も有効**であり、正規利用者の締め出し(第三者の故意の失敗連打による

### 5. `core-areas.json` の窓口
