# 調査メモ: ADR-003 D-14 の発効条件 (i)〜(iv) を条文化するための材料

## 問い

TSK-541 は **(i)〜(iv) を条文として書き、要件書の規範改訂と同一の確定ゲートで通す**。
**条文を書くために**次を確かめた。

1. **(i)〜(iv) が現行の何を置き換えるのか**(決定経緯)
2. **要件書側で何を直すのか**(全量)
3. **現行が実装上どこに依存しているのか**(現況)

調査は 3 本を並列で実施(decision-tracer / spec-checker / Explore)。
**legacy-analyst は投げていない** — 旧システムの実挙動に依存する論点が無いため。
行番号は develop `0e339ed9` 時点。
ADR = `docs/adr/ADR-003-domain-calc-method.md` / R = `docs/requirements/requirements-pitchlog-2026-07-22.md`。

## 結論(要約)

- **(i) は「比較相手を定める」だけでは閉じない。** **比較相手の表は機械可読に実在する**が、
  **2 つの実行体を実際に走らせて突き合わせる経路は 1 行も無い**。
  **`properties.py` の docstring が「等価性は完走証跡の存在だけを確認し、比較そのものは行わない」と明記している。**
  **条文で実施主体も定めないと、文言だけが残る**(台帳 `H-21` の型)
- **(i) の論拠は明文で存在しない。** 「なぜ Python 生成物と TypeScript 生成物を比較するのか」を述べた文は
  ADR にも worklog にも無い。**条文化は書き写しではなく、根拠を初めて書く作業になる**
- **本タスクは凍結資産の取り込み費用を払う。** 要追随の筆頭 `R:1129` は、
  **TSK-509 が触って `contracts/authz/` の 5 段連鎖を壊し、PO 裁定で取り下げたその行**である
- **要追随は 7 箇所。うち 5 箇所は (i)〜(iii) の結論が先に決まらないと文面を確定できない** —
  **ADR と要件書を 1 ゲートで通す判断の裏づけ**
- **(iv) はそのままの向きでは判定できない**が、**逆向きの包絡は付録A 40 行すべてで作った**

### 4. (iv) (β) の必須集計の変換可否

- **D-1-d は v0.1 反映 1 周目で入った**。根拠は **NFR-005 とブロック 4 の DB 側集計の規律**(`ADR:20`・`:115`)
- **D-1 のもとで必須集計の変換可否を判定した記録は無い**(走査「変換可否|変換可能な部分集合|必須集計」の全 docs 走査)
- **そのままの向きでは判定できない** — 部分集合の具体は段階 2(TSK-538)が定める(`ADR:793`)
- **逆向きの包絡を付録A 40 行すべてで作った**(下表)

**包絡(演算の種類 × 該当行数)**: S(単純集計)37 / **P(走者単位の数量・状態計算の出力に依存)11** /
R(比率と丸め)14 / V(語彙 join)約 14 / T2(行順序・前後状態)7 / N(入れ子の集約)5 / Z(座標の領域判定)3 /
B(ビン生成)2 / L(行リスト)2 / T1(時系列)1 / C(設定値)1。

**SQL で素直に書けなさそうなもの — 6 件 → 9 件に増えた**(新規 3 件は【新】):

1. **【新】与四球** — 打席途中の交代では、**交代時のカウントがボール優勢かどうかで帰属先が変わる**(`R:1187`)。行の順序に依存
2. **失点・打点・得点/失点** — 走者単位の数量。**打点フラグは真偽値で点数を持たない**(`R:1163`)
3. **コース分布・コース別打率マップ** — **区画の定義が無い**(`R:1289` が定めるのはゾーン内外の境界だけ)。密度表示の定義も無い
4. **打球方向** — 多角形シードと先勝ちの規則。範囲は標準 PostgreSQL(`R:1061`)
5. **【新】コース別打率マップの結果球の特定** — 打席の最後の球を特定する必要がある(`R:1143`)
6. **A-4 の成否判定(#26〜#32)** — プレイ前後の走者状態の比較
7. **【新】イニング別の「そのイニングを戦った試合数」** — **X 表記になった裏を「戦った」に数えるかの定義が無い**(`R:459-463`)
8. **被打球分布・打球方向の散布** — reducer ではなく**行リスト**
9. **球速分布** — **球速の型(整数か小数か)が要件書に無く**、ビン化の演算を確定できない

**横断的な前提が要件書に無い(重要)**: 23 フラグ・アウト数・得点・塁打・打点の数量・走者の前後状態は
**(α) の状態計算が出す行ごとの出力**だが、**6.1 が毎球データへの保存を明記しているのは走者ごとの責任投手だけ**(`R:1025`)。
**フラグや数量を DB へ保存するかは書かれていない。** 保存しない場合、**ほぼすべての計数が SQL reducer の外に出る**(推論)。
