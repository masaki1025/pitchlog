# TSK-544 T1 P-8先行単位・計画最小追補候補

2026-10-20。承認済み[plan.md](plan.md)と[design.md](design.md) §4のP-1〜P-9、PR-1a/1bの2ステップ、既存レビュー履歴とFR-040延期を維持する。正式契約・正本・凍結値・製品計算コードは変更しない。本書は6.1計画レビュー用の**候補**であり、人間による追補承認と契約所有側の編集受理を代替しない。

## 現計画の射程と追補の最小差分

現計画§2「やらないこと」は「T1・T2の残る契約整備」を明示的に除外し、§3の`contracts/`は「本タスクは反映なし」とする。一方§4のPR-1aはS05〜S32のT1分の照合と契約所有側ゲートへの送付を要求する。従って**既存のT1入力・caseとP-8不足を照合し候補を送る準備**は§4の範囲内、**未収録の規範行・case・負例そのものの作成と正式契約への反映**は現計画の対象外である。

最小追補案は次の3箇所に限る。§2「やること」へ「TSK-544はPR-1aに先立ち、T1のP-8不足について原典照合と入力制約・規範行/case/負例の**別ファイル候補**を作る。TSK-545/T2、分析40行、TSK-538既済み行は対象外」を追加し、現§2「やらないこと」の契約整備除外には「ただし、正式契約に触れない本候補作成は除く」を付記する。§3の既存`contracts/`行は**置換せず全文を維持**し、末尾に「本先行単位はfeature文書の候補のみ。正式編集・受理者はdesign.md §8 J-7に基づきPO/Claude調整役が指名し、未指名の間は共有契約を編集しない。必要な正本・7.7・P-6ゲートは別に行う」を追記する。§3のfeature文書行へ本候補ファイルと今後の`tsk544-p8-candidates/`を追加する。§4の2製品ステップ、着手条件、合格条件、コミット記法は変えない。2026-10-14のTSK-544宛の残件送付（[worklog](../../worklog/2026-10-10-ux1-state-calc.md) 2026-10-18節「(b)項目の処遇」）は**候補作成・照合の責任**として記録し、TSK-544自身による正式受理へ読み替えない。この役割整理と先行候補の計画追加はPO承認対象。

§5-1へ先行単位のDoDを追記する案: 「対象・対象外をIDごとに照合した`tsk544-p8-candidates/`内の別ファイル候補と、原典ID、入力の正常/欠落/重複/矛盾、規範行・case・負例ID、未裁定項目、作成者、独立検証候補の対応、正式受取担当の指名・受領状況を記録する。**未裁定単位では規範行・case・負例IDを『未裁定』と記録すれば足り、値を創作しない**。候補の記録コミットは本feature枝の計画追補成果として別に固定し、正式契約は含めない。正式PRの提出・統合は既存の承認経路に従う」。先行単位のDoD達成はP-8成立、PR-1a着手、正式契約受理を意味しない。

## 先行検査・レビューと停止点

追補承認後、候補を正式契約外に作る順序はA→C→B→D/E/F/G/Hとする。裁定前は各単位の原典照合だけを進め、裁定後にCの有効得点の照合結果をBのRBIとFのサヨナラへ受け渡す。各候補には原典ID、入力の正常/欠落/重複/矛盾、規範行ID、case ID、期待値**候補の作成者**、P-6独立検証対象を明示する。未裁定の欄は「未裁定」と記す。P-6検証者はPOが指名し、候補作成者・実装者・本6.1レビュアを兼ねない。作成者自身の期待値確認、今回の6.1レビューはP-6にもP-8受理にも数えない。正式契約の編集所有・schema/descriptor/行/case/負例/7.7・正本改訂の要否はPO指名の契約受取者と別に確定する。受理前は共有ファイルを編集せず、T1製品計算を始めない。

6.1レビューの対象はこの追補候補、現[plan.md](plan.md)§2/3/4/5と[design.md](design.md)§4への影響だけ。旧計画レビュー周回5、採否、最終回P0限定という履歴を維持する。今回の追補は別のレビュー対象として全文1回（初回P0=0/P1=8/P2=5）を実施済み。反映差分の2回目レビューを行い、追加の周回として**累計7回**に計上する案。追加レビューの根拠は今回のPO「最小追補の起案・既定計画レビューまで」の指示だが、既存5回への追加回数の正式解釈はPO判断対象とし、無断でplan.mdのカウンタを変えない。レビュー完了だけで計画追補・J1〜J6・P-6/P-8を承認済みにしない。
