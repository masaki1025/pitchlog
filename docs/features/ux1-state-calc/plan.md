## 4. 実装方針

**重さ分類 = コア領域**。状況計算は game-state × sync-protocol の重複帰属(`docs/features/product-impl-unit-split/design.md:103` — 同期プロトコルが「サーバー再計算/補正」を含み、FR-040 は状態補正)。計画書は敵対レビュー(設計書 `:381`)、第 1 PR は敵対レビュー + 人間の逐行確認(設計書 `:383`・`:389`・`:391`)。

詳細設計は [design.md](design.md) に分けた。要点:

- **対象計算 6 件・PR 3 本**([design.md](design.md) §1〜§2)。マージ条件は「当該対象について全検査が緑」(`ADR-003:931`)で BOOT-GRANT の免除は効かない(要件書 `:962`)ため、ベクタの揃い方で PR を分ける
- **着手条件 P-1〜P-9**([design.md](design.md) §4)。PR-1だけはD-14-mの対象別条件で判定し、**1つでも欠けたら製品計算コードを追加しない**。段階①全体・D-2全体の発効はPR-1の着手前条件から外れるが、PR-2〜4・分析40行には波及しない
- **T1/T2の方式**([design.md](design.md) §5-2): TS正本を再現ビルドして得る**同一JS artifact**をブラウザと常駐Nodeで実行する。TS正本・生成器・artifactのパスはTSK-538の承認済み基盤契約を用い、実T1/T2の識別値は対象追加PRのmanifestで宣言する。別言語の手書き計算を加えない
- **1 対象 = 1 コミット**([design.md](design.md) §5-1)。正本・派生物・呼び出し部・3 層検査を 1 コミットに入れる(`ADR-003:930`。マニフェストは対象ごとに `vectors[]` / `properties[]` / `mutation` の空を許さない `ADR-003:267`)
