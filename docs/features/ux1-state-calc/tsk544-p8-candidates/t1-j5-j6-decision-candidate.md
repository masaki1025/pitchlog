**J6（付録A-1の非本塁打サヨナラ得点、付録E-1の入力型へ追記）**: 「後攻が同点または負けている局面の非本塁打プレイで、有効生還候補が2人以上いるときは、記録員が観測した本塁接触の先後を`event.perPitch.homeTouchOrder`で渡す。時刻、位置、最終得点、現在の塁状況から順序を推定しない。第3アウト時はOUT3-01〜05に従い無効得点を先に除外し、残る観測順序の先頭から決勝点成立までを算入する。本塁打は有効な全生還を算入し、非本塁打の上限を適用しない。RBI-01〜09は、上限・第3アウト処理後に有効な得点走者ごとに判定する。第3アウトの観測と順序観測が欠落、重複、矛盾または参照越境なら、得点・RBIを推測せず拒否する。」

**候補型**（付録E-1の出力10列は維持し、入力軸のみ追加）:

```text
HomeTouchOrderV1 =
  | { kind: "not-required" }
  | { kind: "observed", scorers: [ScorerRef, ...] }
ScorerRef =
  | { kind: "runner", runner_id: PlayerRecordId }
  | { kind: "batter", batter_id: PlayerRecordId }
```

`scorers`は1〜4人の順序付き一意列で、当該プレイで本塁に実際に触れた者のexact-setを保持する。OUT3で得点無効になる者も観測事実から消さず、計算時に除外する。IDは同一試合・同一チーム・同一適用scopeで解決済みの出場者名簿と照合する。`not-required`はこのイベントで非本塁打の複数有効生還候補の順序を使わない場合だけ許す。必要局面での欠落・`not-required`、空列、重複、候補欠損/余剰、別試合/別チームID、曖昧な同着は拒否する。送信元の一時IDはU-S1の既存P2解決規則を通し、原wireと確定IDを混同しない。外形拒否S-1と意味拒否の結果ID/消費順はU-S1・506の公開境界で確定し、この候補だけで新結果IDを創設しない。

**保存・再送・取消**: V7の原wireに順序列とcodec版を含め、同一D5の指紋は配列順まで区別する。V7原観測と適用時の確定参照を再現可能に保存し、同D5で順序・内容・codec版を変更した再送は既存指紋不一致境界で拒否する。取消・再実行は保存済みの同一観測と前提履歴から評価し、現在のUI下書きや名簿から再推定しない。**U-S1は責任境界だけ条件付き受理**し、現行保存は`projected_event`のpayloadで原wire/codec版の物理保存、正式wire位置、resolver、undo接続は未提供。ここは正式契約・DDL/型/実装の別ゲートで閉じるまでP-7/P-8成立としない。
