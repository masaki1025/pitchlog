## 型差分候補

E-1の出力10列を増やさず、**perPitchの入力**へ`homeTouchOrder`を1フィールド追加する。既存`runnerEventPayload`はrunner-event用、`officialScoringPayload`は失策等の公式記録用であり、打撃結果にも共通する生還順をそこへ詰め込まない。descriptorには軸`event.perPitch.homeTouchOrder`を追加し、現行の入力軸exact-setとschema/digestを正式ゲートで追随する。候補の閉型:

```text
HomeTouchOrderV1 =
  | {kind: "not-required"}
  | {kind: "observed", scorers: [ScorerRef, ...]}  // 1〜4件、順序付き、重複なし
ScorerRef = {kind: "runner", runnerId: ID} | {kind: "batter", batterId: ID}
```

`not-required`を許すのは、そのイベントで非本塁打のサヨナラ上限の選択に生還順を使わない場合だけ。**裏の同点/負け局面で非本塁打の同プレイに有効生還候補が2人以上いる場合**は`observed`を必須とする。IDは認証済みの同一試合・同一prefixの確定名簿と突合する。`scorers`は本塁に実際に触れた打者/走者のうち当該プレイの生還候補のexact-setとし、OUT3で無効になる者も観測事実として残す。OUT3判定後、リストから無効得点を除外した順序で決勝点まで計上する。本塁打は付録A-1どおり有効な全生還を計上し、順序の有無で打点や得点を変えない。順序が曖昧・同着としか観測できない場合は`observed`を捏造せず入力不足として拒否する。必要な上限対象局面で`not-required`、空/重複/欠損ID、得点候補集合との不一致、他試合IDを拒否する。`scorers`配列の並びが唯一の順序権威で、タイムスタンプや座標を併用しない。

**入力所有**: U-F8が記録員の選択を画面下書きからwireへ欠落なく渡し、506はwireの型・重複キーを外形で扱い、U-S1は同一D5の原wire/codec版とともに保存・再掲し、T1単一計算核が適用時に同一scopeで参照する候補。具体DTO/Port署名と各担当の受理は未取得。取り消しは当該受理イベントと`homeTouchOrder`を差分/原入力に保持して再実行し、端末の現在表示・変更後名簿から後付け推定しない。再送は同一D5・同一内容/codec版の指紋一致を条件にDI2へ接続し、順序だけ変えた再送を同じD5で受理しない。保存形式とundo/replayの実接続は実装後に検証する。

U-S1の2026-10-20の項目別回答（`feature-us1-sync-port-surface` HEAD `695a4faf`）は、**順序保持・同一D5の順序変更拒否・保存観測からのundo再評価という責任境界を受理**した。ただし現行保存は`projected_event`のpayloadであり、原wire全体/codec版の保存経路ではない。既存指紋がV7の閉payload内の配列順を区別した読取プローブ3件は、J6の新wire/保存/undoの実提供証拠ではない。候補の`runnerId`/`batterId`というcamelCase名も現行U-S1の参照解決列挙に無い。**正式field名・payload位置・参照型/越境検査・原観測保存先をU-X1/506/U-S1で一致させるまで、型の正式受理や実Port提供とは扱わない。**上の所有記述は提案であり、現存する保存機能の説明ではない。

## 7.3/6.1の対象と影響

J5のXC-13/D-11限定改訂と同じ「T1着手前に閉入力と規範caseを確定する」目的・同一正本（要件書/ADR）に属するため、**候補としては一括の7.3レビューに載せる案**を推奨する。ただしJ6は既存入力軸に新しい観測fieldを加えるので、既承認J5の「解釈だけ」の射程から増える。計画の先行単位は候補作成までで正式資産反映を含まないため、7.3の射程追加と正式契約編集担当の指名/計画追補をPOへ示してから正本・凍結資産を編集する。要求書付録A-1に観測事実と評価順をT1に限り追記、付録E-1に`homeTouchOrder`入力と拒否を追記、ADR D-11にdescriptor追随、descriptor/schema/golden/manual/negative/handoffのdigest・7.7履歴を別の正式ゲートで扱う。既存ケースの入力は「順序不要」variantへ明示的に写し、暗黙の既定値で移行しない。既存受理履歴は上書きしない。
