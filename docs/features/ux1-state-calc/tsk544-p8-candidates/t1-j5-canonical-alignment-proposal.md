## 正本の既存文言との緊張

要件書v2.15付録E-1 XC-13（現行1467行）は、23フラグの導出表、第3アウト種別、記録員判断入力を「段階2で実機とともに確定」とする。同1595行は23キー全件、閉じた観測入力、双方向負例、欠落/曖昧/相反のfailを**同時**に揃えるよう要求する。ADR-003 v0.8 D-11（現行222〜224行）も同じ委任を記す。一方、承認済みdesign §4 P-8と2026-10-20のPO裁定は、T1の閉入力・拒否条件・規範case・必要な独立期待値を**製品計算コード着手前**に正式受理し、実装後でないと得られない接続/検証証跡だけをPR-1a内へ置く。現行「実機」を製品T1完成後だけと読むと循環するため、対象限定の解釈を正本に明記する。

## レビューで判定する点

1. 「実機」を既存のベクタ/検査基盤と読む対象限定例外が、2026-09-26の2回の射程縮小の理由と矛盾しないか。矛盾する場合は、着手前条件を緩めず、必要な別の正本改訂案を出す。
2. 23キー必要十分表を実体のない段階で確定して同じ穴を再発させないため、既存runner・fixtureでどこまで具体的に検証できるか。
3. 要件書・ADR・descriptor・schema・handoffの射影、付録E-1 exact型の維持、S20の表現可否。
4. 第1回全文と反映差分、コア領域レビュー、本人への最終差分提示、正式7.3承認の範囲。今回のPO方針を正式条文承認として扱わない。

## 7.3へ載せる最終候補の境界と、J6の射程追加

上の3段落が**J5の本文候補**である。正式反映時は要件書v2.15→次版、ADR-003 v0.8→次版の`in-review`化、変更履歴の「今回確定する範囲/実装時に確定する範囲」、索引、適用する7.3版と条文コミットを同じゲートに記録する。初回は対象2正本の**全文**、第2回は採用反映差分と影響節をレビューする。既済みの計画6.1レビュー2周・候補レビュー2周はこの7.3回数へ算入しない。各レビュー指摘のP0/P1/P2・起因・(A)/(B)/(-)・採否を作業ログへ保存し、人間には最終差分と未再レビュー残余を示す。現時点では正本はapprovedのままで、7.3初回は未実施。

J6の[生還順候補](t1-j6-home-arrival-order.md)はJ5だけの「実機とともに」の時点解釈と異なり、付録A-1/E-1へ**新しい観測入力と拒否条件**を追加する。1つの7.3ゲートで要件書/ADRを整合させる方が、T1着手前に必要な閉入力とその確定時点を同じ版で審査できる。ただし現行承認済み[計画](../plan.md)§2/§3/§5-1は本タスクの作業を**feature文書の候補作成**までとし、正本や`contracts/`への正式反映を範囲外としている。よって同一ゲートを始めるには、POの追加射程裁定と以下の**最小計画追補**が必要:
