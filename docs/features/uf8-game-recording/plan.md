# 実装計画書: U-F8 試合記録・再開・修正(第 1 期)

## 1. 背景・目的

**Notion**: [TSK-523 U-F8 試合記録・再開・修正(GameScreen ほか 5 画面)](https://app.notion.com/p/3f493b75e68781b49976fc6c5ed970d5)

旧 frontend の試合記録画面群(`dd03160` で **130 ファイル・39,216 行**、うち U-F8 の対象が **約 16,300 行**)を製品へ作り直す。**リハーサル最小集合の中核**がここにある。

**担う FR の面**: FR-001〜006・008〜011・040 の記録・再開・修正の面、FR-020〜023 の記録中の表示面。加えて帰属の正([`frontend-impl-units/design.md` 6.3](../frontend-impl-units/design.md))が U-F8 に置く FR-012・013・014・015・016・019・024・031・036 の分担行。**主所有はいずれも動かない。**

**非 FR の受け先**: 要件書 4.0-4 の断中動作 / `NFR-006` の鮮度表示(Must)/ `NFR-007` の `E4` / `NFR-019` の `E5` / `NFR-020` の 375px 幅。

調査の結論は [research.md](./research.md)、設計は [design.md](./design.md)。

### 1-1. この計画が「第 1 期」である理由

**PO 裁定(2026-10-16)**: U-X1 が凍結中で `ProjectionPort` を所有するため、**計算核に接続した受入は完了できない**。先行できるのは「画面実装・通信層・キューの受け取り口・表示・PR 分割の設計・契約ベースのモック相手の試験」まで。

**あわせて機構上の制約がある**: コア領域の paths を足す**先行追加層の窓口が U-S1 系で塞がっている**(`scripts/core_guard.py` の `AREA_PATH_ADDITIONS`)。窓口は回転式で累積できないため、**新しいファイルを置く PR は U-S1 の着地を待つ**。

**したがって本計画の射程は、既に登録済みの paths の範囲で作れる分に限る。** 残りは窓口が空いた後の後続計画とする(先例: PR #125 が「この PR は U-F8 全体の完了ではない」と明記して一部を先行させた)。
