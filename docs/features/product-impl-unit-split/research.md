# 調査メモ: 製品機能の実装単位を分割する(TSK-363)

## 問い

**backend の製品機能の実装単位をどう切るか。** 母集団は何か、**何が着手を縛るか**、
**コア領域に触れない「器」を先行して切り出せるか**。

## 結論(要約)

1. **母集団は FR-001〜FR-042 の 42 件**(欠番なし・**4 通りの独立検算が一致**)。
   **`backend/src` に FR の振る舞いを実装したものは 0 件**。
2. **着手を縛る条文は 2 本だけ** — **6.1 の計画書ゲート**と **ADR-003 の 4 段階**
   (**後者は `NFR-018` の対象計算に触れる単位にのみ掛かる**)。
3. **`data-model.md` 12-4 は「マージ条件」であって「着手条件」ではない** —
   条文は「**マージまたは有効化しない**」。**着手・実装・レビューまでは進められる。**
4. **器の先行切り出しは機械判定上は成立する** — `core-areas.json` に
   **`backend/src/` 全体を覆うパターンは 1 本も無い**。覆われているのは
   **`db/` の個別 8 ファイル + 5 サブパッケージ**と **`authz/*`** のみ。
5. **ただし意味範囲では「API 直叩き」がテナント分離に含まれる** —
   **テナントデータを返す API は paths に載っていなくてもコアに当たり得る**。
6. **ドメイン計算系は実装を開始できない** — **付録 A の固定ベクタと付録 E の全表が未整備**で、
   要件書が **fail-closed**(「当該計算の実装を開始せず」)を定めている。

**帰結**: **いますぐ着手できるのは「ドメイン計算に触れない FR」+「テナントデータを返さない器」**。

## 訂正 — 本調査で撤回した誤り

**「backend のコードを書くタスクが 1 件も起票されていない」は誤りだった。**

| 誤り | 実測 |
| --- | --- |
| 「製品コードを書くタスクが 0 件」 | **TSK-280 / 319 / 320 / 321**(同期プロトコル)・**TSK-343**(ORM)・**TSK-317**(認可 DDL)が**既に製品コードを産んでいる** |
| 正しい言い方 | **「製品 HTTP 経路(API)の実装タスク」が 0 件**。`docs/features/merge-gate-api-cycle/research.md:362` の「なし」は **API に限った記述** |

**`backend/src` に FR の振る舞いを実装したものが 0 件**なのは事実だが、**「タスクが起票されていない」と一般化したのが誤り**。
**同種の訂正記録が過去にもある**(`docs/worklog/2026-09-01-adr003-display-primitives.md:74`)。

#### 3-2. **12-4 は着手を縛らない**(本調査の中心的発見)

条文の逐語(`data-model.md:2428`)は「**DB を利用する製品機能をマージまたは有効化しない**」。
**「着手しない」とは書かれていない。**

**→ DB を使う単位を「着手してよいが TSK-317 完了までマージしない」形に並べることは条文に反しない。**

**同じ結論が過去にも記録されている**(`docs/worklog/2026-09-08-handover.md:275-281`):

> **上の連鎖は「正本の要求」ではなく自分で課した順序だった** —
> **実際の拘束は 6.1 の計画書ゲートと ADR-003 の導入順序の 2 つだけ**

#### 3-3. ドメイン計算系は**実装を開始できない**

| 典拠 | 逐語 |
| --- | --- |
| 要件書 `:915` | **付録 A の固定ベクタと付録 E の全表はいずれも現時点で未整備**であり…**完成前に `NFR-019(a)` を合格と判定してはならない** |
| 要件書 `:891` | **いずれの区分にも割り当てられない対象計算が生じた場合は、当該計算の実装を開始せず**、本書の改訂で区分を確定する |

**→ カードの「DB 系とドメイン計算系を混ぜない」は、この条文の帰結である。**

### 4. コア領域の機械判定 — **器は切り出せる**

`scripts/core_guard.py` の `load_core_areas` / `matched_paths` を実行した結果。

| 仮想パス | 判定 |
| --- | --- |
| `backend/src/pitchlog/api/routes.py` / `schemas.py` / `errors.py` | **非コア** |
| `backend/src/pitchlog/domain/scoring.py` | **非コア** |
| `backend/src/pitchlog/sync/apply.py` | **非コア** |
| `backend/src/pitchlog/repositories/game.py` | **非コア** |
| `backend/src/pitchlog/services/lineup.py` | **非コア** |

**7 件すべて非コア。`guard_paths` 完全一致もゼロ。**

**`backend/src/` 全体を覆うパターンは 1 本も存在しない。** 覆われているのは:

| 領域 | `backend/src/` を覆うパターン |
| --- | --- |
| 5 領域すべて | `db/` の共通 8 ファイル(`__init__` `all_models` `base` `config` `engine` `mixins` `model_metadata` `url`) |
| 各領域 | `db/<領域名>/*`(5 サブパッケージ) |
| `tenant-isolation` のみ | **`backend/src/pitchlog/authz/*`** |

#### 4-1. **踏んではいけない地雷 6 件**(実測)

| 地雷 | 影響する領域 | 理由 |
| --- | --- | --- |
| `backend/pyproject.toml` / `backend/uv.lock` を触る | **5 領域全部** | 直接登録 |
| `backend/migrations/*` を触る | **5 領域全部** | 直接登録 |
| テストを `backend/tests/db/` に置く | **5 領域全部** | `backend/tests/db/*` |
| **`conftest.py` を `backend/` 配下のどこかに新設** | `tenant-isolation` | **`backend/*conftest.py` の `*` が `/` を跨ぐので全階層にマッチ** |
| テスト名に `test_authz` を使う | `tenant-isolation` | `backend/tests/test_authz*.py` |
| `backend/src/pitchlog/db/` に足す | 該当領域 | 直接登録 |

> **`pydantic 2.13.4` は `backend/uv.lock` に解決済み**(`fastapi[standard]` 経由)。
> **DTO を書くのに `pyproject.toml` を触る必要はない。**

#### 4-2. **機械判定 ≠ ゲート全体**(重要な留保)

**意味範囲の正は設計書 6.3 の境界定義表**(`dev-harness-design-2026-08-07.md:376`)。同表の該当欄:

| 領域 | 器にとって | 逐語 |
| --- | --- | --- |
| 同期プロトコル | **有利** | 「**同期セマンティクスを持たない単純な CRUD 通信** — 通常レビュー」(`:385`) |
| 記録権 | **有利** | 「**認可判定を伴わない権限の表示制御** — 通常レビュー」(`:387`) |
| **テナント分離** | **不利** | 「**全出力経路の越境**(…**API 直叩き**…)」を**含む**(`:388`) |

**→ 器を非コアで通すなら「テナントデータを返さない器」に限る。**
**実データを返す 1 行目が入った時点でテナント分離のコア判定へ移る**、という切り方が 6.3 と整合する。

#### 4-3. 設計書 6.3 規則④ が本タスクの設計目標を支持している

`dev-harness-design-2026-08-07.md:391`:

> ④ 過剰包含は PR 単位の例外で外さず、**モジュール分割で境界を切ってから paths を狭める**

**カードの設計目標は 6.3-④ の適用そのものとして正当化できる。**

**ただし規則①・⑤ も同時に効く** — **器を `api/` に切り出した後、判定ロジックを `domain/` に入れる段で
`core-areas.json` への paths 追加が必要になり、その追加自体が敵対レビュー + 人間承認のゲートを通る。**
