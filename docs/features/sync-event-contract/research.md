# 調査メモ: 同期プロトコル 4 章「イベント契約の骨格」を frontend に実装するための下調べ

## 問い

`docs/design/sync-protocol.md`(approved v0.1)の **4 章**を `frontend/src/` に TypeScript の型 + 実行時検査として実装するにあたり、
① 何が要件として掛かるか ② 正本のどこまでが「写すだけ」で、どこからが実装の裁量か ③ 旧システムに移植元はあるか
④ 射程「4 章のみ」は成立するか ⑤ 後続改訂で手戻りしないか。

**方法**: 調査サブエージェント 3 本(spec-checker / legacy-analyst / decision-tracer)を並列 + **Claude による原典の直接確認**。
本メモで **◎** を付けた事実は Claude が原典を直接読んで確認したもの(設計書 8.5)。

## 結論(要約)

1. **射程「4 章のみ」は文字どおりには成立しない。** 4-3 の V6・V8 の必須区分が **5-5 の参加区分表**へ委ねられており(`docs/design/sync-protocol.md:257`・`:259`)、
   イベント種別の exact-set(#1〜#12)はその表にしかない(`:573-591`)。**「4 章 + 5-5 の参加区分表を参照する(再記述しない)」**へ射程を書き直す必要がある。
2. **Notion カードの FR 10 件は過大かつ過小。** 11-3 で 4 章に対応箇所を持つのは **FR-007・008・011・012・015・040 の 6 件**。
   カード外の付録D/D-3・4.0-4(いずれも「同期側で決める」区分)が 4 章に割り当てられている。
3. **カードの DoD「`NFR-019(d)` の故障系テストがある」は本射程では満たせない。** (d) の列挙 6 項目はすべてサーバー適用・キュー・タブ間ロックを前提とする
   (要件書 `:926-930`・`docs/design/sync-protocol.md:1677-1678`)。**人間の裁定が要る**(下記 6-①)。
4. **4 章は「意味上必須な値と不変条件」までで、型を決めない**と明言している(`:222`)。TS の型を書く行為が D1/D2/D5 の数値型を事実上固定するため、
   **「TS 型は正本の型決定ではない」**ことを計画書で宣言する必要がある((B) 論点 17・18・26 — `:1535`・`:1536`・`:1544`)。
5. **旧システムに移植元は無い。** FR-012・FR-013 は TSK-226 の判定で **×**。さらに**移植すると要件違反になる逆実装が 3 件**、イベント契約に直撃する。
6. **後続改訂(v0.2 / TSK-267)は 4 章の墓標まわりを変える蓋然性が高い**(V9・V10・V2・5-5 #8・4-5 の B3a/B3b)。P3・V11・V12・C1〜C4 は射程外で安全。
