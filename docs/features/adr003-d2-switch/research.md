# 調査メモ: ADR-003 の見直しトリガー第 1 項の発火 — D-1(DSL)から D-2(JS 実行)への切り替えの判定

## 問い

1. 「式の文法は ADR の確定ゲートを通っていない」は本当か(**改訂の射程を決める**)
2. U-X1 の 4 値の内訳はどれが正か(Notion カードと直接連絡が食い違っていた)
3. D-2 の費用の実測はあるか
4. 表現不能 5 件は要件のどこから要求されているか
5. 方式を変えると要件書のどこに波及するか
6. 段階 1 の現況

調査は 3 並列(decision-tracer / spec-checker / Explore)。**報告のうち判定を左右するものは、本タスクが原典で追試した**(追試した箇所は「**追試済み**」と書く)。

## 結論(要約)

- **D-1 の実行経路は存在しない。** 生成器 3 言語がすべて固定スタブである(**追試済み**)。したがって「D-1 拡張」と「D-2 切替」は、**どちらも実行経路をこれから作る**点で同じ土俵にある。捨てる資産の差は小さい。
- **文法(式 8 種・ガード = 単一の比較式・論理結合子なし)は実装由来**。ADR が確定ゲートで決めたのは**語彙の範囲**だけ。本タスクは「改訂」と「初めての決定」の中間にある(**追試済み** — `578f9583`)。
- **4 値の正は 5 / 16 / 0 / 7**。**表現可能は 0 件**。Notion カード本文の `5 / 6 / 10 / 7` は初回提出の古い値。
- **D-2 の費用は実測ゼロ**。v0.2 が D-2 を見送った 3 理由は、**いずれも v0.2 の文脈に限定された相対判断**であり、D-2 そのものの否定ではない(**追試済み** — 逐語確認)。
- **新たな論点**: NFR-018 (b)③ の**動的機構の禁止**が D-2 と正面から緊張する可能性がある。**ADR はこの点を検討していない。**

### 6. v0.2 の 3 理由は D-2 の否定ではない(**追試済み** — 逐語)

### 8. 新たな論点 — NFR-018 (b)③ の動的機構の禁止が D-2 と緊張する

要件書 `:952`(逐語):

> **動的機構の禁止**(動的コード生成・**非リテラルな動的読み込み**・**外部スクリプトの実行**を禁止し、違反を検出する。…)/ **構成の照合**(…**サーバー側も同等に閉じる**)

**D-2 はサーバーで JS artifact を QuickJS / 常駐 Node に読み込んで実行する。** これが「外部スクリプトの実行」「非リテラルな動的読み込み」に当たるかは解釈が要る。**ADR-003 はこの緊張を検討していない**(`ADR-003:121` の却下理由に (b)③ への言及が無い)。

**これは費用の問題ではなく適合性の問題**であり、**D-2 を採る場合は (b)③ の解釈を確定させる必要がある**。クライアント側も、artifact を通常のバンドル以外(Worker・別配信)で読む場合は入口の全列挙(`:952`)の対象になる。

あわせて 7.1(`:1060`)「**サーバーはステートレス**(プロセス内に試合状態を持たない)」— 常駐 Node 案はこれを満たす構成にする必要がある。7.1(`:1059`)の技術スタックの**変更に当たるかは条文からは判定できない**。

### 9. 要件書は方式を固定していない。ただし D-1 前提の文言が 10 箇所

→ **D-2 を採る場合、要件書の改訂が要る。** とくに `:1129` と `:1169` は内容が事実と食い違う。

### 10. 整数符号化(判定者の判断事項)

`ux1-game-state-core/research.md:508-526`。四則と min・max だけで指示関数を作れる。

```
[x ≥ k]            max(0, min(1, x − k + 1))
[x = k]            1 − min(1, max(x − k, k − x))
否定・論理積・論理和  1 − a / a·b / a + b − a·b
a なら x でなければ y  a·x + (1 − a)·y
```

**陽性対照つきで確認されている**(同 `:581`): ①条件ノードは schema 検証で拒否 ②同一イベントに遷移 2 本は生成前検査で違反 ③整数状態へ比較式を代入すると生成前検査で違反 — **検証器が違反を実際に拾うことを確かめた**。

- **代償**: 状態とイベントをすべて整数で符号化する必要がある / 式が大きくなる(C1 だけで 3 フィールド・十数ノード。全体の規模は未測)
- **条文との関係**: `ADR-003:103`「**条件分岐…は引き続き書けない**」。**射程の語だけを使うので条文には反しないが、条文の意図と緊張する**
- **許さない場合**: 状態の層で書けた 10 件のうち **7 件**(C1・C2・C9・C14・C16・C17・C27)が状態の層でも書けなくなる(同 `:659`・`:672`)

**この禁止は原文の位置からは表示規則に掛かる制約として書かれている**(表示規則 3 類を述べた直後)。射程には「ガード / 次状態」が含まれるので、**DSL 全体に条件分岐を禁じる趣旨と読めるかは文言上はっきりしない**(decision-tracer の解釈。本タスクも同意)。

### 14-3. 宣言モデル schema は descriptor の派生物である(**追試済み** — 逐語)

ADR-003 v0.4 の D-11(`:208`):

> 状態軸・イベント軸、終了判定の軸、coverage 軸ではない保持対象、および軸どうしの組合せ規則の
> **唯一の正は入力軸 descriptor**である。…**宣言モデル schema は descriptor に拘束される派生物とする。**
> schema は descriptor の `descriptorId` / `version` / `digest` を参照し、
> 軸の exact-set または値域が一致しない場合は manifest へ登録できない。判定不能も fail とする。

同 `:209`(射影規則): **「schema が軸を追加・削除・再解釈することを許さない。」**

**帰結(本タスクの解釈)**: **D-1 を拡張するには、宣言モデル schema を書き換えるだけでは済まない。**
入力軸 descriptor が唯一の正であり、descriptor は D-11 の規範として ADR から導出される。
**schema 側の一存で軸を足せない。**

**ただし効く範囲は入力側に限られる**:

| 候補 | 側 | descriptor 拘束の影響 |
| --- | --- | --- |
| **C4** 履歴の読み出し / **C13** 閉じない列挙 | **入力** | **効く**。descriptor の改訂が要る |
| **C3** 出力の導出式 / **C10・C12** 可変長・行リスト | **出力** | 直接は効かない(出力側を定める規定が schema に無いことが C3 の根拠) |

**ステップ 3 では、5 件を「入力側 / 出力側」に分けて評価する。**
入力側は descriptor の改訂を伴うため、**D-11 への波及**が生じうる(射程宣言の「実装時に確定する範囲」で
D-11 の追随を挙げているが、**本改訂で波及が確定した場合は ADR へ記録して送る**)。

なお C14 の「最大長」は v0.4 で **descriptor で閉じる**に変わり、`tierCount` の上限は 16(TSK-405 報告・未追試)。
