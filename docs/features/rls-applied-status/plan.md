## 1. 背景・目的

**Notion タスク**: [12-4 ④ と 12-8 の「まだ実スキーマへ適用されていない」を現況へ追随させる(TSK-344 の後続)](https://app.notion.com/p/3f293b75e6878138acddd4907dca9f41)

**本タスクはその追随だけを行う。** v0.6 の射程宣言(設計書 7.3-7)が、この更新を **「TSK-344 の後続タスク」へ名指しで割り当てている** — 変更履歴 v0.6 の行(`:11`)の「実装時に確定する範囲」に次の一文がある:

### `未発効` の扱い — 一律に消さず、一律に残さない

**`未発効 = 本番未配備` は v0.6 から導けない**(確定ゲート 1 周目 `P1`)。v0.6 は `未発効` と書く理由を次のように説明している(`:2598`):

> 使い捨てのクラスタでの検査は資産と適用器の検証であり、配備先への適用の検証ではない(12-8 節…の行が、**使い捨てクラスタでの確認を「未発効」と書くのはこのため**である)

一方で、**ランタイム契約の `PROVISIONAL` は既に `False`** である(`backend/src/pitchlog/authz/runtime_contract.py:7` — 実測)。**したがって `未発効` は「ランタイム契約が暫定」の意味でもない。**

**よって次のように分ける**:

| 種別 | 扱い |
| --- | --- |
| **各 PR が何を検証したかの記録**(「PR A2 = 使い捨てクラスタで確認済み・未発効」など) | **当時の段階の記録なので変えない** |
| **行末の現在の状態の要約**(「製品の資産はまだ実スキーマへ適用されていない」) | **現況へ直す。「#97 が専用の検証対象への適用を確認した」ことだけを書き、本番の配備先への適用状況は本記録の対象外と明記する** |

**本番への未適用を断定しない**(確定ゲート 2 周目 `P1`)。`:2598` が述べているのは「**使い捨てクラスタでの検査では配備先への適用を検証できない**」ことであって、**本番で未実施であることの証拠ではない**。本書は本番の配備先の状態を観測していないので、**「まだ行われていない」と書けば新しい偽を作る**。

### DoD 6 を外した理由(射程の縮小 — 人間の承認を要する)

当初は本タスクで TSK-344 の DoD 6 を閉じる予定だった。**敵対レビューが、閉じられないことを典拠つきで示した**:

1. **改訂後の DoD 6 が要求するのは「通過の記録」**である。**#97 の判定記録は明示的に「通った」と判定していない**(`../product-rls-boundary-tests/gate-record.md` 8-2 節 — 意図的に繰り延べた)
2. **v0.6 は、判定に使う実測の適格条件**として、同じ対象への実行を**網羅して把握した記録の出典**・各実行の採番と開始/終了の時刻・比較の結果を要求する(`:2621`)。**#97 の記録には時刻と「重なりは無い」という記述はあるが、出典と網羅の根拠が無い**(実測: `gate-record.md` 内に「出典」「網羅」の語は 0 件)
3. **「根拠を書けない実測と、網羅して把握したと確かめられない実測は、判定の記録に使えない」**(同条)

**網羅の確認方法を定めるのは運用正本 2-1 の是正(別タスク)である。** したがって **DoD 6 は、そのタスクの後でなければ閉じられない。**

**本タスクは影響を受けない** — 12-4 ④ と 12-8 が述べているのは**「DDL が適用されたかどうか」という事実**であって、**ゲートの通過判定ではない**。事実の追随は通過判定を待たずに行える。

### ④ の結論が変わらないことの根拠

`:2655` は「④: 対象なし」と書いてよい条件を **(i) ④ が掛かるデータを返し得る DB 側の経路(越境関数・共有の状態に依存する読み取り)(ii) それへ到達する入口** のいずれも無いとき、と定めている。

**(i) は越境関数だけではない — 共有の状態に依存する読み取りも含む**(確定ゲート 1 周目 `P1`)。したがって**両方を調べた結果を根拠にする**:

| 条件 | 調べること | 典拠 |
| --- | --- | --- |
| (i) 越境関数 | 製品 DDL 資産に共有集計の越境関数が 0 件であること | `contracts/authz/product/` の資産(実装時に再実測する) |
| (i) 共有の状態に依存する読み取り | `shared_read` の表が 0 件であること・既存の共有状態を読む表が **④ の対象外の制御資源**であること | `../product-rls-boundary-tests/gate-record.md` 3 節の調査(実装時に再確認する) |
| (ii) 入口 | DB のデータへ到達する入口が 1 本も開かれていないこと | `backend/src/pitchlog/api/app.py` の `ROUTERS`(実装時に再実測する) |

**TSK-344 が変えたのは「適用済みか」だけで、(i) の 2 つと (ii) はいずれも変えていない**(DDL を適用しても越境関数は増えず、入口も開かない)。**よって結論は「対象なし」のまま**である。
