## 再計算と照合の順序

1. **受諾/同一性**: 独立担当自身が作成・修正への不関与、既存期待値の先読み状況を実際の事実で記録する。manifestと入力/原典hashを照合する。正確なモデル/セッションIDが取れない場合は未取得とし、架空IDで埋めない。provenanceのauthorIdが`codex`であることを踏まえ、別担当/別セッションの識別と独立性を受理者へ説明する。
2. **段階A**: manifestのA指定原典と判定値非添付入力だけを読む。元契約のdecision/normalized、展開器・検査器・既存試験・gate6突合表・既存独立報告から答えを転記しない。原典から行の条件を整理し、rawを宣言した規則で正規化（identityまたは結果表示名→語彙ID）し、R/L・具体段/回/score等を解決する。得点差/成立段数などは具体導出元と原典から確認する。一意に解けない入力は補完せずblockedとする。
3. **独立出力**: 各caseの正規化/派生軸と6出力について、原典の節/分岐・具体入力・計算/論理の過程・一意に導けるかを記録する。12拒否入力も原典から別に導出する。同一の具体入力の同値分割で手計算を共有する場合も全case IDとの対応を残す。製品計算核/別の参照実装を作らず、補助処理は抽出・集合・hash・比較に限る。
4. **段階Aを固定**: `phase-a-independent.json`とそのSHA-256を実際に保存し、保存時点を実記録する。未導出の値は空欄を合格として扱わず、blockedと理由を記す。
5. **段階B**: その後に初めて固定元契約のdecision/normalizedとcoverage宣言を開き、独立出力へ厳密型で比較する。case ID/row ID/拒否入力のsource位置の集合を照合し、期待値があったから合格へ書き換えない。差異、源の不足、追加で検証が必要な範囲を保持する。
6. **提出**: 下記へ独立性・対象hash・段階Aの固定hash・行/全case/拒否入力の結果と根拠を提出する。原典/入力が不足したまま全体確認の宣誓をしない。原資産や署名は独立担当も編集せず、修正案が必要なら差分提案として分離する。
