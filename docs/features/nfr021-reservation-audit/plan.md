# 実装計画書: NFR-021 予約レコード監査 PR(10.1 ブートストラップ ①)

## 1. 背景・目的

[ハーネス設計書](../../development/dev-harness-design-2026-08-07.md) 10.1「Phase 4 のブートストラップ」が定める**必須の監査 PR**。Phase 4-5(証跡の機械検証器)より前に `develop` へ入れる必要がある。目的は 2 つ:

### 順序逸脱(PO 判断: 規範改訂せず記録に留める)

## 4. 実装方針

**重さ分類 = 通常** の根拠: コア領域に触れない。`.claude/core-areas.json` の `guard_paths`(7 件)に `scripts/check_docs_status.py` は含まれず、`areas`(同期プロトコル / 状況計算 / 記録権 / テナント分離 / データ移行)のいずれにも該当しない。したがって人間の逐行確認は機構上は必須ではないが、**予約レコードは append-only で訂正不能**なため実値は人間が確認してから書く。

**除外述語の設計**(既存の接頭辞機構は流用しない):

- `is_excluded` はパス構成要素の前方一致しか表現できず、`INDEX_COVERAGE_EXCLUDED_PREFIXES` に当該ディレクトリを足す実装は README の「接頭辞単位にしてはならない」に正面から違反する(実測: 足せば exit 0 になるが、**正本 4 件も索引カバレッジから外れる**という禁止された副作用込みの exit 0)
- `EXCLUDED_PREFIXES` 側への追加は、同じ述語が `docs/features/*/plan.md` の検査にも使われるため二重に禁止
- **新設する述語**を `check_index_coverage` の走査ループからのみ呼ぶ:
  - **直下判定**: リポジトリルート相対のパス構成要素が `("docs", "ops", "nfr021-acceptance", <ファイル名>)` と**完全一致**する場合のみ対象(サブディレクトリ配下は構成要素数が増えるので自動的に非除外)
  - **予約の正規形**: `<YYYY-MM-DDTHHMMSSZ>-<gate>-seq<NNN>-reservation.md`
  - **結果証跡の正規形**: `<YYYY-MM-DDTHHMMSSZ>-<gate>-seq<NNN>-<short_sha>.md`(`<short_sha>` = 小文字 16 進 **12 桁固定**)
  - `<gate>` = `phase4-phase4` または `release-v<数値>.<数値>.<数値>`。**`phase4-v1.2.3` や `release-phase4` のような組は不正**(README の「`<gate_kind>` と第 2 要素の組」の規定)
  - **照合は `fullmatch`**(部分一致で通さない)
  - **時刻要素は桁並びだけでなく実在する UTC 時刻として検証する**(計画レビュー 1 周目 P1-1): README が「秒精度の UTC」と定めているため、`2026-99-99T246099Z-...` のような桁だけ揃った文字列を除外してはならない。日付部は暦日として、時刻部は 00:00:00〜23:59:59 として妥当であることを確認する
  - `seq<NNN>` の正規形判定は**専用ヘルパ**で行う(正規表現だけで書くと読めなくなる): 数値部が 3 桁以上・`str(int(n)).zfill(3)` と一致・`n >= 1`。→ `seq001`・**`seq1000`** は正、`seq1`・`seq0001`・`seq000` は不正。**`\d{3}` の固定長で書くと `seq1000` を誤って拒否する**ため、桁数を固定しない
  - 述語に当たらないものは現行どおり索引カバレッジの対象(= 索引未掲載なら違反)。正本 4 件は索引に登録済みなので通る
- `scripts/check_docs_status.py` の「当該ディレクトリが生まれた時点で除外規則を追加すること」という申し送りコメントを、実装済みの規範参照へ置き換える

**予約レコードの確定形**(README の対応契約に適合させる):

- ファイル名: `<YYYY-MM-DDTHHMMSSZ>-phase4-phase4-seq001-reservation.md`
- frontmatter: `gate_key: "phase4"` / `attempt_seq: 1`(**引用符なしの整数**)/ `attempt_id: "phase4-001-<YYYYMMDDTHHMMSSZ>"` / `started_at: "<YYYY-MM-DDTHHMMSSZ>"` / `operator: "山田正輝"`
- **`gate_kind` と `release_version` は持たせない**(`gate_key` が両者を保持する)
- **時刻書式が 2 系統**: ファイル名と `started_at` は `YYYY-MM-DDTHHMMSSZ`(日付部にハイフン)、`attempt_id` 内は `YYYYMMDDTHHMMSSZ`(ハイフンなし)
- **プレースホルダ(`<...>`)を 1 つも残さない** — 予約レコードに対する「完全性」の判定基準は正本に存在せず(結果証跡にしか定義がない)、4-5 がどちらの実装を選んでも影響を受けないようにするため
- `operator` / `attempt_id` / `started_at` の発行主体は**要件書 8 章の判定者(PO)**。設計書 10.1 が採番主体を判定者に固定しており、開発担当・Claude は操作補助と記録の起草のみ

| 種別 | 追加内容 | 置き場 |
