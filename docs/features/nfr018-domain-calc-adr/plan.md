### 調査で確認した機構の制約(実装時に効く)

- **変更履歴表は「frontmatter の直後、最初に現れる表」として読まれる**(`scripts/check_docs_status.py` の `change_history_table`)。ADR の既存メタ表(`項目 | 内容`)が先にあると**それを変更履歴表と誤読して落ちる** → **変更履歴表をメタ表より前に置く**
- **非免除文書は索引の版列に `—` を書けない**(`test_rejects_em_dash_index_version_for_non_exempt_document`)→ ADR-001・002 の版列を数値にする
- **`check_plan_docs_sync.py` はリンク先をリテラルパスとして解決する**(グロブを展開しない)→ 本計画書 3 節では**実在するファイルへの Markdown リンク**で宣言する(将来の ADR-003 をワイルドカードで書かない)
- **`/check` は docs-lint も lychee も実行しない** → リンク検査は CI と同じ lychee コマンドを明示的に走らせる
- 免除辞書の 3 件目 `requirements-draft-pitchlog.md` は**残す**(候補 (8) の対象・本 PR のスコープ外)
- **`docs/development/templates/` は `check_docs_status.py` の検査対象外**(`EXCLUDED_PREFIXES`)→ **テンプレート自体が壊れても機械検査で気づけない**。テンプレートから生成した文書が検査を通ることを**テストで固定する**
- **本 PR では CI の `frontend` ジョブは仕様どおり skipped になる** — 変更ファイル(`docs/` / `scripts/` / `tests/` / `templates/`)は `frontend-changes` の paths filter(`frontend/**`・`contracts/**`・`mise.toml`・`ci.yml`)のいずれにも該当しないため
