## 最優先のdata-model保存ゲート

審査対象は**`docs/design/data-model.md` §6-5の保存形・旧行拒否と、その版/変更履歴・`docs/README.md`索引追随のみ**。§3-2のowner/ロール数、§10-5のF-2配置・帰属、認可面本文、migration/ACL/凍結資産はこのゲートへ混ぜず、ステップ3前ゲートに残す。保存形は既存JSONB内で表現可能で、物理列を増やさない。現行v0.9からの規範追加のため、7.6では構造変更として7.3（正本全文の敵対レビュー→採否反映→人間承認→approved）を適用する。起案時の`in-review`状態と索引を同期し、正本全文SHAを参照する`schema-manifest.json`の更新・基線受理は確定本文の実SHAで行う。本文の候補は[保存ゲート本文](step2-storage-canonical-gate-proposal.md)。TSK-250所有worktreeは変更せず、所有者に本文・ゲート射程の採否を求める。所有者が正式本文を承認した後、TSK-550担当が所有側の承認済みコミットをこのfeatureへcherry-pickし、索引とmanifestの追随を含めて**TSK-550実装と同一PR**へ載せる。取り込み差分が承認本文から変わるなら所有側がその差分を再確認する。

所有者が応答・担当できない場合の**当該本文だけの代替経路案**: TSK-550の候補作成に関与していない独立レビュアが、現行data-model全文と§6-5差分・影響節、凍結schema、旧行、7.6/7.3規則を査読する。採否表と最終本文をPOに提示し、POが**この保存契約ゲートだけ**の代替受理の可否、正本編集担当、7.3人間承認と同一PRへの取り込みを明示判断する。無応答や独立査読だけでapprovedとしない。TSK-250の他の作業・ロール/認可/配置の受理に拡張しない。
