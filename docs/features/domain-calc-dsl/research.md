## 0. 結論(先出し)

### ◎ 0-1. 本タスクの射程は `ADR-003` の「着手順序 1」に限る

ADR-003 の着手順序(`:373-377`)は 4 段階で、段階 1 は逐語で:

> **ベクタの schema と独立に確認した期待値、および検査基盤(生成器・マニフェスト・収集器・CI 配線)を先に確定する**
> (**この段階では対象計算のコードを追加しない**)

段階 2(対象計算 1 件ごとに正本・生成物・呼び出し部・3 層検査を**同一の変更**として追加)には
**TSK-236〜239 の当該契約が必要**であり、本タスクでは着手できない。

→ **本タスクの完了状態は「検査基盤が『対象計算が 0 件・ベクタが未整備』であることを正しく不合格として報告する」状態**である。
要件書 `:900` が「**正解ベクタが未整備の間…不合格として扱う**」(fail-closed)と定めているため、これが正しい完成形。

**「CI が緑」を完了条件に置けない。** ADR `:387`(23 周目で表現を排除):

> **「緑になってからコードを追加する」とは書かない** — 検査は生成物・製品入口・変異対象が存在しないと緑にできず循環するため

### 1-2. ◎ (a) の単一性そのものは機械判定の対象ではない

要件書 `:898`(保証の範囲外・逐語):

> ③**正本と常に同一の値を返す再実装が存在する事実**(値が同一である限り本項の対象となる差は生じない。
> ただし**上位要件のコピー実装の禁止と(a)の単一性には違反する**ため、**(a)とレビューで抑止する**)

→ **「同一値を返す再実装の存在」は (b)② の保証範囲外**であり、抑止手段は**人手レビュー**。
**本タスクの DoD に「(a) を機械判定する」を置けない。**

### 1-3. ◎ (b)② の「経路一致」は要件書に直接の典拠がある

要件書 `:892`(逐語):

> **あわせて、同一入力に対する「実行入口を通した出力」と「正本の生成物を直接呼んだ出力」の一致そのものを合否条件とする**
> (**期待値と一致していても両者が食い違えば不合格**。製品経路が正本以外の実装を使っている事実を、値の面で直接検出するため)

→ **合否条件は 3 つ**: ①入口経由 = 期待値 / ②生成物直呼び = 期待値 / **③① = ②**。
③は独立の条件であり、期待値一致では代替できない。ADR は 9 周目でこれを **5 判定**へ拡張(§2-4)。

### 1-4. (b) の 3 層と fail-closed

**3 層**(`:894-897`)— 「**いずれか 1 層でも欠ければ本要件を満たさない**」:

| 層 | 要求 |
| --- | --- |
| 網羅的な正解ベクタ | 入力範囲を**全件**覆う(「代表例だけで済ませない」) |
| プロパティテスト | **不変条件**と**正本から生成した各実行体どうしの等価性**の**両方**。「区分ごとの対象は設計フェーズの ADR が定める」 |
| 変異テスト | 上位 2 層の**実効性そのものを測定**。**非等価変異の生存を認めない(生存 0)**。等価変異は**人手で判定**して分母から除外し、**除外の記録を残す** |

**fail-closed は 2 箇所にある**:

- `:886`(未分類の対象計算)— 「**当該計算の実装を開始せず、本書の改訂で区分を確定する**」「**自動的に(α)へ倒さない**」「**対象外として逃がすこともしない**」
- `:900`(判定)— 「**未分類・判定不能は合格としない**」「**正解ベクタが未整備の間、変異テストの生存率が閾値を超える間は、いずれも不合格**」

**用語の不統一(実害は小)**: 合否基準は `:897`・`:909` が「**非等価変異の生存 0**」と明記する一方、
`:900`・`:1027`・`:1046` は「生存率」「閾値」と書く。**基準値は 0 と読むのが唯一整合する。**

**退路**(`:901`): 「**①〜③のいずれかが実現不能と ADR が結論した場合は実装を開始せず、本書を `in-review` へ戻して再改訂する**」

### 1-5. (b)③ 構成の完全性 — 9 点(`:899`)

1. 本番到達可能な実行入口を宣言する
2. **宣言外の入口を拒否する**(検出ではなく拒否)
3. 探索対象に **Web Worker・Service Worker・別 HTML・静的配信配下**を含む
4. 本番のモジュール・生成物の集合が宣言と一致する
5. **サーバー側も同等に閉じる**
6. 動的コード生成の禁止と違反検出
7. 非リテラルな動的読み込みの禁止と違反検出
8. 外部スクリプト実行の禁止と違反検出
9. **検査手段を複数重ね、かつ実行時の制限も併用する**(静的検査のみは不適合)

### 1-6. 対象計算の列挙 — (α)5 件・(β)①〜⑧(`:883-885`)

**柱書の 5 名称(状況判定・座標変換・捕球選手推定・成績集計の前処理・終了判定)は分類名であり (α)5 件と一対一ではない。**

**(α)**(クライアント・サーバー双方で実行 — NFR-019(a) の対象):

1. 状況判定
2. **入力と表示のための座標変換** — 画面座標⇄保存座標の相互変換 + 内外角の導出(付録B-3)**に限る**。
   「高低等の別の導出を対象に加えるには**本書の改訂を要する**」。**打球方向の導出は含めない**((β)⑦)
3. 捕球選手推定
4. 終了判定
5. **断中にクライアントで実行する成績集計の前処理**(FR-020・FR-021・FR-022・FR-023)

**(β)**(サーバーのみ。判定規則 = 「**クライアントでの実行を要求する条項が存在しないもの**」):

## 2. ADR-003 の決定(decision-tracer)

**D-6(契約表)・D-8(比較面)・D-12(`contracts/` 構造)は TSK-233 の下調べで全行を写済み。**
本節はそれ以外の D-* と決定の空白。

### 2-1. D-1(正本の実装方式)の全項目

| 項目 | 決定 | 行 |
| --- | --- | --- |
| **正本** | **制約された型付きの宣言モデル**。人手で保守するのはこのモデルだけ | `:95` |
| **射程** | 状態 / イベント / ガード / 次状態 / **整数・boolean・enum** / 四則・比較・min・max / **明示的な丸め** / **有限の** reducer / 入出力の型・範囲・単位・scale / **nullable** / **enum → 表示名の写像テーブル**。**これ以外の計算を正本に書かない**(表せないものが出たら**見直しトリガー**) | `:96` |
| **生成物(target matrix)** | (α) = **Python + TypeScript** /(β)①〜⑤⑦ = **SQL 式 + Python の型付き受け口**(**TypeScript は作らない**)/(β)⑥⑧ = **Python のみ**。全生成先に共通で hash 埋め込み・再生成差分の検出・結果型の構築規則 | `:97` |

| **置き場** | 正本と生成器は **`backend/` 配下**。生成物は backend 側と **`frontend/src/lib/generated/`**。**`contracts/` には置かない** | `:100` |

**枝番 3 件**(a は無い):

| 枝番 | 内容 |
| --- | --- |

| **D-1-c** | **状態テーブルを両言語の手書き interpreter で読む方式は採らない**(interpreter 自体が 2 つの人手保守実装になり (a) を満たさない) |
| **D-1-d** | **(β)①〜⑤⑦ の集計は宣言モデルから DB 側集計の式(SQL 式)を生成する**(NFR-005 が全件読み込みを禁じる) |

### 2-2. ◎ 表示規則の限定と、旧の実体が収まらない可能性

D-1 `:96`(逐語):

> **自由な文字列処理は正本の射程に含めない**が、**宣言的な表示規則は含める**。
> **表示規則として許すのは 2 種だけ**: **①enum → 表示名の写像テーブル** /
> **②プレースホルダの差し込みだけを行う宣言的テンプレート**(例: `{捕球選手}{打球タイプ}`。
> **条件分岐・部分文字列操作・数値整形ロジックは書けない**)

さらに:
- **①の写像テーブルは「管理者管理でない安定した enum」に限る**
- **管理者が改名できる語彙(打撃結果・打球情報・シーズン)の表示名は写像テーブルに焼き込まない**
- 18 周目(`:28`): **データ参照による名称解決は対象計算の出力ではない(比較面にも入らない)**
- **対象計算は「①構造化値」と「②表示規則を適用した表示値」の両方を返す**
- **0 除算時は構造化値 `null` + 表示値「−」**(**表示規則で対応づける** — 比較器で吸収しない)
- 責任投手は**選手 ID(または `null`)を返し、氏名の解決は射程外**
- **写像テーブルとテンプレートも生成対象**であり、(b)① の乖離検出・直接呼び出し対象・変異テストの対象に含まれる

**◎ 旧の実体で 2 種に収まりにくいもの(§4-4 参照)**:

| 実体 | 難点 |
| --- | --- |
| `{捕球選手}ライナー併` | 同じ「打球タイプ = L」を、併殺打では `L`、ライナー併殺では `ライナー` と**別表記でレンダリング** |
| 打者状況の読み替え(長打時「走塁死」→「二塁アウト」) | **打撃結果を条件とする写像** — 単一キーの写像テーブルでは表現できない |
| 投球回 3 表現(`1.1` / `1.333` / `1⅓`) | 数値 → 記号の変換 |
| 構え(aim 9 分類 → ゾーン番号 `[7,6,1,2]`) | **1 対多写像** |
| **打率等の数値書式**(`.333`) | 「数値整形は書けない」と「完成した表示値を返す」の**帰属先が決まっていない** |

→ **D-1 の見直しトリガーに触れる可能性がある。計画で正面から扱う。**

**② 保証する対象**(`:185`):

**◎ この事故記述の典拠について**: `docs/legacy/` に「責任投手」の語は **0 件**(Claude が確認)。
典拠は `docs/features/nfr018-domain-calc-adr/research.md:101` と

**経路一致検査の変遷**:

| 版 | 内容 |
| --- | --- |
| 3 判定(8 周目) | 「①=期待値」「②=期待値」「**①=②**」 |
| **5 判定(9 周目・現行)** | 「**①実行済み・②実行済み・①=expected・②=expected・①=②**」。**いずれか不成立で fail**。**製品経路だけを実行した case で「実行済み」にできない** |
| **要求集合(10 周目・現行)** | **`(calculation, vector, case, runner, entrypointId, directTargetId)` の直積**。**要求集合と証跡集合の差が 1 件でもあれば fail**。**入口が 2 つあり片方だけ実行した場合も差分として検出** |

**`comparison` は lossless に限る**(`:231`): 禁止 = フィールドの除外・`NULL` と既定値の同値化・
値を丸めて差を吸収する変換。許すのは行の全順序による並べ替えと情報を落とさない型の統一だけ。
**比較器は値を丸めない**。**未知フィールド・欠落フィールドはいずれも fail**。

**◎ 独立収集器**(`:235`):

> **証跡はアダプタの自己申告ではなく、CI 側の独立した収集器が生成する** — 収集器はアダプタから
> **生の出力・実行した artifact の hash・(β) では実際に発行された SQL 文または AST** を受け取り、
> **等値判定は収集器が計算する**(アダプタが `true` を 5 個返すだけで通る経路を閉じる)。
> **受け取った hash が `generated[]` の現在の hash と一致しない場合も fail**

**実装・配置・入出力形式は未決**(「証跡ファイルの具体形式」として送り出し済み)。

**マニフェスト `backend/domain/manifest.json` の全フィールド**(`:231`):

`calculation` / `source` / `generated[]` / **`entrypoints[]`** / **`directTargets[]`** / `comparison` /
`normalization[]` / **`vectors[]`** / **`properties[]`** / **`mutation`** / `propertyCatalog`

**空を許さない**: `entrypoints[]` / `directTargets[]` / `vectors[]` / `properties[]` / `mutation`。
`properties[]` は**対象計算ごとに `invariant` と `equivalence` を各 1 件以上**。

**◎ 記述の非対称**: `propertyCatalog` は `:205` と変更履歴 `:20` にあるが、
**`:231` の「宣言の正」の列挙に現れない**。schema 設計時に取りこぼす危険。

**3 層の登録漏れ検出**(`:235`): マニフェストの `calculation` 集合と**各層が実際に実行した対象計算の集合**を
突合し、**差が 1 件でもあれば fail**。層ごとの実行集合の定義:

| 層 | 実行集合の定義 |
| --- | --- |
| 正解ベクタ | 消費されたベクタファイルが覆う対象計算 |
| **プロパティ** | **ランナーの機械可読な実行証跡**から集計した**実際に完走したテスト**。**skip・xfail・todo・0 ケース生成は「実行済み」に数えない**。`calculation` / `propertyId` / `propertyKind` / `generatedCases` / `status` の **5 項目を出力しないテストは実行済みに数えない**(pytest = JUnit XML の `properties` / Vitest = reporter の JSON) |
| 変異 | 変異が生成・実行された対象計算(**生成変異数 0 は fail**) |

**不変条件カタログ**(`:205`): 要件・付録由来の**独立述語**で、**生成器が読むことを禁止**。典拠必須・
`propertyCatalog` 登録・**allowlist とファイルアクセス証跡の突合** + 生成器依存グラフにカタログが
現れないことの静的検査。

対象計算ごとの不変条件: 状況判定/終了判定 = S≤2・B≤3・アウト≤2・同一塁の走者重複なし・
**通常の前進プレイに限った**得点の単調性(状態補正・undo は対象外)/ 座標変換 = 定義域内で全射・単調・
**クランプの冪等性** / 捕球選手推定 = 出力が閉じた集合に属し**タイブレーク規則適用後の帰属が一意** /
集計 = 分母 0 で構造化値 `null`・表示値「−」・**計数と率の非負性**(FIP・wRAA など負値を取り得る指標には課さない)・
部分和の総和一致 / 移行導出 = 出力が入力の値域に閉じ NULL 条件が排他。

**変異テストの運用規則 8 項目**(`:212-219`):

| 項目 | 決定 |
| --- | --- |

## 3. `D`(履歴文脈の検査上限)— 導出

### 3-1. ADR が課している制約

- 深さは **0 / 1 / 2 / `D`** の 4 点(D-6 `:255`)
- 構成は**スタック各要素の種別による等価分割 4 通り**(先頭が確定プレイ / 先頭が状態補正 /
  先頭と 2 件目で種別が異なる / 全要素が同種)
- シナリオ case の長さは **1 / 2 / `D` / `D`+1**
- **`D`+1 は「不正入力」ではなく「(b)② の保証範囲外」**。**製品は `D` を超える履歴でも拒否せず動作する**
- **`D` は検査が保証する範囲の上限であって実行時の上限ではない**
- **履歴文脈は全列挙の軸に入れない**
- **深さは固定値ではなく宣言モデルの schema が上限 `D` を定める**(`:29`)

### 3-2. ◎ 要件書側に典拠が無い

要件書 `:893` は「有限にならない対象(連続値の変換等)は**境界値・等価分割・範囲の端点を明示的に列挙した集合**とし、
**その集合を要件・付録から導出して固定する**」と要求する。
一方、要件書に履歴の深さの記述は無い(§1-8)。

### 3-3. ◎ 必須 case から下限を導く

`ADR-003` D-6 `:255` が必須と定める undo の case 3 本:

| # | シナリオ | イベント数 |
| --- | --- | --- |
| ① | 補正 → undo → 補正前 | 2 |
| ② | 補正 → プレイ → undo → 補正後 | 3 |
| **③** | **補正 → プレイ → undo → undo → 補正前** | **4** |

シナリオ長を `1 / 2 / D / D+1` で固定する規定と併せると、**必須シナリオを表現できる下限は `D` ≥ 4**。

**この下限は FR-006(`:236` の「1 つ前が次の対象になる」)と FR-040(`:337` の「補正が取り消され補正前に戻る」)
から導かれるため、要件書 `:893` の「要件・付録から導出して固定する」を満たす。**

### 3-4. 値の確定方法(提案)

`D` = **max(必須シナリオ長 = 4, 等価分割 4 通りを実現できる最小深さ)** とし、
**プロパティテストで「深さ `D` と `D`+1 で出力が変わらない」ことを示す**。
これにより `D` は恣意的な定数ではなく**測られた境界**になる。

### 5-4. 流用すべき既存の型

**検査スクリプトの共通型**(9 本でほぼ一致):

- 日本語 1 行 docstring → `from __future__ import annotations` → **stdlib のみ**(第三者依存ゼロ)
- モジュール定数で `DEFAULT_*: Path`、閉じた語彙は `frozenset` / `tuple`
- **専用例外 1 個**。`parse_args(argv=None)` + **必ず `--root`(default `Path.cwd()`)**
- `main(argv=None) -> int` + `if __name__ == "__main__": raise SystemExit(main())`
- **exit code 3 値**: `0` = 違反なし / `1` = 検査違反 / `2` = 入力不正・検査不能(fail-closed)
- 違反は **stderr** に `{識別子}: [{検査ID}] {理由}`。スキップ理由は **stdout**
- **選択実行引数は CI では渡さない**。`tests/test_ci_wiring.py` の
  `FORBIDDEN_SELECTORS = ("--defects", "--checks")` が `ci.yml` を機械検査する

**`check_authz_catalog.py`(3,958 行)から流用する型**:

| 型 | 実体 |
| --- | --- |
| **独立収集器** | `extract_source` — 「**内容による選択をせず、空行以外を全数採取する**」。**行番号を ID にしない** |

| **git blob digest** | `sha1(b"blob {len}\0" + data, usedforsecurity=False)` |
| **厳密キー集合** | `_expect_keys` — **未知キーも欠落キーも拒否**。「フィールドを足して情報を忍ばせる」が不可能 |
| **bool 罠** | `not isinstance(x, int) or isinstance(x, bool)` |
