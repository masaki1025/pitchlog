# 調査メモ: public 化後の正本追随(TSK-429)

## 問い

2026-09-19 の public 化と ruleset 適用に対して、①正本のどこが現実と食い違っているか ②リスク受容・承認済み例外をどう閉じるか ③ゲート区分は前段(PR レビュー)か後段(7.3 確定ゲート)か ④公開の根拠は記録されているか。

## 結論(要約)

1. **公開の根拠はリポジトリ内に存在しない。** 2026-08-14 の「旧リポ作者の許諾」は **private ミラーへの完全複製**に対するもので、公開は記録上の対象行為ではない。`LICENSE` も存在しない。**人間の判断が要る(本タスクの前提)**。
2. **影響する正本は既知 4 件では足りず、少なくとも 5 ファイル・18 箇所**。設計書 11 箇所・`onboarding.md`・台帳 H-8・`release/SKILL.md`・`docs/README.md` 4 行。
3. **gitleaks の登録先は `.gitleaks.toml` ではなく `.gitleaksignore`**(正本指定)。**両ファイルとも存在しない**。
4. **リスク受容(設計書 10.2「リスク受容記録(2026-08-10)」)の解除条件は 2 つとも充足**。ただし **NFR-019 条文全体は未達のまま**で、混同すると要件適合を偽ることになる。
5. **ゲート区分は一律に決まらない。** 部分ごとに前段・後段が分かれ、1 箇所は先例が無い。

## 参照の規約

**設計書への参照は節番号と逐語で行い、行番号を使わない。** 2026-09-19 の PR #71 マージで **1033 → 1171 行**になり、初回調査時の行番号が全て無効化したため(実測)。

**留意点 2 つ**:
- **`required_approving_review_count: 0`** — レビュー承認は要求していない。NFR-019 が求めるのは「全グリーンでないとマージ不可」なので解除条件は満たすが、**「PR 必須」と「人間レビュー必須」は別物**。閉じた範囲を書き分けないと誤読させる。
- **リポジトリ設定は squash/rebase も true** で、merge commit 限定は ruleset 側(main/develop のみ)。`github-setup.md` の適用前提に `allow_merge_commit` 確認の記述があるため、どちらが正かを 3 章に書く必要がある。
