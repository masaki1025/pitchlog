## 3. あなたが決めること

**機械が判定できない性質のものだけを挙げる。**

### 3-1. 射程縮小 2 件を条文として受け入れるか

**どちらも既に PO 裁定済みだが、条文の形で確定させてよいかの最終確認である。**

| | 縮小した範囲 | 段階 2 へ送った理由 |
| --- | --- | --- |
| **1 回目** | payload 内部のフィールド制約(一意性・参照整合・相反排除)/ 状態遷移軸の軸間組合せ規則 / ADR D-8 の文字列規定と FR-015 の任意選手名の整合 | 敵対レビュー 2 周目の 5 件中 4 件が初周で追加した payload 内部構造に起因し、**ADR-003 の既存委任条項が警告する「机上で閉じる是正が次の穴を生む閉じた輪」に入った** |
| **2 回目** | `XC-13` の 23 キーごとの導出表 / 第3アウト種別の観測入力(打者走者の一塁到達前・フォースアウト・**先行走者のアピールアウト**)/ 記録員判断の入力契約 | **アピールアウトが既存の `resultId`・`outEffect` だけでは一意に導出できない**と判明。P0 が 4→3→1→4→2 と下がり切らず、是正起因の穴が繰り返された |

**確定を維持したもの**: `statFlags` の **23 件の閉じた外延** / **exact 型** /
**`XC-13` の原則**(**`statFlags` は行の他の列と `precondition` が参照する入力から導出し、
独立した手入力または規範上の任意値としてはならない**)/ **`XC-01`〜`XC-12`**。

**判断の要点**: **原則は残るので「守らなくてよい」ことにはならない。**
**導出の具体をどこで閉じるかが段階 2 へ移るだけである。**
**段階 2 で実機とともに確定するまで、本制約を機械保証済みと判定してはならない**旨も
条文に入っている。

### 3-2. NFR-018(b)② の保証範囲の書きぶりが実態より広くないか

**本ゲートで確定するのは「②の保証する入力の範囲」である。**

**v2.2 で既に「再実装が存在しないことの証明」(決定不能)から
「差分が必ず検出されること」へ目的を変更済み。**
**本改訂はその入力範囲を descriptor の 26 軸へ結びつけた。**

**判断の要点**: **保証していないものを保証しているように読めないか。**

### 3-3. 凍結機構の保証境界を受け入れるか(PO 裁定 5 回目の条文化)

**反映 10 周目で、凍結機構が保証する範囲そのものを変更した。**

| 区分 | 内容 |
| --- | --- |
| **機械が保証する** | 宣言された基準(`scope` / `criteria`)の同一性。**受理記録なしの変更は必ず赤** |
| **機械が保証しない** | **実装が宣言外の基準を新たに持ち込んでいないこと**。理由: **任意コードの意味解析に帰着する** |
| **規範上の地位** | **禁止のまま**(設計書 7.7-1 違反)。統制は **PR レビュー** |

**これは本プロジェクトで 3 度目の同じ処方である**:

1. **設計書 7.7-4 自身**(PO 裁定 2026-09-17)— 述語・類型の列挙・事実の軸の 3 方式が
   いずれも「網羅できていない」型の指摘を出し続けたため、**塞がないと明記して打ち切り**
2. **NFR-018(b)②**(人間裁定 2026-08-18)— **決定不能と結論して目的を変更**
3. **本件**(PO 裁定 2026-09-27)

**判断の要点**: **「機械で見ないから規範上も許される」と読める書き方になっていないか。**
**作成者の確認では、非保証範囲に `prohibited-by-dev-harness-7.7-1` と明記してある。**

## 5. 承認後にもう 1 つ確認が要ること

**authz の再シール。**

**ゲート中に要件書を何度も変更したため、blob digest の凍結が発火したまま**である
(台帳 `H-85`)。**`pytest` の既知 red 3 件がこれにあたる。**

```
test_repository_catalog_covers_the_entire_requirements_file
test_normal_validation_never_reseals_a_semantically_valid_drift
test_repository_shared_preconditions_are_valid
```

**`reseal_policy.human_review_required` が `true`** のため、
**再シールにはあなたの確認が要る。**
**受理記録は PR #81 のぶんが既にあるため、digest の取り直しのみである。**
