## 2. 述語の単一定義(**定義はここだけに置く。他の節は参照する**)

**同じ述語を各節で言い直すと伝播漏れが起きる。** 前タスク(製品データモデル設計)では、述語を集約する節を新設してもなお**残存を検出する機械検査が別に必要**だった(台帳 **H-78**・`docs/development/harness-evaluation.md:548`)。さらに、是正時に**正規語の文字列だけで走査して別名を取りこぼす**事故が繰り返し観測されている(台帳 **H-79**・同 `:555`・`:563`)。

したがって本節は **① 唯一の定義 ② 禁じる別名(残存検査の入力)③ 適用先** の 3 点を持つ。**以降の節は本節を参照し、定義を書き直さない**。

### 2-1. 定義

| # | 述語 | 定義 | 典拠 |
| --- | --- | --- | --- |
| D1 | **同期連番** | **クライアントが操作を受理し、端末内の永続キューへ不可分に追記した順**に、**記録権世代の中で単調増加**に採番される整数。**サーバーが受信した順とは無関係**。用途は**欠番検知・再送の重複排除・undo の逆順**に限る | REQ:284(FR-012「クライアント生成のべき等キーと**記録権世代内で単調増加の連番**」)/ REQ:288(同「**追記と連番の採番は不可分に永続化**」)/ REQ:301(FR-013「**連番(FR-012)は記録権世代ごとに採番され、試合の正史は「世代の連結」として定義される**」) |
| D2 | **論理順序** | **プレイの投影・出場区間の境界・下流再計算の起点**に用いる順序。**同期連番とは別の値**として持つ。**後から生成したイベントが過去の位置へ入る**ことがある(任意位置挿入) | REQ:238(FR-007「**任意位置への挿入**」)/ 候補案 `docs/features/product-data-model-design/design.md:411`(「**境界と再計算の起点は「論理順序」側**を使う。**同期連番は同期と undo に限る**」) |
| D3 | **prefix 水位**(適用水位) | サーバーがある**記録権世代**について「**この同期連番までは欠番なく確定した**」と判定した上限値。**確定イベントまたは墓標を越えて前進する**。欠番があればそれ以降は適用しない | REQ:286(FR-012「**連番に欠落があればそれ以降を適用しない**」)/ REQ:290(同「**prefix は確定イベントまたは墓標を越えて前進する**」) |
| D4 | **記録権世代** | 記録権に付与される世代番号。**引き継ぎのたびに更新**され、**同期連番のスコープ**になる。試合の正史は**世代の連結**として定義される | REQ:301(FR-013「記録権には世代番号を持たせ、**引き継ぎのたびに更新する**」) |
| D5 | **べき等キー** | **クライアントが生成する**、操作イベントごとに一意な識別子。**再送が重複到達しても二重適用させない**ために用いる。**改訂版は新しいべき等キーを持つ** | REQ:284(FR-012「**クライアント生成のべき等キー**」)/ REQ:286(同「**べき等キーにより再送が重複到達しても二重適用されず**」)/ REQ:290(同「**新しいべき等キーで送信し**」) |
| D6 | **墓標** | 拒否されたイベントの**同期連番を正式に消費する空イベント**。内容を持たず、**prefix 水位を前進させる**ためだけに存在する | REQ:290(FR-012「**墓標イベント**(当該連番を正式に消費する空イベント)」) |
| D7 | **改訂** | 拒否されたイベントを**同一の同期連番のまま**、**新しいべき等キー**で作り直したイベント。**サーバーは旧版を置換する**。**新しい連番では表さない** | REQ:290(FR-012「**同一連番の改訂版**として新しいべき等キーで送信し、サーバーは旧版を置換する」) |

### 2-2. 「同期連番」が誤読されやすい点(**本タスクの中核**)

受け取り元の申し送りは「**同期連番が「到着順」であることを明記**し、論理順序を別に持つ前提を共有する」と書かれている(候補案 `docs/features/product-data-model-design/design.md:1774-1775`)。**この「到着順」を「サーバーが受信した順」と読んではならない。**

- 要件書は**イベント生成時にクライアントが採番**することを定めている(REQ:284)。採番は**キュー追記と不可分**である(REQ:288)
- **サーバー受信順は入れ替わり得る**(再送・並行送信・部分到達)。それを連番の意味に採ると、**prefix コミット**(REQ:286 = 欠落があればそれ以降を適用しない)が成立しない — 受信順で採番するなら定義上欠落が生じないため、欠番検知そのものが意味を失う
- したがって **D1 の「到着」はクライアント内のキューへの到着**を指す。**サーバー到着順という概念は本設計に存在しない**

### 2-3. 禁じる別名

**各述語について、本書で使ってはならない語**を列挙する。**「正規語だけを検索して別名を取りこぼす」型の事故**(H-79)を防ぐため、**検査の入力を人手の記憶ではなく表にする**。

**検査の除外区間**: **2-2 節と 2-3 節は検査対象から外す** — この 2 節は**その語を禁じる理由を述べるために当該語を使う**ため、検査すると必ず引っかかる。**除外を隠れた例外にしないよう、ここに明記する**(検査スクリプトはこの見出しを見て除外区間を決める)。**2-1 と 2-4、および 3 節以降は検査対象**。

**表を 2 つに分ける。** 初版では 1 つの表に混ぜていたが、**残存検査を実際に回したところ「再送」「応答」「空イベント」で誤検出が出た** — これらは**それ自体が正しい概念**であり、無条件に禁止できない。**機械検査にかけられるのは無条件の禁止語だけ**であり、文脈依存の語は**人間の逐行確認の対象**である(計画書 6 節が「意味の支持は人間レビューへ分離する」と定めている)。

#### (a) 無条件の禁止語(**機械検査の入力**)

| 述語 | 使わない語 | 理由 |
| --- | --- | --- |
| **D1 同期連番** | サーバー到着順 / サーバー受信順 / 受信順 / 通し番号 / シーケンス番号 | 2-2 の誤読そのもの。**サーバー到着順という概念は本設計に存在しない** |
| **D2 論理順序** | 操作順 / 記録順 / 表示順 | 「操作順」は候補案が **D1 側**の呼び名として使っており(`docs/features/product-data-model-design/design.md:1767`)、**逆の意味に取られる** |
| **D3 prefix 水位** | 適用済み位置 / 同期位置 / オフセット / カーソル | 位置と水位は別概念(水位は「欠番なく確定した上限」であって単なる位置ではない) |
| **D4 記録権世代** | ロック世代 / エポック / リース | 記録権は排他ロックではなく**世代の連結で正史を定義する**機構(REQ:301) |
| **D5 べき等キー** | リクエスト ID / 冪等トークン / 重複判定キー | 「重複判定キー」は旧システムの `プレイの番号` の役割名(`docs/legacy/research/data-layer.md:161`) |
| **D6 墓標** | tombstone(和文中で)/ 欠番埋め / 削除マーカー | 「削除マーカー」は**論理削除**(4.0-2)と混同される |
| **D7 改訂** | リビジョン / 改版 | 要件書の語は「**改訂版**」(REQ:290) |
| **D8 退避** | 待避 / 保留 / デッドレター / アーカイブ | 「待避」は誤字。他は保持期間・復帰経路の含意が異なる |
| **D9 ACK** | 受信確認 / 成功レスポンス / 同期完了通知 | 「同期完了通知」は**利用者へ示す通知**(REQ:285)であって ACK ではない |

#### (b) 条件付きの語(**人間の逐行確認の対象。機械検査にはかけない**)

いずれも**その語自体は正しい**が、**当該述語の意味で使ってはならない**。

| 語 | 正しい用法 | 当該述語の意味で使わない |
| --- | --- | --- |
| **到着順** | 「**クライアントのキューへの**到着順」と限定するときのみ | **単独では使わない**(D1 — 2-2 の誤読を招く) |
| **再送** | **同一イベントを送り直すこと**(REQ:286) | **D7 改訂**の意味で使わない(改訂は内容を作り直した別のイベント) |
| **応答** | HTTP 応答一般 | **D9 ACK** の意味で使わない |
| **空イベント** | **D6 の定義文**(REQ:290 の逐語)でのみ | 定義以外の節で D6 の代わりに使わない |
| **修正 / 訂正** | **FR-007 の利用者操作**(REQ:238-244) | **D7 改訂**の意味で使わない |
| **上書き / スキップ** | 旧システムの挙動の記述(`docs/legacy/research/services-shell.md:150`) | D7・D6 の意味で使わない |
| **UUID** | **一時 ID**(FR-015 の断中登録 — REQ:343) | **D5 べき等キー**の意味で使わない |
| **プレイ番号 / プレイの番号** | **旧システムの 88 列の列名**(`docs/legacy/research/data-layer.md:161`) | D1・D2 の意味で使わない |
| **トークン** | **認証トークン**(NFR-011・REQ:293) | **D4 記録権世代**の意味で使わない |
| **隔離** | **移行の隔離領域**(FR-038) | **D8 退避**の意味で使わない |
| **チェックポイント** | **再計算の粒度**((B) 論点 21) | **D3 prefix 水位**の意味で使わない |

**正本の語との対応(禁じるのではなく、同一物であることを明示する)**:

| 本書の語 | 正本での表記 | 扱い |
