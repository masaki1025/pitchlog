### 成果物の位置づけと後続の依存順

**本タスクの成果物は「候補案」であり「決定」ではない。** 設計書 7.6-4 が `docs/features/<slug>/` を「活動中のみ意味を持つ一時ディレクトリ」と定めているため、[design.md](design.md) には**推奨と根拠・却下案・トレードオフ**を書き、**候補案自身を approved / 最終決定として表現しない**(ドメイン用語の「確定イベント」「確定記録」は要件書の必須語彙なので使う)。

**依存順(本計画で明示する — レビュー 1 周目 P0)**:

```
TSK-259(本タスク・候補案)
  → 同期プロトコル設計の正本化(docs/design/ へ新設・7.3 確定ゲート・approved)

```

**TSK-250 は本タスクの完了だけでは解除しない。** `docs/features/` は正本ではないため、TSK-250 は候補案を正として参照できない。**候補案だけで TSK-250 を動かすと、同期正本化とデータモデル正本化が同じ順序規則・フィールドを二重に決めるか、どちらも決めない空白が生じる**。短縮したい場合の代替は「**同期正本とデータモデル正本を同一の確定ゲートで扱い、規則ごとに正本を一意に割り当てる**」で、これは**人間の判断事項**として申し送る(5 節)。

## 2. スコープ

### やること

成果物は `docs/features/sync-protocol-design/design.md`(**候補案**・`type: design`)。次を含める:

1. **述語の単一定義節** — 同期連番 / 論理順序 / prefix 水位(適用水位)/ 記録権世代 / べき等キー / 墓標 / 改訂 / 退避 / ACK の 9 語を **1 節で唯一定義**し、**適用先の節を表で明示**する。各語に**禁じる別名**を列挙する(H-79 の 5 件目の対応案)
2. **論点の (A)/(B) 分類**(4 節が正 — [design.md](design.md) は論点 ID を参照するだけで表を複製しない)と **(A) 16 件に対する候補案**
3. **イベント契約の骨格** — 同期の意味上**必須な値と不変条件**(識別子 5 種の分離・サイドカー結合キーの成立)。**列名・型・NULL 性・FK・索引・表分割は TSK-250 の責務**として切る
4. **順序の 2 系統と射程** — 同期連番(クライアントのキュー追記順)と論理順序(プレイ投影・出場区間の境界・再計算の起点)の分離 / **順序ラベル方式の選定** / **挿入時の再採番の可否** / **イベント種別ごとの参加区分表**(同期順のみ / 論理位置を持つ / 他イベントへ従属)と**同位置を作らない規則**
5. **prefix コミットと適用水位の規則** — 欠番時の停止・墓標/改訂による前進・水位の意味の正
6. **拒否と再開の決定表** — 内容起因(改訂 / 墓標)と記録権起因(退避へ誘導)を分けた分岐表
7. **サーバー応答・ACK の意味とキューの状態遷移** — ACK が何を保証するか / 部分成功 / gap 検出時の応答 / ACK 消失後の再送 / 「未送信 → 同期済み(24 時間保持)」へ移す条件
8. **クライアント側のキュー規律** — 追記と採番の不可分性・複数タブの単一書き手(**満たすべき条件**)・警告閾値でブロックしない・トークン失効時の保持
9. **undo の同期上の表現** — 常時送信・べき等・相殺・undo 自身は取消不可
