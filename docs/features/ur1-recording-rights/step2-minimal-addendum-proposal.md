# U-R1 新ステップ2の最小計画追補案（承認前）

2026-10-15。承認済み計画の[実装ステップ表](plan.md)2行だけの合格条件を明確にする候補。A/B/Cの順序追補はTSK-550の`8a270c2a`でPO承認済み。本文はRG1個別資産・製品コード・凍結契約の承認を兼ねない。

## 変更する条件

| 現行の表現 | 最小追補候補 |
| --- | --- |
| 「復元開始側の同一状態行`UPDATE`」 | 新2では**隔離DBの競合試験用**に特権接続から同じRG1行を`UPDATE`する。製品の復元開始関数・公開入口は新5に残す |
| 「安全な解除経路が未着地なら製品では書込を開かず、試験の隔離状態で正常系を検証」 | 新2の製品読取2関数は起動・再接続後、行が古い`open`でも常に閉を返す候補。**製品operationの正常open成功を新2の合格条件にしない**。隔離DBの特権fixtureで`open`行を作り、同じ行への直接`FOR SHARE`取得と復元側`UPDATE`の直列化を検証する。安全な解除に伴う製品open成功は新5へ移す |

この追補は新2のRG1判定2登録、非ロック事前読取、同一scopeのコミット直前`FOR SHARE`、起動時fail-closed、欠損/読取失敗、競合・全取消の責務を維持する。fixtureを製品関数・registry・公開経路から参照せず、試験用openを運用解除へ読み替えない。U-G1/U-S1実入口との結合試験は新6、D4方式は新3/5の別ゲートに維持する。現行表の変更はコア計画レビューと人間承認後に限る。

## 検査準備（製品・凍結資産は変更しない）

| 系列 | 準備する証拠 | 新2の期待 |
| --- | --- | --- |
| 製品関数の常閉 | 閉・古いopen・欠損・不正行・再接続で、2関数の直接`EXECUTE`と固定token経由を分ける | 成功値を返さず、B7/P3 B10相当で全取消。試験用分岐なし |
| 隔離DBの開状態fixture | 専用DBの特権接続で1行をopenにし、**製品関数を通さず**同じ行の直接`FOR SHARE`を試す | ロック取得、`FOR KEY SHARE`負例、復元`UPDATE`先行/共有ロック先行の直列化と取消を確認。製品正常系の代替証拠とはしない |
| 待機競合 | `FOR SHARE NOWAIT`候補が拒否する競合と、共有ロック先行時の復元側待機を二接続以上で再現する | 新2通常側の即時拒否・全取消を確認。復元側の具体的`lock_timeout`/再試行上限は新5の別判断。無制限待機を安全と宣言しない |
| 認可境界 | app直表操作、関数直呼出し、PUBLIC/余剰policy、role属性を実カタログで照合する | 専用owner・FORCE RLS・2関数限定EXECUTEの承認済み差分だけを許す |

## 新2の個別承認一覧

具体的なSQL・権限・影響は[RG1個別承認資料](rg1-individual-approval-packet.md)2〜4節を正とする。以下は判断単位であり、A/B/Cの方式承認を流用しない。

| 項目 | 推奨案 | 必要な承認・未確定の確認 |
| --- | --- | --- |
| owner | RG1の2読取関数だけを所有する専用`NOLOGIN/NOBYPASSRLS` role | データモデルのrole数・目的の7.6/必要な7.3、認可担当の採否、POの個別資産承認 |
| RLS | 単一行`FORCE RLS`、専用ownerのSELECT/UPDATE policyと最小列ACL。INSERT/DELETE policy、app表ACLなし | 非テナント`function_only`分類、policy合成と列ACLを実DBで確認後、正本/認可/凍結の個別承認 |
| EXECUTE | appには固定読取2関数だけ、PUBLICを同一transactionで剥奪。復元開始関数は新2で作らない | 関数identity、app直接EXECUTE、schema/関数ACLのexact-setを審査し個別承認 |
| 待機上限 | 通常側の直前照合は`FOR SHARE NOWAIT`候補、競合時は全取消。復元側上限は新5で数値を決める | NOWAIT採否と失敗結果のPO/担当確認。復元側を無期限待機で公開しないことを新5開始条件へ固定 |
| 隔離正常系 | 開状態fixtureでは行ロック機構だけを試験し、常閉製品関数は閉鎖・拒否を試験する | 本追補の6.1/6.3コア計画差分レビューと人間承認。製品open成功は新5へ移す |
