## 6-1へ反映する限定本文候補（未確定）

- 初期の通常記録権世代は、`preparing`試合作成でも復元調整解除でも作らず、U-G1の試合開始・スタメン確定と同じ業務DB transactionで1件だけ作る。世代行・V12配達行・開始状態の片方だけの確定を許さず、RG1閉鎖/不明またはコミット直前閉鎖で全取消する。D3/適用prefixの初期値と現世代の一意性は5-3の既存定義を参照し、ここで複製しない。
- D4は業務DBのバックアップ復元で巻き戻らない外部の耐久予約源から受け、取消後も番号を戻さない。台帳の耐久確定・旧primaryのフェンスを証明できなければ新規発行を停止する。復元完了時は既存D4を持つ試合だけを新D4の対象とし、対象0件なら発行0件で全域RG1を解除できる。復元された`preparing`の初期権は通常の開始時にだけ発行し、過去のD4を再利用しない。
- 同一開始要求・同一認証済み端末へのV12再交付に必要なdigest/暗号文/復旧世代は、既存世代表のapp表単位権限を広げない別の`function_only`配達表へ結合する。V12平文と暗号鍵を業務DB/ログに置かず、現権利・現復旧世代・有効端末資格・開始要求の一致を再照合する。復旧世代の外部現値が不明/不一致なら既存世代を含む書込みを停止する。

これは意味と永続化境界の候補であり、具体的な関数identity・鍵の保管先・端末資格の所有・外部台帳の実配置は7.3本文の確定対象にしない。DDL/owner/RLS/EXECUTEの最小tupleは[3群判断資料](step5-three-part-approval.md)で審査し、正式資産と7.7は別受理とする。

## 本改訂で確定したい範囲

1. 初期通常世代は試合**開始**時に U-G1 の開始 transaction と同じ業務DB transactionで作る。準備中の試合作成では発行しない。世代/配達の片方だけを確定しない。U-S1 R-17と統合済みsync-protocol v0.9は作成と開始を2行へ分け、作成は試合行だけ・開始は初期世代/証明を含めてRG1停止時に全取消とする。data-model側の物理写像は本候補の7.3審査対象として残す。
2. D4 は業務DBの復元範囲外に置く同期保全の発行源で予約し、成功の耐久証明が取れないと発行停止する。予約IDはテナント・試合・開始要求へ束縛し、再照会は同じID/owner tupleに限定する。claimは一度だけ成功し、取消や復元後も番号を再利用しない。D4の値順は発行順を意味しない。
3. 復旧世代の現値は同じ復元外発行源で管理し、業務DB内のRG1状態に記録した世代と毎書込で照合する。不明/不一致では、既存記録権による書込も止める。**外部epoch行の共有fenceを先に取得し、そのロック下で現値を読み照合したうえで**業務DBのcommit/rollback結果が確定するまで保持する。fence前の読取は最終判定に使わない。復元開始の最初のtransactionはRG1状態行だけを閉じて確定し、外部epochの更新はその後に行う。
4. V12の再交付値・digest・復旧世代は、既存世代表へ秘密列を足さず、世代へテナント付き複合参照を持つ別の `function_only` 表に置く。平文V12を業務DB・ログに保存しない。現権利・同一開始要求・同一の認証済み有効端末・同一復旧世代の照合が成功した時だけ暗号文から同じ値を再交付する。失効、鍵不明、端末不一致で再交付しない。
5. 端末IDの自己申告は権利の証拠にしない。認証に束縛された端末資格を内部operationでも再照合し、資格行の共有ロックを業務DB commitまで保持して失効と直列化する。新表はFORCE RLSと専用関数経路に限定し、既存世代表のapp権限を広げない。
