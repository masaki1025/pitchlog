# U-R1 RG1 先行分割の最小追補案（2026-10-14 承認済み）

2026-10-14。旧 [8 ステップ計画](plan.md)の**ステップ 1/2/4 の境界だけ**を調整した提案。同日、依頼者が分割案を承認し、計画を 9 ステップへ更新した。U-G1 の作成側 RG1 接続①〜⑤は `79e3da4a` で受理済み。外部 D4 台帳は未承認、U-S1 の ③-a/⑧ と復元開始直列化の担当受理は未了。**分割承認は RG1 状態資源・起動時 fail-closed の個別資産承認ではない**。

## 分割の判定

RG1 の「状態が open かを同一 transaction で事前/コミット直前に検査し、復元開始の更新と同じ状態行で直列化する」機構は D4 値を発行しないため、**D4 裁定前に独立実装・DB 試験が可能**。分割前の計画ステップ 1 は D4/V12/復旧世代の出所確定を合格条件とし、旧 2 は RG1 と D4 初期付与を**単一コミット**へ束ねていた。そこで人間承認を受け、下表の分割を現行計画へ反映した。

**独立性の条件**: RG1 状態が業務 DB の過去 snapshot へ戻るだけでは、復元後に古い `open` を信用してしまう。新ステップ 2 は、サービス起動/再接続時を既定閉鎖にし、復元制御面が安全を確認するまで通常書き込みを開かない仕組みを含める必要がある。その永続/プロセス間の制御資源・権限・テナント境界は D4 台帳とは**別の具体案と人間承認**が必要。状態資源と安全な起動ゲートの個別承認がない間は新 2 を開始しない。U-S1 の共有直列化点の受理は新 2 前、同期 port の詳細/実経路試験は後続接合ゲートに残す。

**採用後の開始条件**: 計画番号は 9 へ更新済み。新ステップ 2 の前に U-S1 直列化点の担当受理と、RG1 状態資源・起動時 fail-closed の具体的な別承認が必要。個別の schema/認可/凍結資産変更、製品コード、migration は未着手。分割しても U-R1 全体の D4 非再利用保証は一切弱めない。
