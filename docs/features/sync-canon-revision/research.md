# 調査メモ: 同期プロトコル正本の不整合の改訂ゲート(射程の確定)

## 問い

Notion カード **TSK-322**「同期プロトコル正本の不整合 3 件の改訂ゲート」に対し、
① **TSK-267(v0.2)へ合流させるべきか** ② **射程は本当に 3 件か** ③ **改訂のコストはいくらか** を確かめる。

## 結論(要約)

1. **合流させない**(§1)。TSK-267 は**新規規則の設計 + 要件書 v2.5 の版繰り上げ**、本タスクは**既存記述の是正**。
   TSK-267 の ④ は先行タスクの確定ゲート **4 周で収束せず切られている**(累計 P0 8・P1 5)。
2. **射程は 3 件ではない。** 11-3 の食い違いだけで **38 ID / 120 ペア**あり、これは**正本自身が `U-9` として
   既に記録し、受け取り先を「後続の同期プロトコル設計改訂」= 本タスクと名指していた**もの(§3)。
3. **この向きを守る検査 `attribution-destination` が、成り立たない理由で無効化されている**(§3-3)。
   **これが食い違いの累積を許した機構的原因**である。
4. **「正本を 1 文字変えると連鎖する」は誤り**(§6)。実測では最頻ケースの追随は **0〜1 ファイル**。
   カードと `sync-event-contract/research.md:185` の記述は **H-85 の誤った言い換え**であり、訂正を要する。
5. **より重大なのは逆向きの穴** — **正本に新しい規則行を足しても機械が一切鳴らない**(§6-3)。

## 2. ゲートの決定表に本件の類型が無い

### 3-3. 機構的原因 — 検査が成り立たない理由で無効化されている

`scripts/design_relations/profiles/sync-protocol.json` の `not_applicable` に **8 検査**。うち
`attribution-destination` と `attribution-direct` の理由は:

> 二文書目(データモデル正本)向けの検査。**同期正本には対応する資産が無く**、既存の振る舞いを変えないため無効化(TSK-269 design 5-1)

**この理由は成り立たない(自分で検証)**:

- プロファイルは `attribution` を**完全に構成している** — `section_re: "^11-3\\."` / `ledger_section: "11-5"` /
  `destination_grammar: "sync-v1"` / kinds 3 種 / `assignment_header` / `ledger_header`
- **`attribution` は `required_checks` に入っている**
- `check_doc_coverage.py:630-669` の `attribution-destination` は**帰属表と文書本文だけ**で動く
  (`_section_text(text, pattern)` で本文から節を切り出し安定 ID を探す)。**外部資産を参照しない**
- 同じ定型理由が **7 検査に一括で貼られて**おり、この 2 検査には当てはまらない

→ **`attribution-destination` の無効化は誤り。これが累積を許した機構の穴。**

**ただし `attribution-direct` の無効化理由は正しい**(自分で検証): `check_doc_coverage.py:1129-1170` は
`direct_requirements` 資産と `collection_sets` の `direct-requirements-vs-claims` を**必須**とし、
無ければ `ProfileError` を投げる。同期プロファイルは `assets: {}` / `collection_sets: []` で**どちらも持たない**。
→ **有効化の対象は `attribution-destination` の 1 つだけ**。
