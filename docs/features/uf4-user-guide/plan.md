## 2. スコープ

### やること

1. **`dd03160:frontend/src/screens/HelpScreen.tsx`(124 行)を `frontend/src/screens/HelpScreen.vue` へ逐語移植する** — 見た目・文言・構造を同じにする(許容差分は「Vue と React の差で不可避な違い」のみ — PO 裁定 2026-08-16)。**ただし前提 C の例外一覧に当たる文言を除く**

3. **要件の Won't・破棄裁定と衝突する文言を、例外一覧として切り出す**(前提 C — 下記)
4. **Vitest の試験を置く** — 描画・emit と、**ガイド文言を実挙動に固定する試験**(旧 `dd03160:tests/test_frontend_help_foundation.py` が先例)

#### 前提 C: 逐語移植の例外は「I-28 の 2 つの限定に当たる文言」全体とする

**旧 HelpScreen の文言には、現行要件が提供しないと決めた機能の案内が複数ある。** 逐語移植をそのまま適用すると、**利用者に存在しない機能を案内する画面**ができる。

改善台帳 I-28 は「完全に同じもの」裁定を **2 つの限定つき**で再確認している:

> 「完全に同じもの」裁定は「**要件書・改善台帳が改善を既決にした箇所、および実体のない機能を除く**」という限定つきで再確認された(2026-09-02・山田正輝)
> — `docs/improvements-from-baseball-scoring.md:240`

**当初本書は限定②(実体のない機能)だけを見ており、AI分析 1 件に絞っていた。これは誤りだった。** 計画レビューで限定①(改善を既決にした箇所)に当たる文言が **3 件**見つかったので、例外を一般化する。

- **移さない** — 当該機能が Won't / 破棄で、説明そのものが成り立たないもの(AI分析)

#### 文言ではない意図した差分は、別の対応表で持つ

例外一覧は**文言**だけを扱う。本単位には文言でない意図した差分が 1 件ある — **旧は画面内で遷移し(`dd03160:…:28-35` の `useNavigate`)、新は `back` を emit する**。これは移植規則の「props 契約の比較」に差分として現れるが、例外一覧には入らない。

**ステップ 1 の `design.md` に、文言の例外一覧とは別に「旧 → 新の契約対応表」を置く。** ステップ 3 の合格条件は「**対応表の外で契約の差分が 0 件**」とする。

## 4. 実装方針

### 重さ分類 = 通常

- **コア領域に当たらない。** 意味範囲(設計書 6.3 の境界定義表)で 5 領域すべて非該当 — 「`U-F1` の汎用部品と `U-F4` の静的ガイドは、**6.3 の 5 領域の強制点を変更しない**ためすべて非該当とした」(`design.md:356`、判定表 `:332`)。`paths` にも `frontend/src/screens/*` は 1 件も無いが、**非コアの根拠は意味範囲側で取る**(CLAUDE.md が両者を分ける。対比: **U-F2 は `paths` 外だが T に該当** — `design.md:330,356`)
- **軽微でない。** 新規 `.vue` が 124 行相当 + 試験で、fast path の目安(50 行以下)を超える。文言の採否判断(前提 C)も入る
- **機械的軽作業でない。** 逐語移植だが、前提 A〜C の判断を伴う

→ 優先順位(コア領域 > 軽微 > 機械的軽作業 > 通常)で先に一致するものが無く、**通常**。

### 移植の方針

[porting-rules.md](../frontend-skeleton/porting-rules.md) に従う。本単位に効く点:

- SFC は PascalCase、`components/` でなく `screens/` 配下に置く(旧と 1:1 — `porting-rules.md` 2 節のディレクトリ対応)
- `<script setup lang="ts">` + 型引数の `defineProps` / タプル型の `defineEmits`
- `<style>` ブロックは置かず、Tailwind のクラス文字列で当てる(U-F1 の実測と揃える)
- lucide のアイコンは `lucide-vue-next`(既に dependencies にある)

**外部依存の切り出し**:

| 旧 | 新 |
| --- | --- |
| `useNavigate()` + `navigate(token ? '/' : '/login')`(`dd03160:…:35`) | `defineEmits<[back: []]>()` で **`back` を emit** するだけにする。遷移先の判定(ログイン有無)は呼び出し側 = U-F13 の責務 |
| `useAuthStore`(`:18,30`) | **使わない**(上記により不要) |
| `Button`(`:17`) | `frontend/src/components/ui/Button.vue`(U-F1 で着地済み) |

**`/help` の認可**: 旧実装は `dd03160:frontend/src/App.tsx:56-57` で `/login` と並べて置かれ、**未ログインでも開ける**(認可で囲まれた経路は `/` 以降)。**要件にこれを定めた条文は無い**ため、旧挙動の引き継ぎとして記録する。経路の設置は U-F13 の射程なので、本単位は**この事実を申し送るだけ**で実装しない。

### 文言固定試験の設計(旧システムの先例に倣う)

`dd03160:tests/test_frontend_help_foundation.py`(49 行)は、ガイドの文言を実挙動に固定していた — 存在すべき語句を assert し(`:16-26`)、**撤回済みの語句の不在も assert する**(`:28`・`:39`)。

本単位でも同じ形を Vitest で置く。**不在側を必ず含める**のが要点で、これが無いと文言が二重化しても気づけない。固定する語句は、移植した文言から**旧試験が選んだのと同じ観点**(導線の名前・同期の挙動・出力の境界)で選ぶ。

**不在側の対象は、ステップ 1 の表 A の「移さない」「書き換える」の全件**とする(既知 4 件 = 「AI分析」「PowerPoint」「チーム新規登録」と `:83` の別端末からの再送の案内を含む)。**要件の Won't と衝突する文言が再び混入したら red になる**ので、一覧が機械で守られる。

本タスクで得た知見の候補:

- **版の取り違えが沈黙する型** — 旧リポジトリのクローンは作業ツリーが `0423851`(固定コミット `dd03160` の祖先)で、HelpScreen は **81 行 → 124 行**と実質書き換わっていた。ファイル読み取りしか持たない調査主体は作業ツリーを黙って読む。**同じ警告が `docs/features/req-legacy-frontend-gaps/research.md:35-51` に既にあり、再発が 2 件目**。既存候補への実測追記か `H-*` 昇格かは `/pr` で判断する
