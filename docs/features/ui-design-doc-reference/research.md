# 調査メモ: UI 設計書の不在 — ADR-002 が委任した先が存在しない

## 問い

`ADR-002` が「コンポーネント設計規約は設計フェーズの **UI 設計書**で確定する」と述べるのに、
`docs/design/` に UI 設計書が無い。**(a) 新設 / (b) 参照先の差し替え / (c) 委任の撤回** のどれを採るか。
その判断材料として、① 委任の射程 ② 差し替え先の候補が実際に使えるか ③ `H-68` の型に当たるか
④ 要件書が UI に何を課しているか ⑤ 姉妹カード `TSK-530` と合流できるか、を確かめる。

## 結論(要約)

1. **委任は `ADR-002:36` の 1 行だけ**で、正本のほかのどこにも「UI 設計書」は無い。
   **要件書は UI 設計書へ何も委任していない**(全文 0 件)。
2. **`TSK-530` の前提に訂正が要る。** 「ADR-002 と PO 裁定が並存し、改訂の記録が無い」とあるが、
   **PO 裁定の原典は自ら「この判断は ADR-002 の条項どおりである」と述べ、コード流用案を退けている**。
   **裁定のレベルに衝突は無い。** 実際に残る緊張は実装側にあり、**`.ts` 4 本と CSS が旧とバイト等価で持ち込まれている**。
3. **案 (b) は 2 つの理由で成立しない。** ① `porting-rules.md` は**正本ではない**(一時作業域・索引に無い)
   ② **中身が無い** — 「Composition API」「`<script setup>`」が 0 件で、**`ADR-002:36` が名指しした当のものを持たない**。
4. **案 (a) は `H-68` の発火条件に当たる。** 台帳の定義条件は「**検査・検証の対象になる実体が存在しない段階で、
   その実体のフィールド設計まで文書で閉じようとした**」こと。**14 単位の部品はまだ 1 つも無い。**
   ただし台帳は回避策も書いている — **「隣接規範を引き込む要求を 1 つも書かない」という具体的な制約**。
5. **`ADR-002` の当該 2 行は「決定」節ではなく「帰結」節にある。** 決定節は Vue 3 + TS とツールチェーンだけ。
6. **注意**: **`NFR-022`(アクセシビリティ・国際化)は優先度 Won't**。UI 設計書にアクセシビリティ規約を
   入れると Won't と衝突しうる。
