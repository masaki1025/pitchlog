### 3. 私の仮説の訂正 — `malformed` は使われている

着手時の worklog で「`malformed` フラグが使われていなければ、書式未一致の検出材料を既に捨てていることになる」と書いたが、**これは誤り**。`malformed` は `fs.py:707-708` で `inconsistent` へ落とすのに使われている。

**ただし発火条件が限定的**: `STEP_TOKEN_START_RE = [（(]ステップ[ \t]+(?P<step>[0-9]+)`(`fs.py:22`)に一致した場合だけである。要件書 v2.0 改訂タスクの件名(`docs: 要件書 v2.0 改訂 ステップ1 — …`)は**開き括弧がない**ため `tokens=[]`・`malformed=False` となり、**検出材料はそもそも生成されない**。

したがって F5 が足すべきは「捨てている材料を使う」ことではなく、**「ステップ表に N ≥ 1 あるのに有効トークンが 0 件」という状態そのものを縮退として扱う**ことである。
