### 要件書 v2.2 を同一 PR・同一確定ゲートで改訂する(レビュー 6 周目で確定した経路)

**ハーネスに `approved → in-review` の逆遷移の規定が無い**ことが判明した — 設計書 7.1(:366)は frontmatter を現在状態の唯一の正とし、**7.3(:382)は再変更を「新しい版として同じ確定ゲート」と限定**、定義済みフローは `draft → in-review → 承認 → approved` の**順方向のみ**。前例(要件書 v2.1 + 改善台帳 v1.1)も順方向の一括ゲートで、**逆遷移・版据え置きの前例ではない**。計画の書き方を変えても正本の根拠は生まれない。

**人間裁定(2026-08-18)= 規定のある経路に載せる** — **本 PR で ADR-003 の確定と要件書 v2.2 の改訂を同時に行い、同一の確定ゲート(/finalize-doc)で一括検証する**。これは「新しい版としての改訂」であり 7.3 に完全準拠する。**差し戻しの窓(approved な要件書が実現不能な条件を抱えたまま残る期間)も開かない**。

- **v2.2 で改訂するもの**: **NFR-018 (b) の再構成**(①乖離の検出 ②差分の検出可能性 ③構成の完全性)/ **FR-022 の当日打席結果の列定義**(ADR の列案を反映 — NFR-019(a) の比較面の fail-closed を解く)/ 10 章未決事項表の該当行の現況化 / **(b) の再構成に伴う追随**(確定ゲートで追加 — **NFR-018 の測定方法** / **9 章 R-3 の対策欄** / **NFR-021 のリリース候補条件**と **8 章 DoD②** への NFR-018(b) の機械検査の追加〔Must の達成条件でありながらリリース判定の列挙から漏れていた〕)
- **v2.2 で変えないもの**: (α)(β) の区分と対象の列挙 / 達成条件 (a)(c)(d) / 逐語移植の例外表 / 正解ベクタの発効条件
- **順序**: ステップ 1〜5 で ADR を書き上げ、**ステップ 6〜7 で要件書 v2.2 を起案**(frontmatter を `in-review` へ)→ **/finalize-doc で 2 文書を一括検証** → 承認反映で両方を `approved` へ
- **残る穴は台帳へ**: **設計書に「要件が命じた差し戻しの状態遷移」の区分が無い**こと自体は解消していない(本計画は順方向の改訂に載せ替えて回避しているだけ)。**評価台帳へ `H-*` として起票する**

**裁定の組み合わせから確定する設計上の帰結**: 「生成方式を採る」かつ「4 章に触れない」ため、**DSL 正本・生成器・生成物を `contracts/` に置けない**(4 章:179 の限定文「NFR-018 の実現方式そのものではない」と衝突し版繰り上げ + 7.3 を誘発する — research.md §6 の赤帯)。したがって **DSL 正本と生成器は `backend/` 配下、生成物は backend 側と `frontend/src/lib/generated/` の 2 箇所**とする(`backend/`・`frontend/` の内側の構造は 4 章のツリーの規定外)。

### やること

1. **ADR-003 の新設**(`docs/adr/ADR-003-domain-calc-method.md`)— テンプレート様式(frontmatter 3 行・変更履歴表をメタ表より前・メタ表・文脈/決定/理由/帰結/参照)に従う
2. **決定① 実現手段** — 制約 DSL の射程(状態・イベント・ガード・次状態 / 整数・boolean・enum / 四則・比較・min・max / 明示的丸め / 有限 reducer / 入出力型・範囲・単位・scale)、生成器の責務(遷移の重複・欠落・到達不能の検査、生成元位置のコメント、正本・生成器バージョン・内容 hash の埋め込み)、**却下した方式とその理由**(Pyodide / Rust+WASM / 一般トランスパイル / 手書き interpreter × 2)
3. **決定② (b)② は現行定義では実現不能** — **結論の対象を「要件書 **v2.1** の NFR-018 達成条件 (b)②(:867-870)」と明示的に固定する**(レビュー 7 周目 P1-2 — 同一 PR で v2.2 が当該条文を書き換えるため、対象を版で固定しないと「ADR が v2.2 の条文を実現不能と言っている」と読める)。**典拠付きで結論する**: ① プログラム同値性は決定不能 ② 到達可能性検査で閉じられるのは**モジュール・入口・生成物の集合**であって「同じ計算を別の書き方で書いたソース」ではない ③ 単一ツールでは fail-closed にならない(esbuild は非解析 import を verbatim で残す / ESLint `no-eval` は間接 eval を検出できない — いずれも原典確認済み)。**要件書:870 の明文の経路に従い、同一 PR の要件書 v2.2 で (b)② を再定義する**ことを帰結に書く。あわせて**再定義の材料**を提示する — **(a) 実現可能な近似**(アーキテクチャ完全性検査 = 本番到達可能な入力の全列挙・宣言マニフェストとの照合・動的機構の禁止と検出・Python 側の import グラフ検査)と **(b) その近似でも残る検出不能範囲**を典拠付きで示す。**ADR は要件文そのものを書かない**(要件文は v2.2 側で書く)
4. **決定③ 正解ベクタと比較面** — 付録E ゴールデンケース・付録A 固定ベクタ・付録B-5 変換ベクタ・付録B-6 領域シード(**確定ゲートで追加: 終了判定ベクタ・付録B-3/B-4 座標変換ベクタ・FR-038 責任投手導出ベクタ**)の **形式(versioned JSON の schema)・置き場・CI 配線・後続担当**。**適用対象の runner**((α)=両 runner /(β)・付録B-5=pytest のみ)が**同じファイルを全件消費したこと**まで検査する(未対応 case・未知 field・重複 ID・schema 不一致を fail)/ **期待値を正本実装から自動生成しない**(oracle の循環を避ける)/ 数値の扱い(整数範囲・固定小数点・NaN/Infinity/-0 の禁止・除算の丸め規則の明記)
5. **決定④ FR-022 の当日打席結果の列定義**
6. **決定⑤ 設計書 6.3 の「付録A 契約の実装完了」の判定基準・判定者・手続き**(6.3 が発効判断を ADR に委任している空白)。**発効の宣言自体は行わない**(条件は「実装完了後」)
7. **帰結と見直しトリガー** — 後続タスクへ送る項目の明示、および見直し事象(要件書の差し戻し経路 / 付録A 契約の実装完了 / 対象技術の世代交代)

### やらないこと

| 項目 | 理由 |

| **DSL・生成器・生成物の実装** | ADR は決定文書。実装は別タスク(ADR 確定が発火点 — 要件書:880)。**本タスクはコードを書かない**ため、確定ゲートの反映周コミットに非文書ファイルが混ざらず **H-58 の 3 件目を作らない** |
