# 詳細設計: 同期キュー遷移の矛盾 2 件(U-13・U-14)

調査の典拠は [research.md](research.md)。本書は**確定させる規則の本文案と、波及先の対応表**を持つ。
参照は正本 2-6 の規約に従い**節・表行の安定 ID** で引く(行番号で引かない)。

## 1. U-13 — 「未送信 → 同期済み」の条件

### 1-1. 何が矛盾しているか

7-2 の遷移表(`7-2/r7`)は「**`B1` で** ACK の A5 が…受理または重複を返したこと」と境界結果で限定する。
一方、同じ 7-2 の節末(`7-2/p5` 相当)は「**D1 付きキュー遷移の根拠は A5 だけである**…**D3 は遷移の判定に使わない**」と宣言する。
`A5` はイベント単位の結果なので、`B2`/`B3` で停止した要求でも停止点より前のイベントは確定できる。
`B1` 限定を残すと、**7 件目が `B3` のとき 1〜6 件目が未送信のまま残る**。

### 1-2. 既に決まっていること(動かせない)

- **`SP-01`**(`scripts/design_relations/defects.json`)の positive:
  「**7-2 の遷移条件列は直後の宣言どおり A5 の結果だけをキーとし**、未送信から退避済みへの遷移は A5 の「退避」で条件づけられる。」
  `scope` は 6-3・7-1・7-2。
- 出荷済み実装 `frontend/src/lib/sync/queueTransition.ts` の `QT-02` の条件は
  `{kind:'a5-result', a5ResultIds:['受理','重複']}` のみで、`B1` を持たない。
  独立期待表 `queueTransition.spec.ts` の `QT-02` も同じ構造で `B1` を持たない。

→ **`B1` 限定を外す方向が、機構の不変条件とも実装とも整合する。**正本だけが取り残されている。

### 1-3. 確定させる規則(本文案)

**7-2 遷移表「未送信 → 同期済み」の条件列**:

> ACK の A5 が、当該イベントの `(D4, D1, D5)` について「受理」または「重複」を返したこと。
> **境界結果は条件に用いない** — `B2`/`B3` で停止した要求でも、**停止点より前のイベントは A5 が確定を返すため遷移する**。
> **D1 ≤ D3 だけでは不足**(同じ `(D4, D1)` で異なる D5 を取り違えるため — 起草レビュー 1 周目 P1)

**6-3「キュー状態別の保持・破棄契機」の同期済み行**も同じ条件へ揃える(「B1 で」を外す)。

**6-3 境界結果表の `B1` 行**のキュー状態欄は「A5 が『受理』『重複』を返したイベントは同期済みへ移す」のままでよい
(`B1` の場合にそうなることは真であり、**他の境界結果でそうならないとは書いていない**)。**変更しない。**

### 1-4. 帰結 3 つ(11-4 が「一意にならない」と名指しした項目)

| 項目 | 確定内容 | 根拠 |
| --- | --- | --- |
| **再送量** | 再送は「未送信のまま」の先頭から(7-3 手順 1 のまま)。**A5 で同期済みへ移ったイベントは再送対象から外れる**ので、`B3` 停止後の再送量は停止点以降だけになる | 7-3 手順 1・4。`D3` は再送範囲の決定に使う(7-2 節末) |
| **同期件数の通知** | **部分成功でも、その要求で確定した件数を通知する**。「キューが空になった」は**未送信が 0 件になったとき**に限る(要操作・退避済みは別に表示する) | FR-012(通信復帰・自動再送成功 → キューが空・どの試合の何球分)。7-4 の `Q4`(未送信件数)・`Q5`(キューが空) |
| **キュー空判定** | **単一の「空」を定義しない。用途ごとに 4 つへ分ける**(下表) | 同一語に 4 用途があり、1 つの定義では両立しない(敵対レビュー 1 周目 P0-2) |

#### 1-4-A. 「空」の 4 用途(敵対レビュー 1 周目 P0-2 の是正)

**`未送信` / `要操作` / `退避済み` は排他なキュー状態**であり、`要操作`・`退避済み` は `未送信` に含まれない。
したがって「未送信 0 件」と「要操作・退避済みが残らない」は**別の条件**である。用途ごとに次のとおり定義する。

| 用途 | 定義 | 要操作 | 退避済み | 根拠 |
| --- | --- | --- | --- | --- |
| **① FR-012 の未送信件数**(常時表示・9 章 R-2 の Must) | `未送信` の件数 | **含めない** | **含めない** | 条文が「未送信件数」と書く。`要操作`・`退避済み` は別カウントで併記する |
| **② 自動再送対象が尽きた状態** | `未送信` が 0 件 | **含めない**(7-2 が「自動再送の対象から外す」と定める) | **含めない**(適用されない) | 7-2 のキュー状態定義 |
| **③ `Q5`「同期が成功し、キューが空になりました」の発火条件** | **エッジ条件** — 当該要求の ACK 処理により **`未送信` が非空から 0 へ遷移した**、**かつ その要求で A5 が `拒否` / `退避` / `未処理` を 1 件も返していない** | — | — | **状態述語ではなくエッジで定義する**(敵対レビュー 3 周目 P0-2)。FR-012 の Given/When が「通信復帰 / **自動再送成功**」であり、**初期状態から空の場合に誤発火させない**ためにも遷移が要る |
| **③-b ③ の否定(排他)** | **`E ∧ X`** — `E` = 当該要求の ACK 処理で `未送信` が非空 → 0 へ遷移、`X` = **その要求で A5 が `拒否` / `退避` / `未処理` を 1 件以上返した** | — | — | **`Q5` = `E ∧ ¬X`、③-b = `E ∧ X`** で**排他かつ網羅**(敵対レビュー 4 周目 P0-1 の是正)。**過去の `要操作` / `退避済み` の残存は ③ にも ③-b にも入れない** — それは**別の表示軸**(常時表示の件数)である。**黙らない**(NFR-015) |

> **過去の `退避済み` / `要操作` の残存を ③ の条件に入れない**(敵対レビュー 3 周目 P0-2 の是正)。
> `退避済み` は `U-3` が決着するまで自動破棄されない(7-2 節末が明記)ため、条件に入れると
> **一度でも退避が起きた試合では `Q5` が恒久的に出なくなり**、FR-012 の「自動再送成功時に通知する」を満たせない。
>
> **7-5 の完了判定を流用しない**(同)。7-5 が「拒否・退避・未処理が 1 件でも残れば完了としない」と定めるのは
> **「試合終了宣言後の初回同期」に限定された基準**であり、一般の `Q5` 発火条件ではない。**両者は別の語で書く。**
| **④ FR-007 の修正許可条件** | **`未送信` が 0 件 かつ `要操作` が 0 件** | **含める** | **含めない** | FR-007 の目的は「断中の記録と修正が交差して正史が壊れるのを防ぐ」。`要操作` は**現世代の正史へ入る予定の未解決イベント**なので交差する。`退避済み` は**現世代の正史へ適用されない**(7-2・FR-013)ため交差せず、含めると**永久に修正不能**になる |

> **④ で `退避済み` を除外する理由を正本へ明記する。**除外しないと、退避が 1 件でも出た試合は
> 以後すべての進行中修正が不可能になる(`退避済み` の保持期間は `U-3` 未決であり、自然消滅も保証されない)。

> **② と ③ が食い違う状態が正常に存在する**(`未送信` は尽きたが、その要求に拒否・退避があった = `E ∧ X`)。
> このとき **`Q5` は出さず**、③-b を出す。**両者は排他**であり同時には成立しない。
> **過去の `要操作` / `退避済み` の残存は ③・③-b のどちらの条件にも入れない**(別の表示軸)。
> **③ と ④ も食い違う**: `退避済み` だけが残る状態は、**FR-007 の修正は許可する(④)**。
> `Q5` が出るかどうかは**その要求に拒否・退避があったか**で決まり、過去の残存では決まらない。
> **正本はこの 4 つ(+③-b)を別語で書き、同じ「空」という語で束ねない。**

## 2. U-14 — 保存済み P4 退避の再掲で返す境界結果

### 2-1. 何が矛盾しているか

| 側 | 箇所 | 記述 |
| --- | --- | --- |
| `B1` 側 | 6-3「キュー状態別の保持・破棄契機」の退避済み行 | 「**B4、または保存済みの「退避」を A5 で再掲する `B1` のイベント**」 |
| `B1` 側 | 7-2 遷移表「未送信 → 退避済み」 | 「境界結果が B4 の場合に加え、**保存済みの退避結果が `B1` で再掲された場合も含む**」 |
| `B4` 側 | 7-1 の再送の総括 | 「受理済みの再送は B1 の「重複」、拒否済みは B3、**退避済みは `B4` と同じ理由を再掲する**」 |
| `B4` 側 | 7-3 手順 3 | 「…**P4 の退避なら同じ `B4`・退避結果**を返す」 |
| `B4` 側 | 10-2 故障系シナリオの P4 行 | 「引き継ぎ後の再送は現在の V12 を検査せず**保存済みの `B4`・退避結果を再掲**し、第 2 の退避原本を作らない」 |

### 2-2. 選択規則は既に正本から導ける

**一次根拠は 6-2「網羅性の根拠 — 処理段階の列挙」**である。同表は `B1`〜`B7` がどの段階で生じるかを定義しており、
**`B4` は段階 ⑤ でしか生じない**:

| 段階 | 何を確かめるか(原文の要点) | 境界結果 |
| --- | --- | --- |
| **④ D5 の照合** | 「**各イベントを内部候補へ分類する。**既存 D5・同一内容なら**保存済み結果を再掲する候補**として再適用せず、既存 D5・異なる内容は B3b 候補とし、**未使用 D5 だけ⑤へ進む。この段階では外部結果を確定しない**」 | B3b 候補 |
| **⑤ 記録権(D4・V12)** | 「**未使用 D5 の新規操作について**、D4 が現世代で、V12 が現保持端末へ結合された証明として有効か」 | **B4 記録権不一致** |
| ⑥ 連番(D1)の連続性 | 欠落の走査。最初の B2 または B3 で止める | B2 / B3b |
| ⑦ 内容の検証 | ⑥ を通過した**未使用 D5** の内容 | B3a |
| ⑧ コミット直前の RG1 再検証・完了 | 最後まで処理し切ったか | **B1 要求終端** |

→ **保存済みの退避結果は段階 ④ で「再掲する候補」に分類され、段階 ⑤ へ進まない。**
したがって**未使用 D5 を持たない要求は `B4` になり得ない。**

> **前提: 本規則は ACK を返す経路だけを対象とする**(敵対レビュー 2 周目 P0-1)。
> 7-1 の **A3** が「**ACK が返るのは `B1`〜`B4` の場合に限る** — `B5`(認証失効)・`B6`(認可)・`B7`(一時障害)では
> **ACK 自体が返らない**」と定める。**ACK が返らない要求では A5 も返らず、保存済み退避結果の再掲も起きない。**
> **段階 ⑧ はコミット直前の RG1 再検証で `B7` へ分岐しうる**(「復元調整へ移行済みなら `B7` として全変更をロールバック。
> **通過時だけ `B1` 要求終端**」)ので、**段階 ⑦ まで通過しても `B1` に確定しない**。
>
> **ここから先は `B1` に確定しない**(敵対レビュー 1 周目 P0-1 の是正)。
> 段階 ④ は**既存 D5・異なる内容を `B3b` 候補**に分類し、段階 ⑥ が「D3 + 1 から D1 昇順に走査し…
> **最初の B2 または B3 で止め**」てそれを外部結果へ確定する。
> **未使用 D5 が 1 件も無い要求でも、再掲候補の並びに欠落があれば `B2`、`B3b` 候補があれば `B3` で停止する。**
> `B1` は段階 ⑧ を通過したときだけである。
> **確定できるのは「未使用 D5 の V12 不一致なら `B4`、それ以外は `B4` ではない」までで、
> その先は段階 ⑥〜⑧ が `B2` / `B3` / `B1` / `B7` を決める。**

**二次根拠**として 7-1 の経路別応答契約 `P4` が同じことを述べる:

> ③認可後かつ V12 前に D5 を照合し、**保存済みの退避結果は現在の記録権によらず再掲する**。
> **未使用 D5 だけを V12 照合へ進め、不一致なら `B4`** と A5 の「退避」を返す。

6-3 の 3 例表の「**B4 は含めない** — 記録権の照合は段階 ⑤ で **D1 の処理より前**に行われるため、
**B4 では D3 が前進しない**」も同じ構造を裏づける。

**結論**: 境界結果を決めるのは**未使用 D5 が段階 ⑤ を通過するか**であって、保存済み退避結果の再掲ではない。
**この規則は新設ではなく、6-2 の処理段階表から導かれる既存の意味論である。**
`U-14` の欠陥は、7-1 の総括・7-3 手順 3・10-2 が **`B4` を無条件に述べていて 6-2 段階 ⑤ と食い違う**ことにある。

### 2-3. 確定させる規則(2026-09-24・人間の方式判断)

> **保存済み退避結果の再掲は境界結果を決めない。境界結果は未使用 D5 の V12 照合で決まる。**
>
> | 要求の構成 | 境界結果 | `D3` | 通知 |
> | --- | --- | --- | --- |
> | **未使用 D5 があり、段階 ⑤ の V12 照合が不一致** | **`B4`** | **前進しない** | 記録権不一致・退避・**破棄されていないこと** |
> | **上記以外で、段階 ⑧ を通過するか ⑥/⑦ で停止**(未使用 D5 が無い、または V12 が一致) | **`B4` 以外の ACK 経路** — 欠落なら **`B2`**、`B3a`/`B3b` なら **`B3`**、通過すれば **`B1`** | その境界結果の規定どおり | その境界結果の規定どおり。**加えて、A5 が「退避」を返したイベントの退避を顕在化する** |
> | **`B5`**(認証失効)/ **`B6`**(認可)/ **`B7`**(一時障害・段階 ⑧ の RG1 検知を含む) | **ACK が返らない** | クライアントへ返らない | **クライアントへ A5 が届かないため、退避結果の再掲も退避の顕在化もクライアント側では起きない**。キュー状態は変わらない(7-2 の「未送信 → 未送信(応答前の状態維持)」)。**サーバー側の確定の有無は境界結果ごとに異なる** — 段階 ⑧ の RG1 検知は**全変更をロールバック**するが、**通信・ACK 消失の `B7` はサーバーで部分確定済みの場合があり、その D3 は次回再送の応答で取得する**(6-3 の `B7` 行。敵対レビュー 4 周目 P0-3 の是正) |
>
> **ACK を返す `B1`〜`B4` では A5 が当該イベントについて「退避」を返し**、クライアントは `SP-01` のとおり
> **A5 だけをキーに「未送信 → 退避済み」へ遷移する**。
> **`B1` に限らない** — 保存済み退避結果の再掲は **ACK を返す `B1`・`B2`・`B3`・`B4` のどの境界結果の要求でも起こりうる**。
> **`B5`・`B6`・`B7` では起きない**(ACK が返らないため)。

**5 箇所の現状の評価**(敵対レビュー 1 周目 P0-1 で修正):

| 側 | 評価 |
| --- | --- |
| `B1` 側 2 箇所(6-3 保持表・7-2 遷移表) | **不完全**。`B1` を例示しているが、**`B2`・`B3` の要求でも再掲は起こる**。条件を補うだけでは足りず、**境界結果を列挙しない形へ書き直す** |
| `B4` 側 3 箇所(7-1 総括・7-3 手順 3・10-2) | **不完全**。`B4` を無条件に述べており、**6-2 段階 ⑤ と食い違う**。条件を補う |

→ **「削除した記述 0 件」は受入条件にできない**(同 P0-1)。`B1` 側は**書き換えを伴う**。
守るべきは「**どちらか一方の側を丸ごと捨てない**」ことであって、字句の保存ではない。

### 2-4. 各箇所の補い方

| 箇所 | 補う条件 |
| --- | --- |
| 6-3 保持表の退避済み行 | 「`B4`、または**保存済みの「退避」を A5 で再掲した要求**のイベント(**境界結果は問わない**)」— **`B1` を例示しない** |
| 7-2 遷移表「未送信 → 退避済み」 | 条件列は **A5 の「退避」だけ**にする(`SP-01` の positive)。**境界結果への言及を条件列から外す**。境界結果が `B1`〜`B4` のいずれでも遷移は同じであることを節の説明として 1 文で書く |
| 7-1 の再送の総括 | 「退避済みは**同じ退避結果を再掲する**。**境界結果は段階 ⑤ の未使用 D5 の V12 照合と段階 ⑥〜⑧ が決める**(再掲そのものは境界結果を決めない)」 |
| 7-3 手順 3 | 「P4 の退避なら**同じ退避結果**を返す。**境界結果は 6-2 の段階列挙に従う** — 未使用 D5 が V12 不一致なら `B4`、それ以外は段階 ⑥〜⑧ が `B2` / `B3` / `B1` を決める。**段階 ⑧ で RG1 を検知した場合は `B7` となり ACK が返らないため、再掲も起きない**」 |
| 10-2 の P4 行 | 「引き継ぎ後の再送は現在の V12 を**保存済み結果の再掲には**用いず、同じ退避結果を再掲し、第 2 の退避原本を作らない。**境界結果は 6-2 の段階列挙に従う**」 |
| 7-1 の `P4` 行 | **変更しない**(既にこの規則) |
| 6-2 の処理段階表 | **変更しない**(**一次根拠**。段階 ④ で保存済み結果は再掲候補に分類され、段階 ⑤ へ進まない) |

### 2-5. 新しいコードを作らない

決定済み規律「**新しい境界結果コード・新しい A5 結果値・新しいキュー状態を発明しない**」(6-3・O4 の前例)に従い、
`B1`〜`B7` と A5 の 5 値、キュー 4 状態はいずれも増やさない。**本設計は既存コードの適用条件を明文化するだけ**である。

## 4. 通知契約 — 機械で閉じる範囲と、閉じない範囲

> **2026-09-24・PO 裁定 = 範囲確定 + 述語を弱める**(敵対レビュー 4 周目の後)。
> 計画レビューが **8 → 6 → 6 → 9 件**と収束せず、**4 周目の 9 件中 8 件が 3 周目の反映そのものへの指摘**だった。
> 原因は本節で「`N1`〜`N5` を全確定し、発火ロジックと exact-set テストまで本タスクで閉じる」という
> **強い述語を足したこと**。台帳 **H-22**(自分が新設した規定の穴を次の周が突く)・**H-68**(実機のない段階で
> 細部まで確定させようとすると閉じた輪に入る)・**「強い述語が細部を無限に呼ぶ輪」**(TSK-335)と同型である。
> **述語を弱め、閉じない範囲を受け取り先つきで列挙する形へ改める。**

### 4-1. 本タスクが正本で閉じる範囲(機械で表現できるもの)

| 事項 | 確定内容 | なぜここで閉じられるか |
| --- | --- | --- |
| **「空」の 4 用途の存在と定義** | 1-4-A のとおり ①〜④ を**別語**で定義する | **状態語の定義**であり、既存のキュー 4 状態(`R-QUEUE-LIFE` が固定)だけで書ける。新しい語彙を増やさない |
| **③ / ③-b の条件** | `Q5` = `E ∧ ¬X`、③-b = `E ∧ X`(1-4-A) | **論理式**であり、A5 の 5 値(`R-ACK-STATE` が固定)とキュー状態だけで書ける |
