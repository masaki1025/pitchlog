## 2. FR-034 の認可行列

**要求の形**: すべての共有リソース要求は **① グループ ② 対象テナントの集合**を明示する(裁定 10)。集合の要素ごとに下表を評価し、**1 要素でも満たさなければその要素を結果から除外する**(要求全体を失敗させない)。除外されたテナントは**結果に現れない**(存在を漏らさない)。

**全行に掛かる前提条件**(要素ごとに評価):

1. **指定されたグループが `active`**(終了していれば除外)
2. **要求元と対象テナントの参加がともに `active`**(離脱済みは除外)
3. **両テナントが無効化されていない**(FR-035 のチーム無効化 → 除外)
4. 裁定 2 により **要求元テナントが同一の付与を、指定されたグループで出している**
5. **自テナント自身が集合に含まれる場合**は、付与・相互性の条件を**適用しない**(自分のデータであるため常に通る)。ただし**同時比較表示上限には数える**(画面に並ぶ列数の制限であるため)。既定の要求は自テナントのみ(§3.2) — 8 周目 P1-N1
6. **要求された集合の要素数が同時比較表示上限以下**(超えていれば**要求全体を 400 で拒否**する。切り捨てない — §3.2)

| 要求されるリソース | 通るために必要な条件(上記 6 前提に加えて) | 満たさないとき |
| --- | --- | --- |
| チーム集計(打撃・投球成績) | 相手が `成績` を付与 ∧ 要求元も `成績` を付与 | **除外(結果に現れない)** |
| チーム概要(試合数・勝敗等) | 同上(`成績` に含む) | **除外** |
| 選手個別(実名つき) | 相手が `選手個別` を付与 ∧ `成績` の付与あり ∧ 要求元も同等 | **除外** |
| 共有集計のエクスポート | 相手が `書き出し` を付与 ∧ 当該データ種別の付与あり ∧ 要求元も同等。対象は §2.1 の資源に限る | **除外** |
| **1 球単位の生記録**(FR-031 の 88 列 CSV を含む) | **付与によらず不可** | **404** |
| カルテの所見 | **付与によらず不可** | **404** |
| 第三者として記録した対戦相手データ | **付与によらず不可** | **404** |
| **身体プロフィールの分布** | **v2.0 では共有しない**(裁定 9。v2.1 で実体とともに追加) | **404** |
| 単一テナントを名指しした直接アクセス(グループ指定なし) | — | **404** |

**「除外」と「404」の使い分け**: 集合要求の要素は**除外**(結果に現れないだけ。0 件と権限なしを応答から区別できない = 存在秘匿が保たれる)。単一リソースを名指しした要求は **404**。いずれも**理由コードを返さない**。

**404 を維持する理由**: 「同席あり・付与なし」で 403 を返すと「そのチームが存在し、グループに同席している」ことが漏れる。NFR-010 の「内容・存在を含め参照できない」原則を付与範囲外では保つ。

### 2.0 既定拒否の原則(12 周目 — 認可を全域関数にする)

**FR-041 が新設する権限・経路によって得られるアクセスは、§2.0-0 の許可リストに明示的に列挙されたものだけである。それ以外のすべての資源・すべての経路は、既定で拒否される(404)。**

**射程の限定**: 既定拒否が適用されるのは「**FR-041 が新設する権限・経路**」のみである(14 周目 P1-1 の是正 — 当初の表現では**グループの作成と招待の受諾が参加前の操作**であるため射程から漏れていた)。**それ以外の権限源による既存のアクセスは本要件の射程外**であり、現行のまま変わらない — とくに **FR-035・FR-037 の管理者機能**(退避イベントの閲覧・書き出し / チーム・選手・スタメン・試合の横断一覧 / 試合 CSV / 操作ログ閲覧)は**既存の Must 要件として維持される**。当初は管理者の閲覧を全面否定していたが、それでは既存 Must と衝突するため是正した。

12 周目までの 3 周、周回ごとに「未定義のリソースクラス」が見つかり続けた(出力経路 → 管理者出力・制御資源 → テナント所有マスタ・設定資源・認証資源・同期資源・監査資源・移行資源)。原因は**許可されるものと拒否されるものの両方を列挙しようとしていた**ことである。認可を全域関数にするのに必要なのは**既定拒否 + 明示的な許可リスト**だけであり、許可リストは小さい。**この形にすれば「6 つ目のクラス」は原理的に存在しない。**

### 2.1 共有集計エクスポートの資源定義と出力契約

FR-031 の CSV は「88 列互換フォーマット(付録D)の**全プレイ行**」= 生記録そのもの(`:495`)であるため、**優先順位で解決せず別の資源種別として定義する**。

| | FR-031 の CSV 出力(既存) | 共有集計エクスポート(新規) |
| --- | --- | --- |
| 内容 | 88 列互換フォーマットの**全プレイ行** | **同時比較で表示している集計値のみ** |
| 対象 | **自テナントのデータのみ** | 付与された範囲 |
| 共有グループ経由の可否 | **不可**(付与によらず 404) | `書き出し` の付与で可 |

**出力契約**:

| 項目 | 規定 |
| --- | --- |
| 形式 | CSV(BOM 付き UTF-8)。数式インジェクション対策は FR-031 の受け入れ基準を継承 |
| **スキーマ版** | 1 行目に `schema_version` を出力する。指標の追加で版を上げる |
| **異種 grant の扱い** | 参加テナントごとに付与粒度が異なりうるため、**粒度ごとにファイルを分ける**。1 ファイルに混在させると列の有無がテナントごとに変わり CSV として表現できない。各ファイルには**その粒度を付与しているテナントの行のみ**を含める。**除外されたテナント名は出力しない**(存在を漏らさない) |

### 2.2 撤回の経路と効果

**招待の失効は権限の撤回ではない**。未消費コードの参加能力を失わせるだけで、既に参加したメンバーの参照権限には影響しない。

**効果の表れ方は §2 の要求形と一致させる** — **集合要求ではその要素が結果から除外**され、**単一リソースを名指しした要求は 404**(7 周目 P1-1 の是正。当初この表を一律 404 と書いており §2 と二重定義になっていた)。

| 経路 | 効果 | キャッシュ無効化(6.2) |
| --- | --- | --- |
| 付与フラグを戻す | 当該粒度が**除外 / 404** | **要** |
| 離脱 | そのテナントの全リソースが相互に**除外 / 404** | **要** |
| グループ終了 | 全参加テナント間で全リソースが**除外 / 404** | **要** |
| テナントの無効化(FR-035) | そのテナントの全リソースが**除外 / 404** | **要** |
| 招待の失効 | **未消費コードの参加能力のみ**。既存メンバーの権限は不変 | 不要 |

いずれの経路でも **既に閲覧・書き出されたデータは戻らない**(9 章 R-13)。

**テナントの再有効化**(9 周目 P1-N2 — 状態機械の未定義入力だった):

| 論点 | 規定 |
| --- | --- |
| グループへの参加 | **無効化中も参加レコードは維持**され、再有効化で**そのまま復帰**する(離脱とは異なる) |
| 無効化中に自動終了したグループ | **復活しない**。グループの終了は不可逆(§3.5 — 唯一の `admin` テナントの無効化で自動終了する場合) |
| 参加上限の計数 | 無効化中は `active` でないため**計数しない**。再有効化で再び計数する。**再有効化によって参加数が上限を超える場合も既存参加は維持**する(裁定 6 の「上限引き下げでも既存参加は維持」と同じ扱い。新規参加のみ拒否) |
| キャッシュ | **再有効化も失効トリガーとする**(無効化中に「除外」で構築されたキャッシュが残ると、復帰後も見えないままになる) |

| 撤回 | **§2.2 の表**が正 |
| 突合の範囲 | **集計値の比較まで**(裁定 4) |

### 3.2 参加・同時比較の契約(裁定 3・6)

| 項目 | 規定 |
| --- | --- |
| 設定値 | 付録C に 2 行 — **参加テナント上限**(既定 50)/ **同時比較表示上限**(既定 10) |
| **安全範囲** | いずれも 1 以上の整数。**`同時比較表示上限 ≤ 参加テナント上限` を不変条件**とし、これを破る設定値は保存できない(FR-014 の「不正な規則値は検証エラーで保存できない」と同じ扱い) |
| 参加数の計数 | **`active` な参加のみ**(離脱で枠が空く)。無効化されたテナントの参加は計数しない |
| 上限到達時 | 招待の**受諾を拒否**し、**発行時点でも拒否**する |
| **同時受諾の競合** | 参加の確定は**サーバー側で直列化**し、上限超過を発生させない(先着のみ成立し、後着は上限到達として拒否される)。楽観ロックではなく確定時の再検査で担保する |
| 再参加 | 離脱後の再参加は**新規参加として計数**する |
| 設定値の引き下げ | 現在の参加数未満へ下げても**既存の参加は維持**し、新規参加のみ拒否する |
| **比較対象の指定** | **要求パラメータとして受け取る**(裁定 10 — 選択状態をサーバーに永続化しない。個人アカウントが Won't で数十名が PW を共有するため、永続化しても認可の根拠にならない)。要求は**グループと対象テナント集合**を明示する |
| **上限を超える指定** | 同時比較表示上限を超える集合が要求されたら**要求全体を 400 で拒否**する(切り捨てない)。クライアント側の制御だけに依存しない |
| **同時比較上限の引き下げ** | 選択状態を永続化しないため**既存選択の問題は生じない**。引き下げ後の要求から新しい上限が適用される |
| **設定値の変更統制** | 同時比較表示上限の**引き上げは NFR-003・NFR-005 の再試験を要する**。付録C の当該行にこの注意を明記する |

### 3.3 性能試験の母集団(裁定 7)

**参加上限まで参加しているグループ**(既定 50 テナント)で、**各参加テナントが 15 万プレイを持つ**状態を作り、そのうち**同時比較表示上限(既定 10)を選択**して測定する。

- NFR-003 の「初期表示 5 秒以内」はこの条件で判定する
- **非選択の 40 テナントを読み込まないこと**を測定条件に含める(選択されていないテナントのデータ走査が発生しないこと)
- 「グループ全体で 15 万プレイ」という読み方は**採らない**(同時比較 10 なら各 1.5 万 = 半年分程度でしか試験されず、使い込むと遅くなるのに要件上は合格してしまう)
- NFR-005 の「全件読み込み型の集計を実装しない」規律は横断集計にも及ぶ

### 3.4 プロフィール共有は v2.0 の範囲外(裁定 9)

**身体プロフィールの共有は v2.0 では行わない。** 共有対象の実体(身長・体重・生年・野球歴・主ポジション)が現行 FR-015 に存在せず、選手プロフィール・身体測定履歴は v2.1 送りであるため、v2.0 単独では受入データを構築できない(6 周目 P1-3)。

**v2.1 で同時に行うこと**: `プロフィール` 粒度の追加 / **分布の最小集団数**(旧裁定 8 — 対象が少数だと平均・最小・最大から個人の身体データが確定するため、属性ごとの有効母数で閾値を設ける)/ その失敗応答と存在秘匿の両立。

### 3.5 操作の主体

**テナント側の権限**(そのテナントを代表して操作できるか)と**グループ内の役割**(そのグループで何ができるか)の **2 層**で判定する。**下表は本節の本表 8 行を漏れなく 3 分類する**(16 周目 P1-1 — 当初は 2 分類しか置かず、役割欄が `参加が active` の「比較対象の指定」がどちらにも該当しなかった)。

| 判定 | 対象操作 | 根拠 |
| --- | --- | --- |
| **2 層**(テナント側の権限 ∧ グループ内の役割 `admin`) | 招待の発行・失効 / 役割の変更 / グループの終了 | 役割欄が `admin` |
| **テナント側の権限のみ** | グループの作成(役割 `—`)/ 参加(役割 `—`。**加えて招待の有効性検証**)/ 付与フラグの変更(役割 不問)/ 離脱(役割 不問) | 役割欄が `—`(参加前で役割が存在しない)または「不問」 |
| **制御資源への操作ではない** — **§2 の認可行列が支配する** | **比較対象の指定**(要求パラメータ) | 共有データの**参照**であり、許可リスト**行 1**(§2.0-0)に属する。管理権限は不要で、**参加が `active`** であることに加えて §2 の前提条件・リソース行がそのまま適用される |

上 2 行が**許可リスト行 4「制御資源への操作」の 7 操作**であり、§6 のテスト条件もこの 7 操作に対応する。

14 周目 P1-3・15 周目 — 当初「すべての操作で両方」と書き、次に「役割欄が `—` でない操作は 2 層」と書いたが、**役割欄には `—` と「不問」の 2 種類**があり、後者(付与変更・離脱)が両方の分類から漏れていた。

| 操作 | テナント側 | グループ内の役割 |
| --- | --- | --- |
| グループの作成 | 管理権限を持つ者(裁定 1) | — (作成者が初期 `admin`) |
| 招待の発行・失効 | 管理権限を持つ者 | `admin` |
| 参加(招待の受諾) | 管理権限を持つ者 | — |
| 付与フラグの変更 | 管理権限を持つ者 | 不問(`member` でも自テナントの付与は変更できる) |
| 離脱 | 管理権限を持つ者 | 不問 |
| **役割の変更**(admin 追加・降格) | 管理権限を持つ者 | `admin` |
| **グループの終了** | 管理権限を持つ者 | `admin` |
| **比較対象の指定**(要求パラメータ) | 管理権限は不要(参照操作) | 参加が `active` であること |

**不変条件**: グループに `active` な `admin` が 1 名以上存在すること。したがって**最後の `admin` は離脱も降格もできない**(降格だけを禁じ忘れると、降格 → admin 不在になる)。

**テナント無効化との関係**(6 周目 P1-7): FR-035 でテナントを無効化するとき、そのテナントが**唯一の `admin` であるグループは自動的に終了する**(§2.2 の撤回経路「グループ終了」と同じ効果)。無効化を拒否したり移譲を要求したりはしない — 管理者の無効化操作が他テナントの状態に阻まれるのを避けるため。**終了したことは残る参加テナントに通知する。**

### 4.2 付録A-5 チーム指標(初版)

**A-4 は「作戦の成否定義」で使用済みのため A-5。** 冒頭に「実機検証前の設計」の位置づけ注記を置き、**指標の追加**は設計フェーズで確定する(裁定 5 の唯一の適用箇所)。

**共通の母集団**: A-1 の共通規則を継承し、**ゴミ箱内の試合を除外**する。対象は**終了済みの試合のみ**(未終了試合は集計に含めない)。

**期間・区分の既定は分析ブロックの共通規則に従う**(6 周目 P1-10 の是正 — 当初「既定 = 当該年度」としたが、ブロック 4 の共通規則が「**絞り込みは任意で既定 = 全データ(全期間・全区分)**」と定めており衝突していた)。軸は期間・試合区分・大会名。

**選手の在籍区分との関係**: チーム指標は**試合単位の集計**であり、選手の在籍区分(現役 / OB)で母集団を変えない。OB 化した選手が出場した試合も、その試合が対象期間・区分に含まれるならチーム通算に算入する(6 周目 P1-10)。※共有機能(FR-041)が選手個別を `active` に限るのは**選手単位の共有**の話であり、本節のチーム集計とは別軸である。

| 指標 | 定義 |
| --- | --- |
| 試合数 | 対象期間の終了済み試合数 |
| 勝 / 敗 / 分 | 最終スコアの比較による。**引き分けは分**。コールド・タイブレークで終了した試合も最終スコアで判定する |
| 得点 / 失点 | 対象試合の合計 |
| 得失点差 | 得点 − 失点 |
| チーム打率 | **通算の分子分母で算出**する(試合ごとの打率を平均しない)。安打合計 ÷ 打数合計。打数の定義は A-3 と同一 |
| チーム出塁率 | 同上。定義は A-3 と同一 |
| チーム長打率 | 同上。定義は A-3 と同一 |
| **イニング別得点・失点** | イニングごとの**合計得点と、そのイニングを戦った試合数**を併記する(平均ではなく合計 + 母数)。**延長回は「10 回以降」として 1 つにまとめる**(タイブレークの有無で回の意味が変わるため、回ごとに分けない) |

## 6. テスト影響(NFR-019)

本タスクはコード変更を伴わないため本 PR でテストコードは追加しない。**要件書側に合否定義を書き**、実装は Phase 4 以降のタスクへ送る。

**越境アクセステスト(NFR-019(b))の網羅すべき組合せ**:

- **付与の粒度 3 種**(`成績` / `選手個別` / `書き出し`)の組合せ × 相互性(要求元が同一粒度を出しているか)
- **グループ終了後** / **離脱後** / **付与撤回後** / **テナント無効化後**
- **複数グループへの同時参加** — 同じ 2 テナントが片方のグループでは付与あり・他方では非付与のとき、**要求で指定されたグループの付与のみを評価する**(裁定 10)。付与ありのグループを指定すれば通り、非付与のグループを指定すれば除外される。**他グループの付与は一切影響しない**
- **資源種別ごと**(成績 / 選手個別 / 概要 / エクスポート / 生記録 / カルテ所見 / 第三者データ / **プロフィール分布は v2.0 では常に 404**)
- **制御資源の認可**(13 周目 P1-4) — グループ一覧 / メンバー一覧(テナント名のみ vs 参加日時・役割) / 各メンバーの付与状態 / 招待の一覧について、**① 参加テナントの正当な閲覧 ② `member` が `admin` 限定の情報を要求したときの拒否 ③ 非参加テナントからの要求が 404**(参加していないグループの存在が漏れないこと)
- **制御資源への操作**(§3.5 の判定表)— **2 層を要する 3 操作**(招待の発行・失効 / 役割変更 / 終了)で `member` からの要求が拒否されること。**テナント側の権限のみの 4 操作**(作成 / 参加 / **付与フラグの変更** / **離脱**)が役割によらず通ること。**参加は招待の有効性検証**も要すること。**最後の `admin` の離脱・降格が拒否**されること
- **再有効化後**(13 周目 P2-5)— 共有が復帰すること / **自動終了したグループは復帰しないこと** / 無効化中に構築された除外キャッシュが残らないこと
- **既定拒否の検証** — 許可リスト(§2.0-0)に無い資源への共有グループ経由のアクセスがすべて 404 になること。**2.0-1 の各クラスから代表サンプルを 1 つずつ**取る(網羅ではなく既定拒否が効いていることの確認)
- **グループを指定しない**単一テナント名指しの直接アクセス(裁定 10 により選択状態は永続化しないため、「選択していないテナント」という状態は存在しない — 8 周目 P1-N1)
- **参加上限の同時受諾**(直列化により超過しないこと)
- **同時比較上限を超える集合**の要求に対する 400 拒否(切り捨てないこと)
- **自テナントを含む集合**の要求(自テナント要素は付与によらず通り、上限には数えられること)
- **選手の在籍区分の変更(FR-017)後**にキャッシュが失効し、OB 化した選手が共有結果に現れないこと
- ※**招待の失効は権限撤回ではない**ため、認可の主要組合せには含めない(発行・受諾の可否テストとして別に扱う)

**その他の種別**: 単体 = 付与の評価ロジック・第三者データの除外・チーム指標の計算契約・同時受諾の直列化 / 故障系 = 撤回とキャッシュ無効化の競合 / E2E = 作成 → 招待 → 参加 → 付与 → 選択 → 閲覧 → 撤回の一巡 / **一致性(NFR-019(a)) = 拡張しない**。
