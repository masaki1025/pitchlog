## 4. 実装方針

**重さ分類 = 通常** の根拠: 変更は**正本ドキュメントのみ**で、`backend/`・`frontend/`・`contracts/` に触れない。CLAUDE.md が列挙するコア領域(同期プロトコル / 状況計算 / 記録権 / テナント分離 / データ移行)の**コードには一切触れない**(`.claude/core-areas.json` の `guard_paths` にも該当しない)。ただし**確定ゲート自体は `/finalize-doc` が `review adversarial`(sol xhigh)を使う**ため、レビュー強度は敵対レビューになる。

### arch の識別経路(1 周目 P0-2・2 周目 P1-5 の是正)

`:920` は**固定版の切替規則**であり通常の受入証跡を拘束しない。したがって arch の識別は **`:923`(証跡の必須項目)の既存欄の要求内容**で担保し、**onboarding に判定可能な採取手順**を置く。

- **採取する 3 値**(それぞれ独立に正規化する — 計画レビュー 3 周目 P1-2): **`host`** = `cmd.exe /C 'echo %PROCESSOR_ARCHITECTURE%'`(**パイプを挟まずに終了コードを捕捉**し CR はパラメータ展開で除去 — 確定ゲート 2 周目 P1)/ **`wsl_uname`** = `uname -m` / **`wsl_dpkg`** = `dpkg --print-architecture`
- **6 ラベルを `; ` 区切りの 1 物理行で出力し、結果証跡の「標準出力またはログ成果物への参照」欄へ直接記載する**(確定ゲート 2 周目 P1 — 別ファイルへの参照だけにしない。証跡本文は append-only で保護されるが参照先は上書きされうる。**確定ゲート 3 周目 P0**: 当該欄は Markdown 表の 1 セルなので、**改行を含めると完全性検査 ⑩ の表抽出が打ち切られ当該欄と後続欄が欠落扱いになる**。`<br>` もプレースホルダ検査に掛かる)。ブロックは**サブシェル**で実行し `errexit` を呼び出し元へ残さない
- **許容表記の対応表**(正規化の規則):

  | 正規化後 | 許容する生出力 |
  | --- | --- |
  | `x64` | `AMD64`(Windows)/ `x86_64`(`uname -m`)/ `amd64`(`dpkg`) |
  | `arm64` | `ARM64`(Windows)/ `aarch64`(`uname -m`)/ `arm64`(`dpkg`) |

- **不適合の判定(fail-closed)**: ① 3 値のいずれかが**欠落**している ② いずれかの生出力が**上表のどの行にも一致しない** ③ **`host` / `wsl_uname` / `wsl_dpkg` の正規化結果が 3 値そろって一致しない** — このいずれかで**受入プロファイル外**とする(WSL2 は同一アーキテクチャの VM で動くため、不一致は環境の異常を意味する)。「どちらを WSL の代表値とするか」を実装者判断に委ねない
- **現行 onboarding には依拠できない**: `dpkg --print-architecture` は `:116`・`:155` の apt ソース設定内にあり、**WSL 側の値であって記録対象にもなっていない**
