## 4. 発効条件 (iv) の判定基準(原典の要約 — `ADR-003:895-983`)

- **射程**: NFR-018 の (β) 全体(①〜⑤ および ⑦)。Must に限らず Should・Could の受け入れ基準が定める集計も対象(`:898-905`)
- **母集団**: 付録A の指標行 40(2 節)
- **判定の材料**: 各必須集計が SQL 側で要求する**演算の包絡**。包絡は「変換可能な部分集合」が満たすべき**下限**(`:911-913`)
- **判定**: 40 行それぞれの区分(`:934-958`)が、段階 2 が定めた変換可能な部分集合に収まるか。「/」の行は**どちらも覆うこと**(`:931-932`)
- **変換不能と判定されたとき**: (a) 部分集合を拡張 / (b) 当該集計の対象区分を変更 / (c) 要件側で再定義 — **いずれも正本の改訂を要し、手書き SQL での代替は不可**(`:972-976`)
- **充足時点**: 「どの構文・どの演算を許すかの具体は段階 2 で定める」ため、部分集合が存在しない時点では判定できない。包絡が部分集合に収まるかの判定は**段階 2 が部分集合を定めた後**(`:977-983`)。v0.6 の変更履歴も「(iv) の充足は本改訂では行わない…発効は段階 2(TSK-538)の後」(`:11`)
- **充足の判定の仕方**: (iv) は条文の approved に加えて、「必須集計の全件が変換可能な部分集合に収まるかの判定結果」が確定した時点。否定の結果なら 3 択のいずれかを選び、その正本改訂が approved になってはじめて充足(`:712-719`)
- **現行の部分集合**(TSK-538・#131 で着地 — `frontend/scripts/domain-sql/generate.mjs:7-51`): 式の種類 = 識別子・プロパティ参照・BigInt/文字列/真偽リテラル・括弧・単項・二項・条件式 / 演算子 = `+` `-` `*`・比較 6 種・`AND` `OR` / 単項 = `!` `-` / **関数 = なし** / **集計 = `count`・`sum` だけ** / コメント「除算と丸めは含めず」
  - TSK-538 の計画は「SQL 生成経路は枠までで、必須集計の変換可否は (iv) の入力として渡す」(`docs/features/adr003-stage2-runtime/plan.md:40`)
  - 【推論】現行の部分集合を「段階 2 が定めた部分集合」とみなしてよいかを宣言した原典は無い。みなした場合、R(除算)・`AVG`/`MAX`・B・Z・T1/T2 などの区分を持つ行は収まらない
