# 調査メモ: U-X1(状況計算核)を宣言モデルで書けるか — ADR-003 見直しトリガー第 1 項への判定材料

## 問い

**送り先は `ADR-003` の見直しトリガー第 1 項**(`../../adr/ADR-003-domain-calc-method.md:461`・逐語):
「**DSL の射程で表せないドメイン計算が現れたとき** — D-1 の正本の射程(状態遷移 + 有限の算術)に収まらない計算が要件に入った場合」。

> **【2026-10-09 是正】** 初稿はここで `TSK-235` の実装ゲートである「トリガー 1」(`../domain-calc-dsl/design.md:1497` —
> 発火条件「履歴スタック・規則配列・語彙 snapshot map・スコアボード全欄・`NumericValue` / `DisplayAtom` の型語彙で表現できない」)を引き、
> 本書を「その裁定を再評価するための反例集」と位置づけていた。**2 つは別条項であり(§5)、本書の送り先は `ADR-003` の見直しトリガー第 1 項である。**

**本調査の問いは 1 つ** — **`U-X1` が主所有する 13 の FR のうち、現行の宣言モデルで書けないものがあるか。**

本書は実装計画の下調べではない。**`ADR-003` 見直しトリガー第 1 項に当たる計算があるかを、判定者が決めるための材料**である(**発火の判定は判定者が行う**)。

## 結論(要約)

1. **候補は 28 件で、4 値に判定した**(§9〜§11): **表現不能 5 件**(C3 出力の導出式・C4 履歴の読み出し・C10 可変長の出力・C12 行リストの出力・C13 閉じない列挙)/
   **未確定 6 件**(C5b・C11・C15・C18・C23・C25)/ **表現可能 10 件** / **要件に不要 7 件**。
   **【2026-10-09 改訂】** 初稿は「反例の候補が 6 件ある」「条件分岐・論理演算・履歴の読み出し・出力値の導出式を書く場所が無いことは実測で確定」と書いていた。
   **条件分岐・論理演算を書く式のノードが無いことは事実だが、分岐の結果は整数の四則と min・max で書ける**(§11-0)ので、この 2 つは表現不能の根拠にならなかった。
   **ただし「表現可能」は状態の層までで、利用者に見せる出力への結び付けは C3 により表現できない。**
   (2026-10-03 の 2 周目 `P1-2` の是正で、初稿の「反例は成立する」「少なくとも 6 件が受け皿を持たない」という断定は既に格下げしていた)
2. **それ以前に、宣言の `rules` / `outputs` から実行コードを生成する経路が存在しない。**
   中間表現に入るのは `displayRules` だけで、3 言語 backend は宣言を読まない固定スタブである
   (2026-10-09 に develop `0bbf3be6` で再測 — `backend/domain/model.json`・`manifest.json` は無く、`backends/python.py` は 48 行のまま)。
3. **これは `TSK-235`(PR #74)の欠陥ではない。** 同タスクの射程は `ADR-003` 段階 1 の②(検査基盤)であり、
   生成は段階 2 に属する。**ただし段階 2 の生成経路を所有するタスクは現時点で存在しない。**
4. **`TSK-235` のトリガー 1 の裁定は合成 DSL fixture に対して行われており、実 FR で検証されていない**(**本書の送り先とは別条項** — §5)。
   裁定自身が限界を記録している(「**置き場がある**」までで「**書き切れる**」ではない)。
5. **この再浮上は予告されていた** — `../domain-calc-dsl/design.md:1863-1881` の PO 裁定(2026-09-18)が
   「**`U-X1`(状況計算核)が結果表示名を実装する時点で必ず再浮上する**」と明記している
   (**ただし同節はトリガー 2 についてのもの** — §6 を参照)。
6. **候補の行き先は `ADR-003` の見直しトリガー第 1 項**(「DSL の射程で表せないドメイン計算が現れたとき」)。
   **`TSK-235` のトリガー 1 は無関係であり、同 PR を停止させる話ではない**(§5 の再是正)。

#### 11-0. 判定の前提として新たに分かったこと — **分岐の「結果」は、射程の語だけで書ける**

**本書 §3 の反例 1・2(条件分岐・論理演算が書けない)は、そのままでは「表現不能」の根拠にならない。**
整数の値域が閉じていれば、**四則と min・max だけで 0/1 の指示関数を作れる**からである:

| 作るもの | 式(すべて `ADR-003` D-1 の射程の語) |
| --- | --- |
| `[x ≥ k]` | `max(0, min(1, x − k + 1))` |
| `[x = k]` | `1 − min(1, max(x − k, k − x))` |
| 否定・論理積・論理和 | `1 − a` / `a·b` / `a + b − a·b` |
| 「a なら x、でなければ y」 | `a·x + (1 − a)·y` |

**したがって、整数で表した有限の状態とイベントの上の関数は、イベントごとに遷移 1 本(`guardRefs` は空)で書ける。**
`pregen_checks` が拒否するのは「同じイベントに遷移が 2 本」であって、分岐の結果を算術で表すことは拒否しない(陽性対照で確認 — 11-2)。

**この書き方の代償**(判定者への材料。**表現力の可否とは別の論点**):
- **列挙型と真偽値は算術に入れられない**(比較式の結果を整数の状態へ代入すると生成前検査が拒否する — 陽性対照)。**状態とイベントをすべて整数で符号化する必要がある**
- **式が大きくなる**。例: 第 3 アウトの攻守交代(C1)だけで 3 フィールド・十数ノード(`evidence/expressible_models.out.md` の導出規則)。付録E の全行に広げたときの規模は測っていない
- `ADR-003` D-1 は「**条件分岐 … は引き続き書けない**」(`A:101`)と書く。**本書の書き方は射程の語だけを使うので条文には反しないが、条文の意図(分岐を書かせない)と緊張する。** これを許すかは判定者の判断事項である
