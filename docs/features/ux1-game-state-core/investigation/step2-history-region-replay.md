### C4(undo)
- FR-006 補足(要件:245)の逐語:「対象は常に**直前の取消可能な操作1件**。**取消可能な操作は『確定プレイ』と、FR-040 を採用した場合の『状態補正』**(**未採用なら確定プレイのみ**)とし、**undo 自身は取消可能な操作としない**(undo を undo しない)。**undo を適用した後は、取り消された操作の1つ前の取消可能な操作が次の対象になる**(例: 状態補正 → プレイ → undo は当該プレイを取り消し、続く undo は状態補正を取り消す)。それ以前の誤りは FR-007」
- 履歴スタックに差分を持たせる決定(ADR:271)の逐語:
  - 「履歴文脈は『取消可能な操作のスタック(新しい順)』であり、各要素は『種別』と『その操作が状態へ与えた差分』の両方を持つ(種別だけでは連続 undo を実行できない…)」
  - 「実行時のスタックの長さに上限は置かない」
  - 「undo を適用した後の履歴文脈は先頭 1 件を pop したスタックになる」
  - 「`expected` には『遷移後の履歴文脈(スタック)』と『操作結果の区分』を必ず含める」
- 比較面は ADR:324(「…および遷移後の履歴文脈(取消可能な操作のスタック — 種別と差分)、ならびに操作結果」)。schema 側の受け皿は `model.schema.json:297-319`(`HistoryStack` = `HistoryEntry` の配列、各要素が `operationKind` と `differences`)。
- ADR:28(13 周目の変更履歴)は「直前の確定プレイ 1 件に限る」「上限+1〔不正〕」と書いていますが、ADR:271 と ADR:36(21 周目)で置き換えられています。引用しないでください。
- `history-depth.json` が定めていること:
  - 典拠(:4-11)。`historyCases` の典拠を「ADR-003 D-11 ② 入力範囲表 状況判定行」としているが、深さ 0/1/2/`D` と構成 4 分類の逐語は D-11(ADR:203)ではなく D-6(ADR:271)にある。
  - 検査上の上限 `D` の導出(:13-100)。必須シナリオは 1 件(確定プレイ 2 件 + undo 2 件、長さ 4、`requiresFr040: false` — :14-26)。スタック構成は 4 件(:27-58)。式は 2 つの max の max(:59-73)。当方の算出では `D` = max(4, 2) = 4。限界 3 件(:74-96)では、どちらの集合も全件であることは示していないと明記している。
  - case の集合(:101-144)。深さ 0/1/2/`D`、構成 4 分類、シナリオ長 1/2/`D`/`D`+1。
  - `D`+1 の扱い(:145-153)。保証は `execute` / `not-rejected` / `not-truncated` で、出力の一致は求めない。
  - 主要フラグの値域(:163-266)。走者は boolean 3 本(:239-258)。表示 primitive のパラメータ(:267-371)も定める。
