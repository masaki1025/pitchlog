## 2. 計算の形の分類(最重要)

分類記号:
- T = 表で書ける(状態×イベント→次状態 / 閾値 / 四則 / 丸め)
- N = 条件の入れ子
- H = 履歴を遡る
- S = 集合・配列
- D = 外部データ(DB・シード・スナップショット)

DSL 欄の記号:
- ○ = 現スキーマで書ける見込み
- △ = 書けるが分解が要る
- × = 受け皿が見当たらない
- — = NFR-018 の対象外

DSL 欄は `model.schema.json` の事実からの推論です。スキーマの事実は次の 4 点です。

- フィールド型に、レコードの配列・選手 ID・文字列は無い(`:176-197`)
- reducer の初期値は数値 1 個(`:505-506`)。スタックを積む・取り出す式も無い

### FR-014 について(DSL か別物か)

結論: カードが U-X1 の持ち物としている「規則を読む関数・大会へ規則を結ぶ関数」は、要件上 NFR-018 の対象計算ではありません。DSL では書かない別物と読めます(**要件に記載なし**)。

- NFR-018 の対象列挙は「状況判定・座標変換・捕球選手推定・成績集計の前処理・終了判定」だけです(`:892`)。
