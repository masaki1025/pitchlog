### 3. 契約形式の追加は DSL の表現力の判定に効くか

**入力側は DSL と独立ではなくなった(新しい事実)**
- 新 `:208`: 「宣言モデル schema は descriptor に拘束される**派生物**とする。schema は descriptor の `descriptorId` / `version` / `digest` を参照し、軸の exact-set または値域が一致しない場合は manifest へ登録できない」
- 新 `:209`(射影規則): 整数範囲は `minimum`/`maximum` へ、有限な列挙は `enum` へ射影する。`nonCoverageFields[]` も schema へ必ず射影する。
- 新 `:211`: descriptor は「走者別・対象別・タグ付きの入力を表現できる能力」を宣言する。payload 内部の制約と軸間の組合せ規則は段階 2 に委任する(`:213` に委任 ID 8 件の exact-set)。
- 「宣言モデル schema」が `backend/domain/model.schema.json` を指すかは、ADR に書かれていません(不明)。

**出力側に DSL の表現要素は追加されていない**
- 追加されたのは契約の規範行(`matrixRows[]`/`operationRows[]`/`undoRows[]`/`decisionRows[]` — 新 `:283-295`)と、D-8 の閉じた列の型(新 `:368-399`)です。
- 「規範行が正であり、`cases[]` は規範行から展開される派生物」(新 `:295`)です。
- `stateEffect` は要件書付録E-1 の `StateEffect` を参照し、D-8 では再定義しません(新 `:368`)。

**該当 5 件それぞれへの影響**

- **C3(出力の導出式)**: DSL 側に出力導出の仕組みは追加されていません(D-1 は不変)。新しい事実は次の 2 つです。
  - 新 `:219`: 「成績計上フラグは入力軸ではなく期待出力・比較面であり、閉じた 23 件をすべて比較する」
  - 新 `:211`: 23 フラグの「閉じた外延・exact型、および他の列と`precondition`から導出して独立した任意値にしない原則」は段階 1 で確定。フラグごとの導出表は段階 2(`stage2-constraint:stat-flag-derivation-rules` — `:213`)。
  - つまり出力の形(23 件・導出値であること)は具体化しました。ただし導出を書く場所は契約側の導出表(段階 2)と書かれていて、DSL の構成要素ではありません。
- **C4(履歴の読み出し)**: 根拠に使った文言は変化なしです。
