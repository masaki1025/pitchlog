## 4. 実装方針

### (1) 重さ分類の根拠 — 通常

**コア領域ではない。**設計書 6.3 の 5 領域(同期プロトコル / 状況計算 / 記録権 / テナント分離 / データ移行)に
ハーネス設計書の Phase 表は含まれず、`core-areas.json` の `paths` にも `dev-harness-design` は入っていない。

**計画レビューは `review normal`。敵対レビューは 7.3 の確定ゲートで必ず入る。**
計画段階でも敵対を回すと射程が広がる(このセッションで TSK-235 が 12 → 22 ステップ、
TSK-278 が 5pt → 確定ゲート 2 本へ膨らんだ)。

### (2) 歯止め

| # | 歯止め | 検査 |
| --- | --- | --- |
| 1 | **Phase を追加しない** | **Phase 表の行数が不変** |
| 2 | **既存の Phase 0〜5 の記述を書き換えない** | **`git show origin/develop:` と突合してバイト一致** |
| 3 | **「Phase 4 の分割」節に一切触れない** | 同上 |
| 4 | **追加は 13 章の 1 節(5 項目以内)に限る** | 差分行数 |
| 5 | **群・順序・段階計画・進捗の機械判定を定めない** | 追加節に「群」「段階」「順序を定める」を含まない |
| 6 | **新しい規則を作らず、既存決定を参照する形で書く** | 各項に典拠がある |
| 7 | **10.1 の「実装期」を定義しない** | 10.1 に差分なし |

### (3) ◎ 縮小順序を着手前に決めておく(`7.3-6` の裁定が発火したとき何を落とすか)

**H-68 の実測では裁定が 5 周分遅れた。**順序を先に決めておけば即時に実行できる。

**着手前に決めた順序(旧案)**:

| 段 | 落とすもの |
| --- | --- |
| 第 1 段 | 「本章では順序・群・段階を定めない」の項 |
| 第 2 段 | 「適合判定との関係」の項 |
| 第 3 段 | 「開始条件」の項を残し、他をすべて落とす |

**実際に落としたもの(2026-09-02 の PO 裁定 — 旧案と逆)**:

| 落としたもの | 理由 |
| --- | --- |
| **「開始条件」の項** | **旧案は「最後まで残す」としていたが、最初に落とした。** 3 条件を書いても `/task-start`・`/implement` に照合点がなく**実効を持たず**、4-6 マージ〜マージ後検査の区間と進行中実装に穴が残った(確定ゲート 2 周目 P1-1・P1-2)。**着手可否は 6.1 の計画書ゲートへ戻した** |
| **「適用する規約」の項**(1 周目に追加した項) | `AGENTS.md` に 8.6 が rules へ持たせる内容が実在せず、非阻害化の根拠が成立しなかった(同 P1-3)。**TSK-303 へ全面送り** |
| 残した 3 項 | 「Phase の対象外 + 6.1 に従う」「適合判定との関係(ADR-003 の導入順序)」「順序・群・段階を定めない」 |

**旧案が外れた理由**: 縮小順序を「文言の重要度」で並べたが、実際の判断軸は**「機構の裏付けがあるか」**だった。
**照合点のない条件が最初に落ちる。** この観測を台帳へ渡す。
