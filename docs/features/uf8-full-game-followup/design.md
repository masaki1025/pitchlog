U-F8の停止UIは表示と利用者操作の受渡しを所有する。停止判定、通信結果の分類、再送可否、耐久索引集計、旧要求遮断・取消の証明は506/U-S1が所有する。commit不明・旧要求禁止未確認・取消証拠なしでは内容訂正を有効にしない。後続記録を消さず、自動送信を開始しない。同内容再開は照会結果確認後の明示操作とし、試合状態の再開（FR-007/008）とは分離する。

## 2. 接続・編集順

1. U-F8が封鎖付きの画面/DOM契約試験と最小routeを`GameScreen*`/`router*`で用意し、P-7の境界確認へ提供する。仮Portを製品へ登録しない。Playwrightの設定・シナリオも登録済み`GameScreen*`へ置き、package/既存CIで再実行可能にする。CI編集は他担当と開始前に順番を照合する。
2. 506がHTTP/codec/ACK/限定キューの公開型と提供SHA・編集完了を通知する。その後だけU-F8が共有`client*`の呼出側を追随する。506側の未提供実装を先取りしない。
3. U-R1のD4/V12/RG1、U-S1の単一適用核/耐久provider、544/545の対象別条件・型・提供SHAを照合する。preparingでD4を発行せず、D4を数値比較せず、V12をログに残さない。未知/停止を成功扱いしない。
4. T1実呼出部（外部前提M-T1）は544のPR-1a、T2実呼出部（外部前提M-T2）はT1マージ後に545のPR-1bで実施する。実Port/実HTTP/隔離DBの検査を共同で揃える。T2のP-1〜P-9＋T1マージ条件は保持する。受渡し先の承認済み計画・件名規則と実コミットを対応記録し、U-F8のステップ表にはこれらの外部コミットを数えず、U-F8自身は欠番のない9ステップで実施する。未提供UIは独立提出し、提供待ちを偽の実装で埋めない。

FR-007下流再計算・捕球推定などT1/T2経過措置の対象外は、当該対象の正式開始ゲート成立まで接続しない。これらが間に合わない場合、11/12の全試合記録能力に不足が残る。機能を落としたリハーサルを「任意の1試合を記録できる」と評価しない。

## 3. 最小通しシナリオと不足の判定

正式なページ付き一覧/開始経路→初球→単打（打球座標/捕球者）→四球押出し→非投球の盗塁/牽制/ボーク→複数走者イベント（停止/進塁/アウト）→第三アウトと生還候補の観測→回切替→投手/代打/代走/守備交代→過去交代の人/回/時点訂正と下流帰属→undo→オンライン過去修正（更新/挿入/論理削除とプレビュー）→一覧から再開/再読込復元→延長タイブレーク→通常/早期終了→未同期警告→通信復帰/確定→終了後追記再開→再終了。

一本の試合ですべての枝を不自然に起こさず、通常試合を主シナリオとし、別試合の分岐fixtureで早期終了/裏不要X/サヨナラ（本塁打と非本塁打）/タイブレークを補う。#153の候補5セルは`X / blank / 3 / blank / 0`。E02は宣言後prompt=false、E09はロック中undo可/交代不可・undo後再評価、E10の再開は毎球強制dialog/再ロックにしない。545の正式投影と生成formatterから表示し、画面で判定しない。

実通しでは正常に加え、内容拒否、HTTP/DB通信失敗、ACK消失/遅延、永続化拒否、アプリ/端末再起動、同時2タブ、停止後の再読込・再開照会・訂正不可を確認する。未同期記録と後続記録が残り、二重受理・黙った完了・勝手な再送がないことをDB再読込と端末キューの両面で確認する。E5は既存3シナリオをそのまま通す。

入力/閲覧2端末を使い、最終反映時刻・入力端末オフライン・未同期/暫定の表示を確認する。NFR-020前提1/5/6を単独と2個以上の複合で不成立にして全不足列挙・開始拒否・キュー保持・閲覧継続を確認し、persistだけの拒否では警告して記録継続できることを区別する。FR-020〜023はH/E/K/B、投手/打者の当日/シーズン成績、7列打席履歴、球種割合/球数を提供値・未取得・断中暫定の各状態で突合する。

## 4. 人間へ提示する判断

推奨は本計画を承認し、停止UIを先行、表示/フォームを封鎖付きで独立提出し、正式提供後にT1/T2同一変更と通し検証へ進むこと。代案は停止UIだけを先に承認し、残る表示/入力と接続計画を保留すること。いずれも#160の第1期逐行確認と統合判断は別に行える。

この承認だけで未分類計算を分類済みにせず、正式資産の受理・耐久provider担当の指名・NFR-006の新意味契約・11/12段階提供の正本確定・追加レビュー枠の許可を代行しない。必要な決定は不足表の具体的な所有側へ送り、独立作業は続ける。


## 5. CI差分に伴う凍結基準の限定更新候補

`ci.yml`は`contracts/tenant_boundary/base-allowlist.json`と`census-baseline.json`の外部入力、および`tests/fixtures/frozen-archive-cases/manifest.json`のcorpus入力である。ステップ7はCIだけ書き換えて終わらせず、同じ差分の基準・前後識別値/digest・追記履歴・history-snapshots・比較corpus再固定の候補を3節の宣言範囲で用意する。検査対象や合否規則・過去履歴を緩めない。候補の正確な波及は受理時基線から機械導出し、未宣言資産への波及があれば具体差分を添えて計画追補へ戻す。

U-F8が候補を作成し、現所有者と編集順を調整して、PO/正規受理者が7.7の正式受理を行う。計画承認は資産受理を兼ねない。受理前に`approved_by/on`等を代記しない。実施された人間の記録を受け取り、凍結/受理遷移・越境・比較corpusの既存検査と必須frontend CIが緑になるまでステップ7は完了としない。待機中にも1〜6は封鎖付きで提出できる。

FR-020〜023は各チームの開始済み全イニング欄と合計/H/E/K/B、現在/次打者と代打記録時点の切替を比較する。断中に新たなプレイを確定した後のスコアボード/当日成績/球種割合/球数は、単一のクライアント計算核が出す最新投影で更新されることを実測する。古い表示へ暫定ラベルだけを付ける挙動は不合格とする。シーズン成績はサーバー供給の鮮度を示し、画面で全件集計しない。
