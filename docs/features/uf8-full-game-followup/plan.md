## 2. スコープ

### やること

- 既存`GameScreen*`の中で停止・端末未確認件数・未取得・再開照会中・訂正不可を表示し、**同内容の明示再開／内容訂正／試合再開を別操作として扱う**。停止原因や他tenantの原本の存在は表示しない。
- 打球・走者観測、undo、過去修正、交代、タイブレーク、回の切替、終了宣言、終了後追記再開、同端末の復元の画面を、担当の公開契約を受ける形で段階追加する。計算や必須観測対象の判定を画面で新作しない。
- 最初は登録済み`GameScreen*`に収まる表示と入力フォームを作り、接続待ちの操作は明示して封鎖する。`GameScreenEntry*`に最小のページ付き一覧/開始/再開入口を置き、既存`router*`へ`/games`と`/games/:gameId/record`を追加する。試合ID・開始情報・スタメン・再開状態はU-G1/U-G2の正式APIから受ける。独立5画面への分割や共通component再編は行わない。
- 実接続の呼出部は544/T1と545/T2のそれぞれの同一変更に届ける。担当の公開SHA・型を照合してから、506の既存通信／キューを使い、実画面・実HTTP・専用隔離DBを通す。第1期の封鎖解除は接続と検査が整う変更でだけ行う。
- [design.md](design.md)の不足表を受渡し台帳とし、TSK-523全体DoD（単一計算・一致性・E5・鮮度・座標・全5コア領域・レビュー）を残す。1試合リハーサル成功をカード全体/MVP完成へ読み替えない。

### やらないこと

- 506のHTTP/wire codec/ACK変換/限定キュー、U-S1の適用核/耐久provider、U-R1の記録権、544/545の計算や生成formatterを再実装しない。実Port・計算核を仮実装で代用しない。
- FR-003走者入力対象判定・FR-011の9ポジション検証など未分類計算を実装しない。分類は要件所有側の改訂ゲートへ送り、成立前の該当確定は封鎖する。
- FR-040状態補正は11/12段階提供で延期する既存PO裁定を維持し、新たに採用しない。診断不能なずれは記録停止を表示する。正式な段階提供表記の正本改訂は別ゲートへ送る。
- 正式資産受理、独立oracleの作成者兼任、共有DB/ロール変更、本人逐行確認・公開・マージは行わない。

## 4. 実装方針

**重さ分類はコア領域**。同期・状況計算・記録権・テナント分離・移行の5領域に既存`GameScreen*`が登録済みである。敵対レビューと人間逐行確認をPRごとに行う。既存ハーネスを保ち、検査例外を足さない。

表示・フォームの隔離検査と実製品接続を分ける。[design.md](design.md)の接続条件は、既存担当の着手条件を変更するものではない。544/545のP-1〜P-9、T2のT1マージ待ちを維持し、実装後に得る証跡を先方の着手前条件へ追加しない。先にUI契約試験を提供し、製品呼出部を受け渡す順で循環待ちを避ける。
