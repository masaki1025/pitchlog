# 詳細設計: 確定ゲート収束規則(7.3 v1.12)の詳細規則

[plan.md](plan.md) 4 節の裁定表が参照する詳細規則。7.3 改訂条文(ステップ 1)と finalize-doc スキル手順(ステップ 3)は起草時にこの表・算式・様式と 1 対 1 で対応させる(合格条件)。

**本書の役割と正の所在(H-44 の二重管理を避ける)**: 本書は起草の入力であり、**確定ゲート開始時点で正は移る — D-1〜D-4 と D-5a は設計書 7.3 条文へ、D-6 の様式は設計書 6.3 へ、確認手続は github-setup.md 2 章へ**。**D-5b(シャドー観測)は本タスク限りの運用で正本・スキルへ移さない**(置き場は plan 4 節と worklog)。**D-7 は本タスクの作業手続であり正本へ移さない** — guard_paths の正は `.claude/core-areas.json`(機械可読)にあり、追加の経緯は設計書 v1.12 の変更履歴行と本タスクの PR に記録する。以後の本書は経緯資料(照合先にしない)。ゲート中・ゲート後のレビュー・突合の照合先は常に正本の条文とする。

## D-1. 終端遷移表(A1)

**用語**: 「周」= レビュー実行 1 回。**カウンタ(`確定ゲート周回`)と `反映<r>周目` コミットは「採用反映を伴う周」のみに発生**する(現行 6.1・設計書:295 の規約を変更しない — レビュー実行回数 ≧ 反映周回数)。

| 周の結果 | 処理 | カウンタ / コミット | 次の状態 |
| --- | --- | --- | --- |
| P0/P1 あり(通常周)・1 件以上採用 | 全件を採否裁定し、採用分を反映(不採用分は理由を採否記録に明示) | 周回 +1・`反映<r>周目` コミット 1 件 | 差分再レビューの次周へ |
| P0/P1 あり(通常周)・**全件不採用** | 不採用理由を採否記録に明示(反映なし) | カウントしない(採否記録の追記コミットは反映周コミットにしない) | 残存 P2 の扱いへ(P2 もなければ最終全文確認周へ)。**全件不採用が 2 周続いた場合は PO へ判断を上げる**(黙殺の疑いを人間が裁定) |
| P0/P1 ゼロ・P2 ゼロ(通常周) | 反映なし | カウントしない | **最終全文確認周**へ |
| P0/P1 ゼロ・P2 あり(通常周) | 残存 P2 を一括裁定: **採用分は一括反映・不採用分は理由を採否記録に明示**(7.6-1 充足。反映しない場合もコミットは採否記録の追記で発生し得る)。**P2 (B) は送り先(実装タスク or 申し送り)を採否記録に記録した時点で当該ゲートでは解決扱い**(反映コミット不要 — 不採用理由明示の一種) | 採用反映がある場合のみ 周回 +1・`反映<r>周目` コミット 1 件 | **最終全文確認周**へ |
| 最終全文確認周: 指摘ゼロ | — | カウントしない(現行の収束確認周) | **収束**(人間承認へ) |
| 最終全文確認周: P0/P1 あり | **通常周の該当行と同じ扱い**(採否裁定し、1 件以上採用なら反映・全件不採用なら不採用理由の明示のみ) | 採用反映がある場合のみ 周回 +1・反映コミット(全件不採用はカウントしない) | 採用ありなら差分再レビューへ戻る。全件不採用なら通常周の全件不採用行に従う(残存 P2 の扱いへ・2 周連続の全件不採用は PO へ) |
| 最終全文確認周: P2 のみ | 一括裁定・採用分を反映し、**再確認周は回さず収束**(P2 = 実装挙動を変えない定義のため。不採用分は理由明示) | 採用反映がある場合のみ 周回 +1・反映コミット | **収束**(人間承認へ) |

- 優先規則: 重大度は D-4 の定義**のみ**で判定する。種別ラベル(内容面 / artifact)や (A)/(B) 分類で P0/P1 を降格しない。「ゲート進行自体が生む記録・参照の追記要求」は定義上 P2(H-42 ①の条文化)。

## D-2. エスカレーション算式(A2)

- **帰属フラグ**: レビュアは各指摘に「前周修正起因 / 非起因」を必須で付ける(D-3 依頼文規約)。論点の単位はレビュアの指摘番号(分割・統合が起きた場合は当該周の指摘番号で数える)。
- **母集団**: 当該周の P0+P1 件数(P2 と (B) 分類は算入しない)。
- **発火条件**: `起因件数 × 2 > 母集団` が **2 周連続**で成立 → PO スコープ裁定へエスカレーション。
- **PO 裁定の 3 選択肢と裁定後の遷移**(いずれも連続カウントを 0 にリセットする — PO が判断した事実で流す):

| PO 裁定 | 文書への編集 | カウンタ / コミット | 裁定後の次周 |
| --- | --- | --- | --- |
| 射程縮小 | 縮小範囲と理由を本文・変更履歴・worklog へ反映 | 指摘反映を伴う周に準じ 周回 +1・`反映<r>周目` コミットに含める | **全文レビュー**(射程が変わったため対象を取り直す) |
| 範囲確定 | 「本書で確定する範囲/実装時に確定する範囲」節を更新 | 同上 | 差分再レビューを続行 |
| 続行の明示指示 | 編集なし(指示を worklog に記録) | カウンタ・コミットなし | 差分再レビューを続行 |
- **判定行欠落の周**: 周として数えず(連続性は中断せず同一周を再依頼)、母集団にも算入しない。
- **6 周警告**: `確定ゲート周回` が 6 に達したら、finalize-doc 手順が周回・重大度推移・起因比の一覧を PO へ提示する(判断は求めるが強制打ち切りはしない)。

## D-3. 依頼文規約(A3)

- 依頼文の**冒頭に命令文を必須で置く**: 「実際にレビューを実施し、次周の依頼文を作らず、判定を返すこと」(H-75② で実測有効だった文言 — メタ解釈の防止。差分指定と判定行必須は検出側)。
- 2 周目以降の依頼は**反映差分と影響節の指定のみ**とし、前周指摘の全文並記をしない(H-75② メタ解釈対策)。全文レビューは**初周・最終全文確認周・および D-2 の射程縮小直後の周**(射程が変わったため対象を取り直す — この周を新たな起点とし、以後は再び差分)の 3 種のみ。
- レビュア応答の必須様式(欠落時は周として数えず再依頼):
  - 各指摘: `P0|P1|P2` + `起因|非起因`(前周修正への帰属)+ `(A)|(B)`((A) 方式が分岐する / (B) 実装時に決めれば足りる)
  - **(B) を付けられるのは P2 のみ**。P0/P1 は必ず (A) として扱う。(B) には**送り先**(実装タスク or 申し送り先)を記録する
  - 最終行に**判定行**: `可決|否決 + P0/P1/P2 件数`
- 重大度定義(D-4)を依頼文プロンプトへ毎回組み込む。

## D-4. 文書ゲート限定の重大度定義(A5)

| 重大度 | 定義 |
| --- | --- |
| P0 | このまま実装すると挙動・データ・安全が壊れる |
| P1 | 実装が迷う・規約と矛盾する・**「文言は直したが実効がない」型(H-21)を含む** |
| P2 | 表現・語彙・記録(実装の挙動を変えない)。ゲート進行自体が生む記録・参照の追記要求を含む(H-42 ①) |

- 適用範囲は **7.3 の文書確定ゲートのみ**。コードレビューの既定(AGENTS.md — 重複実装 = P0 等)には適用しない。

## D-5. 適用版の原則(恒久)とシャドー観測(本タスク限り)

- **D-5a 適用版の原則(恒久 — 7.3 条文へ移す)**: 確定ゲートには**その時点で approved の 7.3 の規則**を適用する。**7.3 自身の改訂ゲートでは、当該改訂の開始時点で approved の版の規則で運用する**(ゲート対象の未確定条文を先取り適用しない — 循環の排除。恒久除外は作らない: v1.12 approved 以後は v1.13 以降の 7.3 改訂ゲートにもこの原則がそのまま効く)。finalize-doc スキルはこの原則を参照する。
- **D-5b シャドー観測(本タスク限り — 正本・スキルへ移さない。置き場は plan 4 節と worklog)**: 本タスクの v1.12 ゲートは D-5a により旧規定で運用されるが、新規則の初期データ取得のため各周で新規則の判定を併記記録する。シャドー分類の重大度は D-4 の定義を用いる(実運用の分類と独立に付ける)。**観測行の固定様式**(worklog へ毎周 1 行・終端判断には使用しない):
  `シャドー: 周<N> 実判定=<継続|収束> シャドー判定=<収束|継続|エスカレーション> 根拠=<P0 x/P1 y/P2 z・起因過半 有|無>`

## D-6. 逐行確認の実施記録様式(B2)

- PR 本文の必須チェック行(canonical・不変)の**直後**に記録行を置く:
  `- 実施記録: 対象=<ファイル群> 範囲=<行数・節など> 方法=<目視|突合シート|その他>`
- 人間マージ手続(github-setup.md 2 章)に「チェックの確認に加え、**実施記録行の存在**と**最新 HEAD への追随**(記録後に guard 対象へ追コミットがあれば記録の更新)を確認する」を追記する。
- 記録行は運用規律であり機械検証しない(残余リスクと機構化の再評価条件は plan 4 節)。
