# 詳細設計: 数値表示 primitive — D-1 改訂の骨子(ステップ 2)

[plan.md](plan.md) 4 節から参照される改訂案の骨子。典拠と決定の空白の全数は [research.md](research.md) が正(複製しない)。
**ここに書くのは ADR へ規定する内容の設計判断であり、規範の正は改訂後の ADR-003 本文**(本ファイルは feature 文書 — 7.6-4)。

## 1. primitive 候補の型(上限 4 種 — 最終決定はステップ 3 の binding 確定後)

すべて **`NumericValue → DisplayAtom`** の写像として宣言モデルに書く(§2)。**パラメータは有限・型付き・宣言時に固定**で、
生成前検査(D-1 の生成前検査行)が**指定漏れを fail** させる。任意の数値整形ロジック・条件分岐・部分文字列操作は引き続き禁止。

| # | primitive | パラメータ(すべて必須) | 賄う要件 | 備考 |
| --- | --- | --- | --- | --- |
| P1 | **fixed-decimal(固定小数)** | `scale`(0..3 — **0 で整数表示を含む**)/ `rounding`(D-6 の数値の扱いに列挙された丸め 4 種から選択)/ `leadingZero`(bool — `.333` か `0.333` か)/ `negativeSign`(負値の文字 — binding の符号列から) | 打率・出塁率・長打率・被打率・WHIP・FIP・平均球速・得失点差(整数 + 負号) | 独立の「整数」「符号付き整数」primitive は作らない(scale=0 と negativeSign に統一 — 計画 §4-(4)(5)) |
| P2 | **percentage(百分率)** | `scale`(**0..2**)/ `rounding` / `leadingZero`(scale ≥ 1 の 1% 未満で `0.5%` / `.5%` を一意化)/ `symbol`(`%` の文字種 — binding から) | 球種割合「40%(12球)」の率側 | ×100 と `%` 付与まで。**母数併記は本 primitive の仕事ではない**(§7-e)。値域・先頭 0 はゲート 13〜14 周目で確定 |
| P3 | **mixed-fraction(混合分数)** | `denominator`(投球回 = 3)/ `integerSuffix`(「回」)/ `zeroRemainderForm`(剰余 0 の表記 — **binding で確定**: 「5回」か「5回0/3」)/ `fractionStyle`(`n/d` — ASCII スラッシュ。`⅔` 等の合字は使わない) | 投球回「5回2/3」(A-2 投球回行) | 旧の `⅓`・`1.1`・`1.333` の 3 表現は移植しない(新書式の正は binding) |
| P4 | **null-substitute(null 代替)** | `substitute`(既定 `−`) | 0 除算「−」(A-1 の 0 除算規則) | **既存の破れの是正**(research §0-5 — 現行 ADR は 2 種のどちらにも収まらない参照を既に持つ)。**binding 確定後の最終判定で独立 primitive として確定(4 種 — §8)**。既存規則①の拡張は不採用 |

**作らないもの**(計画 2 節と一致): interval-label(**球速ビンはビン下端の構造化整数 + テンプレート `{下端}km/h`**〔enum 写像は不採用 — ゲート確定〕・「10回以降」は有限 bucket enum + 写像①)/ 正値 `+` / 色・装飾属性 / ロケール可変。

## 2. `NumericValue → DisplayAtom` の型付き変換

- **`NumericValue`** = 対象計算が返す構造化数値の総称(整数・decimal・有理数〔分子/分母〕・nullable)。**表示前の値はすべてこの型空間に閉じる**
- **`DisplayAtom`** = 表示文字列の最小単位となる**不透明型**。**template(既存②)が受け取れるのは `DisplayAtom` と enum 写像(既存①)の結果のみ**
- **変換は必ず §1 の primitive を経由する**。`NumericValue` を template へ直接渡す宣言は**生成前検査で fail**
- **暗黙の言語既定文字列化(Python `str()` / TS `String()` / SQL `CAST(... AS TEXT)` 等)を生成物に出さない** — 生成器は primitive 宣言から各言語の整形関数を生成し、それ以外の文字列化経路を作らない(NFR-018 の暗黙重複実装の防止 — 計画 §4-(4))

## 3. `(β)①〜⑤` の複合 target — 証跡スキーマ(D-11 へ規定)

**3 段 composite の対象は表示 primitive を持つ `(β)①〜⑤`**。**`(β)⑦` は 2 段 composite(sql → 写像①適用の受け口 — 確定ゲート中の PO 裁定 2026-09-03 で追加)**・`(β)⑥⑧` は現行の単一 target のまま(composite は段数可変の一般定義 — 規範の正は改訂後の ADR D-11)。

```
directTargets[] の要素(kind で判別):
  { "directTargetId": "...",            // 従来どおり証跡直積の軸(1 複合 target = 1 要素 — 要素を 3 つに分けない)
    "kind": "composite",                 // 既存の単一 target は "single"(現行スキーマのまま)
    "components": [                      // 順序固定・各構成生成物に hash
      { "role": "sql",            "generated": "...", "hash": "..." },
      { "role": "typed-receiver", "generated": "...", "hash": "..." },
      { "role": "formatter",      "generated": "...", "hash": "..." }
    ],
    "invocation": { ... },               // 固定 fixture・クエリの与え方・受け口への取り出し方・formatter の呼び出し(現行の SQL 式 target の規定を 3 段へ拡張)
    "comparison": { ... }                // 最終表示文字列の完全一致(§7-d)
  }
```

- **5 判定の証跡(①実行・②実行・①=expected・②=expected・①=②)は従来どおり `directTargetId` 単位** — 複合化で直積は増えない
- **比較の相手**: 参照実装(Python reference)も**同一宣言モデルから formatter まで生成**し、**最終表示文字列同士**を比較する(途中段の構造化数値の比較は現行の property 層の検査として残る — 置換ではなく延長)
- **D-7 への波及**: `(β)①〜⑤` の property 比較の終端を「構造化数値」から「最終表示文字列」へ延長する(D-7 の該当行の改訂 — ステップ 6)

## 4. 表示 primitive の同値分割の必須軸(D-11 へ規定)

ADR で規定するのは**軸**まで(具体ケース値・証跡形式は TSK-235 — 計画 §4-(8)):

**丸め境界の直前・一致・直後** / **scale の上下限** / **正・負・0** / **分母 0**(null-substitute 経路)/
**剰余 0・1・分母−1**(mixed-fraction)/ **nullable** / **オーバーフロー**(整数範囲の上限側)

**軸の組合せ要件(ゲート 18 周目)**: 丸め境界 × 符号は直積で必須 — **負値の丸め境界一致(負のちょうど中間値)を必ず含める**

## 5. D-2(QuickJS / 常駐 Node)を採らない 3 理由(ADR「採らなかった案」節へ)

1. **対価が過大** — ADR 自身が挙げる「バックエンドに JS ランタイム・境界の直列化・timeout・クラッシュ処理」を、数値書式のためだけに払わない
2. **D-2 は「射程で表せない計算」全般への代替**であり表示規則固有の対処ではない — 状態遷移・有限の算術という中核の射程は現行のまま足りている
3. **D-2 へ切り替えても書式の正は生まれない** — 要件書に書式が無い問題は方式に依存せず残る(だから要件書 binding を対で改訂する)

## 6. 16 周目への回答(「表示の都合が正本へ流れ込む」への先回り — research §2-1)

- 本改訂は **17 周目の決定(表示規則を正本へ取り込み、利用者が見る値を単一実装の中に置く)を完成させる**ものであり、16 周目の全面除外へ戻る話ではない
- 追加する primitive は **有限・型付き・宣言時固定・生成時に機械検査可能** — D-1 の射程制限の論拠(「射程を制約することで生成器は小さく保て、生成物の検査を生成時に機械化できる」)と**同じ形**を保つ
- **書式の実引数の正は要件書の binding**(本タスクで対改訂)であり、「表示の都合」ではなく**要件**として正本に入る
- 表示の**都合**に当たるもの(色・装飾・ロケール・任意整形・UI 限定の読み替え)は**引き続き禁止のまま**(「カルテ帳票の配色テーマ」「多言語・タイムゾーン対応」の Won't と整合 — 行移動のため行番号では参照しない)

## 8. witness(ステップ 3 で検証済み — binding 確定値・判定者: 山田正輝)

binding(2026-09-03 PO 裁定: 率 = 3 桁先頭 0 なし四捨五入 / 投球回 = 剰余 0 省略・`n/3` / WHIP・FIP 2 桁 / 平均球速 1 桁 / 百分率整数 / `%()` 半角 / 負号半角 / null 代替 = MINUS SIGN(U+2212)「−」/ 期間ラベル = JST 年度導出):

- A-2 投球回: アウト数 17 → `NumericValue(整数部 5・剰余 2/3)` → **P3**(denominator=3, integerSuffix=「回」, zeroRemainderForm=省略, fractionStyle=`n/3`) → **「5回2/3」**。アウト数 15 → 整数部 5・剰余 0 → **「5回」**(省略形)
- FR-023 球種割合: 率 `12/30` → **P2**(scale=0, rounding=四捨五入, leadingZero=true〔A-1 の既定 — scale=0 では出力に現れないが必須パラメータのため宣言する〕, symbol=半角`%`) → 「40%」、母数 `12` → **P1**(scale=0, rounding=四捨五入, leadingZero=true〔A-1 既定〕, negativeSign=半角`-`〔A-1 既定〕) → 「12」、template `{割合}({球数}球)`(括弧半角) → **「40%(12球)」**
- 追試(binding 表の代表値): 打率 `1/3` → P1(scale=3, rounding=四捨五入, leadingZero=false, negativeSign=半角`-`〔A-1 既定〕) → 「.333」/ 得失点差 `-3` → P1(scale=0, rounding=四捨五入, leadingZero=true〔A-1 既定〕, negativeSign=半角`-`) → 「-3」/ 0 除算 → P4(substitute=「−」) → 「−」

**P4 の最終判定(binding 確定後)**: 独立 primitive として維持する(**4 種で確定**)。既存規則①(enum→表示名写像)の拡張は不採用 — `null` は enum 値ではなく型機能であり、写像テーブルの定義域に混ぜると「安定した enum に限る」という①の制約を壊すため。
