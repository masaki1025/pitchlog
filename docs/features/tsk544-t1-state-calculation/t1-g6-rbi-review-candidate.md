## 7.3 に提出する本文候補と影響

### FR-009 へ追加する候補

> 保存済みの適用規則 snapshot が対象とする各半回の先頭では、走者配置と先頭打者指定をその半回に一度だけ適用できる。既にタイブレークが有効であることだけを理由に、次の対象半回での配置を拒否しない。同じ半回に配置を適用済みなら、別の操作として二度目の配置をしない。開始可能な状態は、当該半回・アウト0・カウント0-0・配置前の空塁とし、途中の状態を開始可能に戻すためのリセットは行わない。開始前に合法な選手交代等がある場合は、その確定後の同一scopeの打順・名簿・規則snapshotで開始操作を評価する。通信断で遅れて届いた開始操作も、同期時の正史上の半回と事前状態に照らして評価し、過去の半回へ遡って配置しない。

この文言は **G6-S04=方針B、G6-S05=方針A** の意味候補。F-1 の規則 snapshot、FR-005 の攻守交代時の count 後処理、FR-006 の確定プレイだけを対象とする undo、FR-007 のオンライン過去訂正と整合させる。適用済み印の**一意キー**は `(試合ID, 半回ID, 正史系譜ID)` とし、開始操作D5と開始前/後の差分は印の属性とする。同じ半回・同じ正史で別D5の印を作れない。正史系譜IDとは、FR-007の訂正・再実行で新たな列を確定したときに変わる識別子の候補であり、**通常の後続プレイで正史revisionが進んでも変えず、当該半回の印を消さない**。半回IDは `(回, 表裏)` の構造化値であり、送信端末の時刻で代替しない。同D5・同指紋の再送は既存結果の再掲であり再配置しない。別D5の同半回開始は状態不変の拒否候補であり、結果分類・D5消費はU-S1受理待ち。訂正・再実行では旧正史系譜の印を新正史に流用せず、対象半回の状態と配置を再計算し、一つの新正史に印を一度だけ作る。FR-006 の undo がタイブレーク操作を直接取り消せると拡張しない。過去訂正で操作を除去・再適用する経路と、遅延して到着する旧D5の遮断条件は U-S1 の責任境界で確定する。

候補状態は `tiebreakActive` を試合全体の有効性として維持し、**別に半回単位の最終適用情報**を持つ。既存のタイブレーク3行（適用 `ST-OPERATION-93799cd3c928a723` / `ST-OPERATION-6e73a96c10ecd75c` と前提拒否 `ST-OPERATION-2133d452dd1be1f3`）の `tiebreakActive=false` 前提だけでは次半回の再配置と同半回の重複を同時に表せないため、D-11 descriptor の状態座標、D-8 `operationRows[]` の前提・効果、case/schema/runner の追加を7.3・正式契約レビュー対象にする。物理保存場所・ACL・D5結果への写像は未受理であり、上記 tuple を即座にDB列として確定しない。

### 付録E-1・A-3へ追加する候補

> RBI-01〜09 の判定に必要な公式記録上の走者別因果と送球段階は、原則として既存 `event.perPitch.officialScoringPayload` の閉じた `error-recorded` variant に記録する。公式失策の件数・帰属野手と参照整合し、RBI 分岐のID自体を記録員の入力値としない。走者別の因果、フォース併殺の第1アウト後の完成送球と捕球失策の関係、ミスプレイ後の走行継続／停止再発進が必要な分岐では、それぞれ観測値を必須とする。値の欠落を `false`、失策なし、依存なしなどへ補完しない。既存 `rbi.runnerContinuityByRunner`・`rbi.doublePlayRelayError`・`rbi.wouldScoreWithoutErrorByRunner` との関係は、重複した正を作らない射影として定める。

現 descriptor の `officialScoringPayload` は `no-error` / `error-recorded`、次元は `error-count` / `fielder-reference` だけであり、**走者別因果と送球段階の値域は宣言されていない**。したがって現行型だけで損失なく表せるとの証明は不可。第一候補は同軸を維持し、`error-recorded` の内部形を `errors[]:{errorRef,fielderRef,phase,completionCatchError}` と `scorerCausalityByRunner[]:{scorerRef,errorRefs,effect,continuity}` で閉じる。`completionCatchError` は第1フォースアウト後の完成送球を受ける野手の捕球失策だけを指す観測で、同じ送球段階の別失策とは区別する。`continuity` は走者別の `continued` / `stopped-and-restarted` 観測とし、失策の有無によらずRBI-03/04に必要なら必須とする。位置・時刻から補わない。現行の物理型にこれらのfieldがあるとは主張しない。**失策件数は `errors[]` の長さ、帰属野手は各 `fielderRef` から導出し、別の書込値を持たない**。`no-error` には失策参照を置かず、失策のないフォース併殺（RBI-01）とミスプレイ継続（RBI-03/04）は既存 `rbi.doublePlayRelayError`・`rbi.runnerContinuityByRunner` の観測を使う。公式失策がある場合の `rbi.doublePlayRelayError`、`rbi.runnerContinuityByRunner`、`rbi.wouldScoreWithoutErrorByRunner` は上記観測からの射影に限り、矛盾した別値の入力を受けない。`phase` は少なくとも `first-force-out` / `completion-throw` / `other` を区別し、`effect` は `would-score-without-error` / `would-not-score-without-error` の観測済み二値とする。単一得点者に複数失策がある場合の因果関係がこの形で表せない具体例が見つかった場合だけ独立軸を再提案する。RBI-02は `completionCatchError=true` と受球野手参照、RBI-03/04は同じ他fieldで `continuity` だけが違う対向負例として検査する。

この型は field 名・参照の正式決定前の候補。既存109件の欠落fieldを既定値で埋めず、現値が明示する事実だけを保持し、不足caseは拒否または未検証とする。要件書E-1の入力能力、ADR D-11 descriptor、schema、規範行・case、両runner、P-6入力、7.7 digestに影響する。旧受理履歴は書き換えない。

## G6-S09〜S11と初回MVPの境界

ADR D-8 `XC-09` の `D+1` は、`liveness-only` で結果 `applied`・履歴要素数が1減ることだけを保証し、状態・残要素の同値を主張しない。一方、長さ1/2/Dは同条文により `full-equality` が必須。**既存保証で可能**なのは FR-006 の「直前の確定プレイ1件」を取り消す操作、空履歴の `nothing-to-undo`、保証範囲内の比較面全欄と23フラグ寄与差分の逆適用である。長さ1/2/Dを「原典不足につき製品対象外」にしない。**追加判断が要る**のは、連続undo列とタイブレーク開始操作を含む履歴の順序・差分の規範case、FR-007の任意位置修正後の下流再計算と旧印の失効・遅延旧イベントの扱いである。具体的には「前半回の第3アウト確定 → 次半回のタイブレーク配置 → undo」が最小反例となる。FR-006のundo対象は第3アウトのプレイであり配置操作ではない。第3アウトを取り消すと次半回とその配置印は現正史に残せない。2026-10-22のPO方針により、第3アウトの逆適用と、その取消で前提を失う後続配置・適用印の正史からの除外を**同一scopeで行う**。監査原本、既存D5台帳、保存済み応答は削除・改変しない。同じD5・内容の再送は取消前の保存済み結果をDI2で再掲し、再配置しない。未消費の旧要求が後着しても旧正史を復活させず、遮断を耐久化する。訂正後に適格な半回が再び成立する場合は、旧D5を別内容へ読み替えず、明示した新要求・新D5で再配置する。第3アウトの逆適用・依存配置と印の有効性解除・新正史の前提/遮断記録・投影更新は同一業務transactionで不可分に確定し、失敗時は全取消する。外部耐久制御が同一transactionに入るとは主張せず、必要なら有効化前と全適用経路でfail-closedに照合する。commit結果不明時は保存済みD5と正史を照会するまで成功・未消費のいずれにも断定しない。遮断に必要な因果識別子と発行・照合の責任、結果分類はU-S1の受理待ちで、初回MVPのundoを対象外にしない。FR-007の製品要求そのものは維持し、`D+1`の保証をこれらへ一般化しない。

候補caseは `TB-S09-last-play-undo` (長さ1/2/Dの `full-equality`)、`TB-N09-empty`、`TB-S10-D-plus-one` (`liveness-only`)、`TB-S11-past-edit-replay` (FR-007の別経路・差分プレビューと旧印遮断) に分ける。**長さ1/2/Dの閉包とFR-007経路は現計画ステップ1の「D+1内」を越えるため、正式資産への収録には対象ID・成果物・停止点を明示した最小計画追補と6.1レビューが先行する。**今回の文書は必要caseの候補固定までとし、計画追補承認前に実装・正式ID化しない。最後の入力列と正式結果型は U-S1/訂正所有者の受理待ちであり、現段階で正式ID・期待値を仮置きしない。
