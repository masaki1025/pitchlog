## 6. 観測の独立性(本計画書 4-4-d 節)

**「観測」と書いた合格条件を runner の自己申告で満たしていない。**

| 観測 | 取得主体 | 実測 |
| --- | --- | --- |
| **再 provision 0 回** | **PostgreSQL のサーバーログ**(`log_statement='all'` を runner の外側で設定し `docker logs` で採取) | `CREATE DATABASE` **1** / `CREATE ROLE "pitchlog_owner"` **1** / `INSERT INTO alembic_version` **1** / `GRANT CONNECT ON DATABASE` **1** — **いずれも作り直し 1 回分だけ**で、48 node の実行中には 1 回も起きていない |
| **入口の分岐を 48 回とも通った** | 同じサーバーログ | **`TRUNCATE TABLE` が 96 回 = 48 node × 前後 2 回**。データ初期化は外部供給の分岐でしか起きない |
| **Docker のコンテナ作成 0 回** | **`docker events --filter event=create`** を実行中ずっと購読 | **0 件**(使い捨てクラスタが 1 つも立っていない) |
| **サーバー・DB の同一性** | 接続したサーバーの識別値を**compose の実コンテナの中から独立に読んで**突合 | 観測 **96 件 = 48 node × 2 接続**が全件、クラスタ実体の識別値と対象データベース名の両方で一致 |

**独立に取れていない項目を 1 つ明示する**(同節「独立に取れない観測があれば、その旨を判定記録へ書く」):

- **JUnit XML の成果物は、runner が書き出したあとに後処理している** —
  例外文と捕捉出力を消している(NFR-014。失敗時の出力に接続文字列が混ざりうるため)。

  生の pytest 出力そのものではない。** **この 1 項目は実行側の申告を含む。**
