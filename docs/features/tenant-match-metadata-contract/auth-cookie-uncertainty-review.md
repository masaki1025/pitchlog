## 残る判断と推奨する方向

**最初のfrontendだけの無効化案を、別タブを含む競合の完全解消として採用しない。** 観測できた旧応答の安全側無効化という限定保証と、login後に別identityを採用しない保証を分ける。

公開前の推奨は、Codex Dが **login/sessionの相関を検証できる最小C1追補** を具体化・レビューする方向である。候補の所有ファイルはbackendの`api/schemas/auth.py` / `api/routers/auth.py`と必要な既存auth境界、frontendの`api/auth.ts` / `api/client.ts` / `authStore.ts`と固有spec。具体的なfield/header/literal・相関の生成方法・保存候補の扱い・失敗分類はまだ正式化していない。新endpoint/ACL/DB操作を必要とする場合は、その個別差分だけを別ゲートへ出す。

Cookie更新の単純廃止は推奨しない。要件NFR-011は7日既定のスライディング延長を定め、U-A1 HTTP計画ステップ9はDB発行期限へMax-Ageを追随させる承認済み契約を持つ。独自の絶対期限・アプリ側TTL計算を足して解消したことにしない。Cookie方針を変えるなら、別途その正本・契約ゲートが必要である。

上記方向の人間判断前に、新しいfield/header/literal/endpointを正式仕様や製品へ追加しない。C2の承認済み7経路、経路未登録U-F3の実装・検査・コミット・PR準備は独立して仕上げる。U-F13の公開・競合受入完了は宣言しない。
