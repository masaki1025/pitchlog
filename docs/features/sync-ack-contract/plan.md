### なぜこのタスクが要るか

**後続 α は注入境界を 7 点空けたまま完了している。** すべて fail-closed なので、
**供給側が来るまで α の遷移は一度も発火しない**。本タスクがその供給側を作る。

**ただし 7 点は同じ応答経路に属さない**(**計画レビュー 1 周目 P0-1** — 当初は「7 点すべてを ACK から」と書いていた誤り):

| α の注入境界 | 供給元 | 本タスクの扱い |
| --- | --- | --- |
| **A5 結果** | **D1 ACK** | **実装する** |
| **B3 の理由分類** | **D1 ACK**(**「内容起因 / `O4`」まで** — 下記) | **実装する** |
| **A4 の写像確定** | **D1 ACK**(条件付き) | **実装する** |
| **`accepted_at`** | **P3 の独立応答**(**D1・D3・`A3`・`A5` を使わない別経路**) | **実装する**(別の封筒として) |
| **`I6` 退避保存完了** | **ローカル永続化の完了** | **射程外**(α が既に receipt で受ける) |
| **`O4` 是正済み確認** | **管理者の是正ワークフロー** | **射程外**(後続 γ / 運用) |
| **RG1 状態** | **再試行時の外部状態確認** | **射程外**(後続 γ) |

**`A1`・`A2` は ACK のペイロード項目ではない。** サーバーが保証する性質であり、
**受け取り側からは検証できない**(`docs/design/sync-protocol.md:911-912`)。**封筒の型に入れない。**

### `B3` の分類はどこまでか(**計画レビュー 1 周目 P0-3**)

**`改訂待ち` / `墓標待ち` は ACK から決まらない。** 正本 6-4 は
「**B3(恒久的な内容拒否)からの再開だけを 2 択に限定する**」と定め(`:835`・`:839`)、
7-2 も「**内容起因では操作者の判断**を待つ」と書いている(`:989`)。
**`B3a` / `B3b` も `reason` も、どちらを選ぶかを決めない。**

したがって **ACK 消費が供給できるのは「内容起因 / `O4`」まで**であり、
**`改訂待ち` / `墓標待ち` の確定は操作者の 2 択が供給する**。
**α の `classifyB3` は「内容起因ならラベルを返す」形になっており、これを是正する**(§4 の変更許可ファイル)。
