# 調査メモ: ORM 導入(SQLAlchemy 2.x・Alembic)と models・migration の実装射程

## 問い

TSK-343 の実装計画を書くために、次の 5 点を典拠付きで確定させる。

1. TSK-317(`feature/pg-authz-verification-g2`・実装中)との**実装衝突 5 箇所の所有境界**
2. `tests/test_ci_wiring.py:1272` と**設計書 10.1 の連動**、および改訂のゲート水準
3. **マージ順序**(TSK-348 / TSK-317 / 本タスク)の根拠
4. **TSK-344**(越境テスト再実行ゲートの実行)との依存の向き
5. 本タスクが満たすべき**要件条項と論理スキーマ側の制約**、および**射程の穴**

調査は /investigate で 4 並列(spec-checker / legacy-analyst / decision-tracer + 衝突実測 1 本)。
**本メモの事実はすべて `ファイル:行` を典拠に持つ。典拠のないものは「不明」と明記する。**
**エージェント間の食い違い・誤りは原典を自分で読んで裁定した**(→ 6 節)。

## 結論(要約)

1. **申し送りの衝突 5 箇所のうち、実際に衝突するのは `backend/tests/db/conftest.py` の 1 箇所だけ**。
   設計書 10.1・`environment-expectations.json`・`backend/uv.lock`・`backend/pyproject.toml` は
   **TSK-317 が計画書で明示的に本タスクへ手放している**(`pg-authz-verification-g2/plan.md:153,160,171`)。
   `tests/test_ci_wiring.py` は TSK-317 の**改訂 3**(`S-8`)でのみ触られる。
   **申し送りに無い 6 番目の衝突面 `.claude/core-areas.json` が判明した**(両者が同じ `tenant-isolation.paths` を編集予定)。
2. **本タスクの実装方針は `data-model.md` 12-4 節が approved 済みで既に固定している**。
   本タスクの裁量として開いているのは **3 点だけ** — Alembic の**置き場**(論点 15)・
   **`D5` の「経路と種別の一致」の強制機構**の選択・**ADR 起票の判断**。
3. **裁定 `R-5` が指定した確定ゲートの受け皿が存在しない** — 相乗り先だった `data-model.md` の
   `/finalize-doc` は TSK-342 が 13 周で通して閉じた。**人間の裁定が必要**(→ 未解決 `Q-1`)。
4. **DoD の 3 条件に正本の典拠が無い**(型境界の限定 / exact-set テスト / `downgrade`)。
   **計画書で自主基準として定義するか、典拠のある形へ寄せるかの判断が必要**(→ `Q-2`・`Q-3`)。
5. **接続 URL の `postgresql+psycopg://` への「統一」は範囲を切らないと配線検査を壊す**。
   ただしこれは**罠であって障害ではない**(→ 4-3 節の裁定)。

#### 5-3. コミット記法(設計書 6.1)

- **ステップコミットの件名には完全トークン `(ステップ <k>[/<N>][ 付記])` をちょうど 1 個含める**(設計書 `:280`)。
  **厳密文法**: ① 開き括弧と閉じ括弧は同種で一致 ② **`k = 0` は不正** ③ **`/<N>` を書く場合、実装ステップ表の総数 N と一致**
  ④ 数値の直後に許すのは `/`・同種の閉じ括弧・空白の 3 つだけ ⑤ **括弧のない文言は不算入**
  ⑥ **1 件名に 2 個以上のトークンがあれば不整合**。
- **本タスクは `backend/` のコードと `tests/test_ci_wiring.py` を触る = 文書系・計画系のどちらでもない**ため、
  **全実装コミットにステップ記法が必要**(無記法だと `feature_status.py` が `unknown` に落ちる — 設計書 `:280` 後半)。
- **`/<N>` を書くなら表を確定してから**(規則③ — 表を後から増減すると既存コミットの `/<N>` が全部不整合になる)。
  `/<N>` は任意なので `(ステップ k)` も規約上許される。
- **確定ゲートの反映周コミットにはステップ記法を付けず `反映<r>周目` だけを含める**(設計書 `:307`)。
  **`確定ゲート` を含むだけの件名は反映周コミットとみなさない**(同 `:308`)。
  **`<r>` は 1 始まり・採用反映を伴う周のみ**(同 `:301,416`)。**全件不採用の周は反映周コミットにしない**(同 `:421`)。
- **注意(台帳 `H-58`)**: **反映周コミットが非文書パスを含むと現在地導出が「不明」へ縮退する**
  (`harness-evaluation.md:54`)。**解消済みかを示す記録は確認できていない(不明)**。
  TSK-342 は「ステップ表の 13 段目に置く」ことで回避した(`data-model-schema-orm/plan.md:353-358`・実コミット `a8648f1`)。
- frontmatter に **`反映周コミット: 適用`**(必須・既定値なし — 設計書 `:303`)。
