# 実装計画: 旧 Baseball_Scoring 画面への操作感一致

## 1. 背景・目的

PO 指示(2026-11-11)により、PitchLog のフロントエンドを「旧アプリを参考にした新デザイン」ではなく、旧 Baseball_Scoring 固定 HEAD `dd03160` と同じ画面構成・情報配置・操作順へ合わせる。旧 React 実装は仕様・挙動の参照に限定し、Vue で再実装する。PitchLog の実 API・単一ドメイン計算・耐久キュー・認可・記録権・保存処理を接続先とし、旧バックエンドや別の計算・保存経路は追加しない。

## 2. スコープ

### やること

1. 旧 `dd03160` の `StartScreen` / `GameListScreen` / `GameScreen` と現行画面を同じ試合状態で比較し、比較画像と差分を記録する。
2. 記録画面を旧 `GameScreen` の 3 ペイン構成へ置き換える。スコア・回表裏・カウント・アウト・走者・打者・投手のヘッダー、構え・球速、ストライクゾーン・球種、結果パッド、下部バーを同じ位置・順序・大きさで再現する。
3. 通常投球の連続入力、走者あり打球、交代、取消、終了・再開、reload を実 API/実 DB で確認する。ブラウザ内 `fetch` の直接成功は画面操作の証拠にしない。
4. 旧画面にない安全表示(未送信・結果不明・記録権・単一 writer)は旧画面のヘッダー/バーへ自然に統合する。
5. 記録画面の方向性確認後、試合一覧・作成/開始・選手管理・成績・CSV へ同じ基準で広げる。

### やらないこと

| 対象 | 理由 |
| --- | --- |
| 旧 React を依存・同梱する | ADR-002。Vue で再実装する |
| 旧バックエンド・旧計算核の移植 | 単一ドメイン計算(NFR-018)と保存経路を増やさない |
| 未接続機能を有効に見せる | 成功表示の偽装をしない |
| 旧アプリにない MVP 必須機能の削除 | 安全確認・未送信・記録権は維持する |

## 3. 影響する正本

反映なし。実装は `frontend/src/**` と本 feature の計画・進捗、比較画像の置き場に限定する。ADR-002 の参照境界に従い、旧実装から取り込む部品は pitchlog の資産としてテスト・lint・型検査の対象にする。

## 4. 実装方針

旧 `GameScreen.tsx` のレイアウトを基準に、次の順で進める。

| # | ステップ | 合格条件 |
| --- | --- | --- |
| 1 | 比較固定と記録画面の旧レイアウト化 | 旧 `dd03160` の実画面画像と現行画像を同一状態で取得。記録画面が旧 3 ペイン・ヘッダー・下部バーを持つ。既存の pitch 保存経路とテスト ID を維持 |
| 2 | 通常投球・走者あり・交代の実画面接続 | 実 API/実 DB で通常投球の連続、走者あり打球、交代、取消、終了・再開、reload を画面操作で確認 |
| 3 | 試合一覧・作成/開始・選手管理・成績・CSV の旧画面化 | 各画面を旧構成へ寄せ、実データで確認 |
| 4 | 独立レビューと残余ギャップ記録 | P0/P1 を是正し、未接続を明示する |

## 5. DoD

- 旧 `dd03160` と現行の比較画像が同一試合状態で存在する。
- 記録画面の通常・走者あり・交代操作が実画面から実 API/実 DB へ到達する。
- 通常投球の連続記録が製品 UI で成立する(ブラウザ内 fetch 代行を証拠にしない)。
- 未送信・結果不明・記録権・単一 writer の安全表示が維持される。
- `vue-tsc`・eslint・対象 Vitest・実画面 E2E が成功する。
- 未接続の旧機能は「未対応」と明示し、成功表示しない。

## 6. テスト計画

- 旧 `dd03160` を mock モードで起動し、1440×900 / 1024×768 / 390×844 の画像を取得する。
- 現行は所有 DB の一時環境で同じ画面状態を作り、同じ viewport で画像を取得する。
- 記録画面は Playwright でボタンクリック・入力のみを使い、通常投球、走者あり打球、交代、取消、終了・再開、reload を確認する。
- Vitest で表示部品と結果パッドの選択・無効理由を検証する。
