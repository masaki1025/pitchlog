# #176 母集合 fixture core path 登録 専用2ステップ計画案

状態: 未承認。これは同 feature の [承認済み計画](plan.md) のステップ1未達DoDを是正するための専用手順であり、別タスク・別PR・新たな正規実装ステップではない。正本6.1の機械可読な実装ステップ表と既公開 `(ステップ 1/1)` は `plan.md` に保持する。

## 1. 背景・目的

TSK-391／#176 の O5 母集合 fixture `tests/fixtures/sync-protocol-population_v1.json` は同期プロトコルの意味範囲に属するが、現行 `.claude/core-areas.json` の `sync-protocol.paths` で検出されない。ハーネス設計書6.3⑤に従い、既存PRの残P1を解消する。O5の正本意味・製品実行検証は本追補で変更しない。

## 2. スコープ

### やること

- `scripts/core_guard.py` の `AREA_PATH_ADDITIONS` に `sync-protocol` の当該fixture完全一致パスを宣言し、既登録の `game-state`／`tenant-isolation` 層を維持する。
- `tests/test_core_guard.py` に、宣言済み候補の検出、据え置き層保持、未宣言・部分追加・未チェックの拒否を検証する試験を追加する。宣言のみの段階でも試験が緑になるよう、登録候補は一時リポジトリで合成する。
- 宣言コミットの後に、`.claude/core-areas.json` の `sync-protocol.paths` へ同じ完全一致パスを1件だけ追加する。PR head側の実設定でfixtureが同期プロトコル領域へ検出されることを確認する。

### やらないこと

- fixture本文・O5契約・製品コード・他領域の登録、正本、凍結資産、CI設定の変更。
- O5製品経路の実行済み扱い、本人逐行確認の代記、Draft解除、マージ。

## 4. 実装方針

重さ分類はコア領域。登録対象は fixture の完全一致1パスと `sync-protocol` 1領域に限定する。基線の既存登録順序・内容を保ち、候補の末尾追加を6.3の二層契約で照合する。既存の宣言済み `game-state`／`tenant-isolation` は消さず、現在のbaseに取り込まれた層として扱う。後続で基線が進んだときは実baseから再照合し、登録範囲を推測で拡大しない。

| 2 | JSON登録だけ | `.claude/core-areas.json` の `sync-protocol.paths` に完全一致パスを1件追加。PR headの実設定でfixtureがcore検出され、未チェックPR本文を拒否。基線検査と関連guard試験が通り、他領域と既存登録が不変 |

### 6.1のコミット規律と開始条件

同一ブランチの公開済み初回コミットは `(ステップ 1/1)` である。正規表を3件へ増やすと既公開の `/<N>` が不整合になる。表を1件に保ち無記法のコード是正コミットを2件作る案も、6.1が無記法実装を規約逸脱として「不明」に落とすため、**第2回レビューでP0として否決された**。`/pr` の差し戻し往復を根拠とする案も、現HEADのplanは最初から `active` であり、`in-review → active` の遷移がないため採用しない。

**推奨する次の判断**: #176内完結を維持するなら、6.1へ「公開済みステップ総数を変えず、コア登録の残P1を既存PRで二つの是正コミットに分ける場合」の狭い手続を正本改訂案として定め、7.3の正式ゲートを通す。その改訂では対象PR、対象パス、コミット件名、feature_statusの表示と受入判断、承認記録を明示し、guard検査を緩めない。これを避ける規約適合案は、独立 `plan.md`／専用PRを起こすことだが、今回の「新規PRを増やさない」と衝突するため、方針変更の人間判断が必要。どちらも未承認であり、現時点で実装開始可能と扱わない。

**登録開始条件**: 上記6.1処置の正式確定またはPR方針変更、追補最終SHAと6.3⑤の登録範囲への旧計画とは別の人間承認を、`plan.md` 追補欄へ承認者・実日で記録すること。`plan.md` のfrontmatterはそれまで `承認: 未` とし、旧承認は本文履歴で保持する。承認前は `scripts/core_guard.py`・`tests/test_core_guard.py`・`.claude/core-areas.json` を編集しない。
