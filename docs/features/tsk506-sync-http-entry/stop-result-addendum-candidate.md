## 候補設計と境界

| 観測 | 506 の候補動作 | 別契約の受取条件 |
| --- | --- | --- |
| B1〜B4 の有効 ACK | `(D4,D1,D5)` ごとの A5 だけで既存状態遷移を行う | 既存契約を維持 |
| 既存 B7 の通信断・408/500/502/503/504 | `no-ack/B7`、未送信保持と既存の自動再送 | 新停止に包括的に読み替えない |
| 新停止結果候補 | 新しい識別子と型付き wire 封筒を厳格に検証する。ACK ではないので A5 遷移、同期済み化、D3 前進の端末確定、内容拒否扱いを行わない。要求全体を未確認として保持し、送信を停止する | U-S1 の結果 ID・非機密の公開理由・HTTP 形・前方確定／対象取消／後続未処理、commit 不明時の扱いを正本と wire 設計で確定 |
| S-1 の 422・未知応答 | 既存の別分類とキュー保持を維持 | 新停止と同じ自動再送停止の意味を推測で与えない |

公開理由は、内部原因をそのまま返す項目ではない。以下は端末に保存する**表示群と再開条件の候補**であり、wire の理由値は U-S1 と TSK-331 の契約確定後に決める。

| 内部観測（端末へ直接返さない） | 利用者向け表示群の候補 | 明示再開の前提 |
| --- | --- | --- |
| 原本 0 行（RLS で不可視の場合を含む） | 記録の参照を確認中 | 同一テナントの正しい原本をサーバーが確認。参照内容を直すなら新 D5 |
| DB 読取・接続障害 | サーバーの復旧待ち | 読取経路の回復をサーバーが確認 |
| 明示的な DB 権限エラー | 管理者の確認待ち | 既存の最小権限で読めることをサーバーが確認。権限拡大は別ゲート |
| **未使用 D5** の改訂元となる不変の拒否原本の不整合 | 管理者の確認待ち | 管理者の是正後にサーバーが原本の整合を確認。復旧不能なら停止継続 |
| D-2c 前の墓標 `"8"` | この記録操作の提供待ち | D-2c の正式提供と同一要求の適用可能性をサーバーが確認 |

既存 D5 の保存済み台帳・再掲結果の破損はこの表に含めない。現行 U-S1 設計 11 節の B7 扱いを維持し、今回の結果候補から意味を変更しない。

端末側では、既存四状態に第五状態を足す前提を置かず、**送信保留の耐久メタデータ**を第一候補とする。同一 `(game,D4)` の送信対象、停止した要求の D1/D5/内容・codec 版の同一性、利用者に出せる停止理由・必要操作、明示再開可否を IndexedDB の同じ原子的な更新で保存する。送信スケジューラは送信前と再読込直後にこの保留を読み、保留中は同 scope の自動送信を許さない。後続球は既存キューへ保存できるが送信しない。保留の保存に失敗した場合は「停止を保持できた」と返さず送信を閉じて顕在化する。**停止応答受信から端末保存までにブラウザが失われる窓**と、保存失敗後の再起動時の保証は試験・正式契約で扱い、現段階で保証済みと主張しない。

明示再開は、サーバー側が同一テナントの前提回復を確認できた場合に限り、保存した同じ D1/D5/内容/codec 版の要求を送る。前方で確定済みのイベントは U-S1 の DI2 再掲で確認するまで端末で成功扱いにしない。停止が解消したという端末申告だけで保留を解除しない。内容訂正では、旧要求の送信抑止と同一 D1・新 D5・訂正内容への置換を一つの耐久更新にする。既存の B3 改訂／墓標 API をそのまま流用できるとは扱わず、U-S1 の新 D5 契約、キュー所有側、U-F8 の操作導線が確定するまで訂正 UI を公開しない。

利用者には「送信を停止し、記録を端末に保持した」ことと、契約で認めた必要操作を示す。他テナント原本の存在、DB 権限、原本破損の内部詳細は表示・ログに出さない。停止応答自体を成功通知や内容拒否通知へ写さない。HTTP は混在 E-1 を分割せず、前方確定分も同じ要求の未確認キューに残す。U-S1 の対象取引の取消が確認できたときだけ D5 非消費とする。commit の結果不明は別の隔離・耐久照会条件へ送る。

独立に準備する試験ケースは、(1) 現行 5xx 全種が B7 のままで同 D5 を保持、(2) 新停止候補の識別子または封筒が欠ければ成功・B7 と推測せず送信を閉じる、(3) 有効な新停止を耐久保存後に DB を閉じて再読込しても自動送信 0、(4) 保留中の後続球追記と送信 0、(5) 同一 D5/内容の明示再開だけが送信可能、(6) 訂正では旧要求の送信 0 と新 D5 の原子的置換、(7) 混在バッチ前方分を ACK 前に同期済みにせず、再開後の DI2 で一度だけ確定、(8) S-1・未知応答・認証切替と新停止の分類分離、(9) 他テナントと不存在の応答同一性・停止理由の非開示、(10) 保留保存失敗／応答消失／commit 不明の fail-closed をそれぞれ分ける。正式値を要する負例は仕様確定後に Vitest・pytest・隔離 DB 試験へ落とす。
