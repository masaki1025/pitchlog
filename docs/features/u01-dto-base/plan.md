### **本単位が決めることは要件の帰結ではない**(**明示**)

**次の 3 点は、要件書にも正本にも決定が存在しない**([research.md](research.md) 1 節)。
**`U-01` の設計判断**として決める。**`U-00` の (A)/(B) 2 層の書き分け**(`u00-api-shell/design.md:45-72`)に倣う。

| 決めること | 根拠の層 | 制約 |
| --- | --- | --- |
| **ID の表現** | **(B) 実装事実に合わせた判断** — **UUID のサロゲート ID に限れば**ORM は例外なく `Uuid(as_uuid=True)`(実測)。**自然キー(`Text`)と同期系の `D1`〜`D4`(数値)は別系統で対象外**(**1 周目 `P2`**)。**これを固定した正本条文は無い** | 型まで固定された正本の ID は**断中の一時 ID = `uuid`** の 1 件のみ(要件書 `:363`) |
| **時刻の保持形式・精度** | **(B) 同上** — ORM の `DateTime(timezone=True)` 39 箇所すべて | **(A)** 日時は **JST 基準**(`D-33 ①`・要件書 `:1019`)/ **タイムゾーン対応は Won't**(`NFR-022`) |
| **ページングの形** | **(B) 設計判断** | **(A)** 「一覧系画面はページングする」(`NFR-005` `:818`)**のみ**。**同時比較上限の「切り捨てず 400 で拒否」(要件書 `:508`,`:628`)は比較対象テナント集合の規則であり、件数上限一般へは及ばない**(**1 周目 `P0` で範囲を限定**) |

**ページングは「形だけ決め、値は決めない」**(**PO 判断 2026-09-17**)。
**理由**: 同期プロトコルが「HTTP 形状・ペイロード形式・**バッチサイズ**・バックオフ定数」を実装計画へ送り、
「**実クエリ・実回線が無い段階で定数を確定させるのは根拠のない固定になる**」と書いた前例と同型
(`sync-protocol.md:1552` 論点 18)。**既定件数・上限件数の数値は各葉の単位か設定値の正本が持つ。**

**下流への先決になることの明示**: TSK-363 は一覧を返す `U-M1` / `U-A2` / `U-C2` / `U-D1` / `U-X2` について
**ページングの形を 1 つも前提していない**([research.md](research.md) 1-5)。
**本単位が形を決めれば下流 5 単位への事実上の先決になる。** 許した条文も禁じた条文も無いので、
**本計画書の承認をもってその線引きとする。**
