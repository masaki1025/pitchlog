# 調査メモ: U-01 DTO 基盤(共通型・ID・時刻・ページング・バリデーション写像)

## 問い

**`U-01` は何を決められて、何を決めてはいけないのか。**

単位名が「共通型・ID・時刻・ページング・バリデーション写像」(`docs/features/product-impl-unit-split/plan.md:197`)である一方、
**主所有 FR は「—」**で、`design.md` の帰属表 3 つ(4-1 主所有 / 4-2 分担 / 4-3 重複帰属)に**器 3 本は 1 行も現れない**。
**要件の帰結として書ける範囲**と、**`U-01` が新たに引く線**を切り分けることが本調査の目的。

## 結論(要約)

1. **ページングの形・ID の表現・時刻の保持形式・「一覧系画面」の集合のいずれも、
   要件書にも正本にも決定が存在しない**(**事実**)。**何をどこまで決めるかは [plan.md](plan.md) 2 節が正。**
2. **TSK-363 は一覧を返す 5 単位についてページングの形を 1 つも前提していない**
   (「ページング」の語は単位名の 1 箇所のみ — **事実**)。
   **先決を許した条文も禁じた条文も無い**(**事実**)。**扱いは [plan.md](plan.md) 2 節が正。**
3. **API 契約の正本は `TSK-346` で、まだ存在しない。** `U-00` は自分の規約を
   **(A) 要件の直接帰結 / (B) `TSK-346` 従属の暫定規約**の 2 層に分けて書いた。**`U-01` も同じ書き分けが要る。**
4. **機械が落とす地雷が 9 件ある。** とくに **`generation` が禁止語**で、**経路はちょうど 2 本に固定**されている。
5. **`ResponseValidationError` が 500 に落ちる。** **語はリポジトリ全体で 0 件**で、
   **意図の痕跡も見落としの痕跡も無い(判定 = 不明)**。**既存の `/health` `/version` は `response_model` を持つ。**
   **本単位がこれをどう扱うかは [plan.md](plan.md) 7 節が正**(本書は判断を持たない)。
6. **既存の規約テストと上流 TSK-363 の契約は、広い面と狭い面が別々にある。**
   実装は**対象範囲(`api/**` の全文連結)と照合方式(単語境界なし)が広く、語彙は 5 語と狭い**。
   上流は**差分行・単語境界つき・7 語**。**どう守るかは [plan.md](plan.md) 4 節が正**(本書は判断を持たない)。

> **本書は調査の記録であり、判断を持たない。** 判断は [plan.md](plan.md) と [design.md](design.md) が正。
> **2 周目レビューで、本書の結論に残した判断が計画側の改訂へ追随せず `P0` を 2 件生んだ**ため、
> **結論から判断を外した。**

### 3. 実コードの現況

**`schemas/base.py` の 5 クラスすべてが `pydantic.BaseModel` を直接継承している。**

#### 3-2. ORM の実表現

| 項目 | 実測 |

#### 3-4. バリデーションエラーの現在の出方

`errors.py` が登録しているのは **`fastapi.exceptions.RequestValidationError` だけ**。
**`pydantic.ValidationError` を直接ハンドルする登録は存在しない。**

写し方(`errors.py:55-65`): `errors()` から **`loc` だけ**を取り出しドット連結して `ErrorField.location` に入れる。
**`msg` / `type` / `input` / `ctx` は一切写さない。** メッセージは固定文言、ステータスは常に 422。

**穴**: `ResponseValidationError` は **`RequestValidationError` のサブクラスではない**
(fastapi 0.141.1 — `fastapi/exceptions.py:212`,`:234` がともに `ValidationException` を継承)。
そのため**応答 DTO の検証失敗は `Exception` ハンドラに落ちて 500** になる。

**`ResponseValidationError` の語はリポジトリ全体で 0 件。** `U-00` の写像表(`u00-api-shell/design.md:74-83`)が
列挙するのは `RequestValidationError` / `StarletteHTTPException` / 未捕捉 `Exception` の **3 系統だけ**で、
**応答側の検証失敗という項目自体が存在しない**。テスト計画の列挙(`plan.md:178`)も 422 / 404 / 405 / 403→404 / 500 まで。
→ **意図の痕跡も見落としの痕跡も無い(判定 = 不明)。** ただし**現状の挙動は既決に違反していない**
(未捕捉例外は 500 + `logger.exception` + 本文に内部情報を出さない = `NFR-015` `docs/requirements/requirements-pitchlog-2026-07-22.md:872-875` の直接帰結)。
