## 結論(要約)

1. **規約が要求する docs 検査 28 件のうち、機構が検査しているのは 5 件のみ**(部分的 6・**なし 17**)。frontmatter status とその索引整合・plan status・除外ディレクトリ・リンク切れは検査されるが、**変更履歴表・版・最終更新・逆突合・確定ゲート経路・計画書 3 節の宣言突合は機構がゼロ**
2. **H-1 の主張は実コードで事実**。索引から読むのは「文書」「状態」の 2 列だけで、正規化が `split("(", 1)[0]` により**最初の半角 `(` 以降を丸ごと捨てる**
3. **H-17 の残余(`test_check_docs_status.py` の版・履歴テストの欠落)は、どの F-ID にも割り当てられていない**。F1 に入ったのは `git_guard` 系のテスト 3 種だけ。**F2 の DoD ⑤ がこの空白を埋める位置にある**(スコープ重複はない)
4. **索引の掲載基準は明文化されていない(不明)**。逆突合(H-15)を実装するには**基準の明文化が先**。なお**現時点の実害はゼロ**(索引未掲載は `docs/README.md` 自身のみ = 設計どおり)

7. **変更履歴表を機構検査すると既存 3 文書が失敗する**。容認する決定は存在せず、**除外規則を設けるか 3 件に表を新設するかは PO 裁定事項**(§8)
