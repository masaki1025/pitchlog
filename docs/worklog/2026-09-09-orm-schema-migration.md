### 罠 1 — DSN のスキームが DB 必須テスト 102 件を全滅させていた

`tests/db` が **102 件すべて setup error** になっていた。原因は環境変数
`PITCHLOG_TEST_ADMIN_DSN` / `PITCHLOG_TEST_ROLE_DSN` のスキームが `postgresql+psycopg://` で、
これは **SQLAlchemy の URL 形式であり libpq の conninfo ではない**こと。psycopg の

これで説明できる。

#### 裁定の材料として提示した分析

**この発火は射程の問題ではない。** 7.3-6 のエスカレーションは
「**起因の集中 = 射程に無理がある**」ことを想定した機構だが、
**今回の起因の集中は射程ではなく私の反映品質**である。

- **レビュアは射程宣言を尊重しており、射程外の指摘は 2 周とも 0 件**

  ① **反映の向きを反転させた**(「却下案」の見出しの下に否定形を置き、却下対象が逆になった)
  ② **「片方だけ直す」の 3 回目**(前周の採否記録に「索引も同時に直した」と自分で書いた直後に、
     索引の記述と日付が残っていた)
- **射程縮小も範囲確定も、この原因には効かない**

#### 裁定に伴う手順の変更(以後の反映に適用する)

**記録に「同時に直した」と書くことは対策になっていない**(2 周目でそれを実証した)。
**実測で突き合わせるまで閉じない**ものとして手順に組み込む。

1. **三者突合を反映と同一手順にする** — 反映のたびに
   **本文・変更履歴の当該版行・`docs/README.md` の索引**の 3 つを**実測で突き合わせ、
   結果を採否記録に表で残す**(件数・日付・記述の一致を個別に確認する)
2. **極性を持つ見出しの下では項目名を肯定形にする** —
   「却下案」「禁止事項」のように**見出し自体が否定の意味を持つ**箇所では、
   項目名に否定形を置くと**二重否定で意味が反転する**。項目名は
   「〜する案」の形にし、却下・禁止の語は本文側に置く
3. **反映後に「反映が指摘の逆になっていないか」を明示的に読み直す** —
   本セッションで 2 例目(1 例目は計画レビュー 3 周目の出場区間の背番号)
