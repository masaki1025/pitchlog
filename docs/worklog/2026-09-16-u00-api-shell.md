## CI red と是正(PR #67 作成後)

**backend ジョブのみ fail**(`2 failed, 421 passed`)。落ちたのは `test_api_errors.py` のログ表明 2 件。
他 8 ジョブは pass。**人間のレビューによる差し戻しではなく、CI の失敗を PR 作成者が検出した。**

**原因(実測で確定)**: `backend/migrations/env.py:17` の `fileConfig()` が Python 標準の既定
`disable_existing_loggers=True` で動き、`backend/alembic.ini` の `[loggers] keys = root,sqlalchemy,alembic`
に `pitchlog` 系が無いため **`pitchlog.api.errors` ロガーが `disabled = True` にされる**。
CI は `tests/db/test_alembic_migrations.py` が `alembic upgrade head` を走らせ、
**`tests/db/` が `tests/test_api_errors.py` より先に実行される**ためログが 1 件も出なくなる。
**製品コードの欠陥ではなくテスト隔離の問題。**

**なぜローカルで出なかったか**: DSN が無いため `--ignore=tests/db` で回しており、`env.py` を読み込む経路が無かった。

**是正**: `backend/tests/api_fixtures.py` へ `error_logger` フィクスチャ(`disabled` を一時解除し `finally` で復元)を追加し、
ログ表明 3 件が明示 import して使う。**表明は弱めていない** — 各テストの冒頭で
`assert not logging.getLogger("pitchlog.api.errors").disabled` を置き、無効化されたまま素通りしない形にした。
**毒性値の否定テストも対象に含めた**(ロガーが無効だと「毒性値が出ない」が自明に成立し、表明が空洞になるため)。

**再現手順の妥当性を確認した**: 同一プロセスで `fileConfig('alembic.ini')` を先行させてから当該テストを走らせ、
**修正版は 7 passed・修正前のテストへ戻すと CI と同じ 2 件が落ちる**ことを実測した。

**根本側は別タスクへ送る**: `env.py` に `disable_existing_loggers=False` を渡す 1 行の是正。
`backend/migrations/*` は **5 領域すべてのコア paths** で、本計画書 2 節の「やらないこと」に明記した範囲のため触らない。

**台帳**: 既存候補「検証コマンドを人が選ぶと…」の**昇格条件が実害つきで成立**した
(**2 例目を書いた当の PR が同じ型で落ちた**)。**昇格の可否は PO 判断事項として上げる**。
あわせて**新しい観測**を記録した — **除外したディレクトリが、除外していないテストの前提を壊す**形は、
「分けた 2 回の和 = CI の 1 回」という既存の観測では捕まらない。
**テスト間に順序依存があると、母集団が同じでも実行単位が違えば結果が違う。**
