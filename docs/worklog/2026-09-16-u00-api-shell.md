## 決定

- **エラー封筒に `code` を置かない・器は 403 を外へ出さない**。403 を受け取ったら **404 へ落とし ERROR ログへ顕在化**
  させる(fail-closed)。根拠は要件書 `:645` `:681` と改善台帳 `:39`(PO 確認済み「403 を返す分岐は存在しない」)。
  **検査はリテラル走査ではなく挙動テスト**(1 周目レビュー P0)
- **根拠の性格を 2 分した** — 「要件の直接帰結(器が破ってはならない)」と
  「安全側の U-00 規約(TSK-346 に従属)」。封筒全体の `code` 不在・404 文言の固定は後者(1 周目 P1)
- **`/health` の応答契約 `{"status": "ok"}` を変えない**。既存 `test_health.py` を無変更で green にする
  (PO 裁定 2026-08-19 由来・Phase 4 受入証跡が参照)
- **`/version` は実装する**が、要件に典拠が無くカード由来であることを計画書に明記。返すのはアプリ版のみ
- **バリデーション写像の帰属**: 転送層(`RequestValidationError` → 封筒)は U-00、
  フィールド単位の検証規則と DTO 側は U-01(原典 `product-impl-unit-split/plan.md:197`)
- **ルータ登録は静的列挙**(`ROUTERS` タプル・動的探索を使わない)。ADR-003 D-11 の列挙要求に備える
- **影響する正本は全件「反映なし」**。入口を開かないので `route_id` 付与要求が掛からず、
  `contracts/authz/*` も `.claude/core-areas.json` も触らない
