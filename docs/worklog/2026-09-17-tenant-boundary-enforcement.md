## 追補(2026-09-21・7A の射程復帰と 8 周目)

### 7A を射程へ戻した

**「この欠陥で何が起きるか」を人間に問われ、実測して初めて当初の影響評価が誤っていたと分かった。**

切り出し時(2026-09-20)に「影響するのは統治の網であって製品のテナント分離ではない」と説明したが、
`base_ref` は**迂回検査の母集団(どのファイルを検査するか)も決めていた**。
`HEAD` を宣言すると差分が空になり、**検査全体が no-op になる**。

**対照実験**: 強制点を通らずに DB へ到達する製品モジュールを置き、`diff.base_ref` だけを変えた。

| `diff.base_ref` | CI と同じ起動 |
| --- | --- |
| `origin/develop` | **exit 1**(`TB005`) |
| `HEAD` | **`ok` / exit 0** |

**1 コミットで DoD「迂回していないことの機械検査を同梱している」が空洞化する。**
人間の判断(2026-09-21)で射程へ戻し、本 PR で閉じた。

**是正**: 比較元は**検査対象ではなく検査の手続き**に属するものとして、CI が `--base-ref` で与える。
資産から `diff.base_ref` を削除し、宣言したら `ContractError`。
外部指定が無い実行は**検査器のソースに置いた凍結された既定値**を使う
(検査器は `frozen_projection.external_files` に入っているので、動かせば記録が残る)。

**迂回の変種 4 件**(`command` へ `HEAD...HEAD` 直書き / 別名キー / プレースホルダ置換 /
検査対象パスを存在しない場所へ狭める)も**いずれも固有の理由で拒否**された。

### 検出できた理由(残す価値のある手当て)

**レビューのプロンプトで「検査機構そのものを無効化・空洞化する経路が他に残っていないか」を
最重点観点に据え、あわせて脅威モデルの例外を明示した** —
`design.md` 6-0 は「意図的な偽装は静的解析の射程外」と線を引いているので、
**「検査そのものを無効化する経路は 6-0 が守ると書いた『強制点自体の静かな書き換え』に当たるので、
漂流でなくても出してよい」と書き添えた**。
**これを書かなければ 8 周目の P0 は「射程外」として落ちていた可能性が高い。**

**射程を絞るときは、絞った結果として落ちてはいけないものを同時に名指しする必要がある。**
