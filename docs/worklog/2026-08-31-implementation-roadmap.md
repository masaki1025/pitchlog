### 取り下げの決定的な理由

**この射程では、後続の実装作業を機械的に減らす成果物が無い**(2 周目 P0-6):

- 検査器は **JSON 自体の整合性を検査するだけ**で、後続の縦切り計画・API 設計・実装差分を
  評価する入力も規則も無い
- **正本化しない以上、後続タスクが従う義務が無い。正本化するなら「正本への反映 0 件」という
  宣言と両立しない**
- **消費者が存在しない** — 後続計画・`codex_run.py`・CI のいずれもこの資産を入力として読まない

**そして最大の点**: (A) に残そうとした制約は**すべて既に approved な正本に書かれていた**
(`NFR-019(a)` / `ADR-003 D-8` / `FR-034` の出力経路表)。
**新しい JSON へ写すのは 7.1-1「1テーマ1正本」の複製にあたる。**
→ **必要だったのは新しい資産ではなく、既存の正本を参照することだった。**

### 射程縮小そのものが H-68 を回避できていなかった(2 周目 P0-5)

> **13 章改訂を射程外にした一方で、その改訂判断を先に確定しようとしており、
> P0-3 と H-68 を別ファイルに移しただけである**

伝播表の `改訂` / `不変` / `歴史記録` の判定には**実際の新フェーズ案と変更差分が必要**であり、
**語の出現全件 ≠ 意味の伝播全件**である。
