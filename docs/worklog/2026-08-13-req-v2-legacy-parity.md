## 決定

- **旧リポの追加分を全面踏襲する**(PO 決定・2026-08-13)。要件書 v1.9 → **v2.0** へ改訂する
- **Won't 撤回 3 件を明示承認**(いずれも要件書 2.2 に理由が記録されていたもの):
  1. 対戦相手チームとのデータ共有・突合(分析ワークスペース)— 理由は「テナント分離が価値の核」
  2. チーム単位の分析(チーム攻撃分析レポート)— 理由は「将来検討」
  3. 自責点・防御率の算出(公式記録判定エンジン)— 理由は「自責点判定の複雑さに対し失点+FIP で代替」
- **自責点の撤回を取り下げ、Won't 維持に戻す**(PO 判断・2026-08-13・`/investigate` の結果を受けて): 旧の判定エンジンは**本番未接続**(永続化 API の呼び出しがフロントに 0 件・`ENGINE_VERSION = "manual-api/1"`・9.16(g)(h) は呼び出し元がテストのみ・ERA 非算出)で、踏襲の動機(旧の利用者が使っている機能に追いつく)が成立しない。かつ pitchlog は責任投手帰属という**土台を既に持っている**(毎球データの必須項目・移行仕様がエラー帰属を保護)ため、**将来の追加は加算的に可能**と確認した。撤回は 2 件へ
- **波及して確定**: 自責点が Won't のままなら公式記録の**専用レビュー機構を作る理由が消える**ため、(a) 4 つ目の Won't「イレギュラー判定の専用自動化」(`req:75`)は**撤回不要**、(b) 公式記録の判定・改訂ワークフローは**踏襲しない**(新規 FR 12 要素が範囲から落ちる)。打点は付録E の「成績計上フラグ」= 機械判定を維持、責任投手の曖昧ケースの顕在化は NFR-015 + FR-003 手動上書き + FR-007 修正の射程で扱う
- **着手順序**: 本タスク(要件 v2.0)を Phase 4 骨格より先に着手する。要件書がクリティカルパス上にあり(実装は承認済み計画書に従う規律のため、v2.0 未承認の間は機能実装へ進めない)、骨格側は機能要件に依存しないため後追いで並行できる
- **重さ分類 = コア領域**: NFR-010・FR-034 のテナント分離に触れるため、計画レビューは敵対レビュー + 人間承認、PR は人間の逐行確認が必須
