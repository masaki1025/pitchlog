## 決定

### 射程 — 退去(削除)機構を外した(人間の判断 2026-09-26)

**敵対レビュー 2 周目の P0 を原典で確認した。** `check_tenant_boundary_bypass.py` の `load_contract` は **`FROZEN_BASELINE_ASSETS` の 7 資産すべてを無条件に `_read_json` する必須入力**である。**資産ファイルを削除すると、退去の記録を検査する前にここで落ちる。**

**したがって「非 authority 資産なら削除できる」は成立しない — 7 資産のどれ 1 つも削除できない。** `load_contract` を一律に条件付きへ変えると、検査入力を退去記録だけで外せる経路ができる(空洞化)。**「実行不能か空洞化の二択」**であり、7D の残りという射程では安全に閉じられない。

**448 が実装するのは D4(履歴アーカイブの規律)・D5(実装の隔離)だけ。** **退去の仕様は [design.md](../features/frozen-history-7d-remainder/design.md) 3 節に契約として書き、TSK-452(新設提案)へ送る。**

### 「本タスクが開くもの」の見直し — 448 は PR B を開かない

**当初は `product-authz-surface/plan.md:43`(★8)の「PR B は 7D の後」を根拠に、本タスクが PR B を開くとしていた。**

**TSK-424 の回答(2026-09-26)で、PR B が待っているのは `contracts/tenant_boundary/runtime-authz-contract.json`(7 資産の 6 番目)の削除**だと確定した(原典 `product-authz-surface/design.md` 9 節)。**それは射程から外したものそのものである。**

**PR B の解錠は TSK-452 または TSK-443 の設計判断へ移る。**

### PR B(TSK-443)への申し送り

**迂回できない点(実測)**: **保護資産の母集団は `FROZEN_BASELINE_ASSETS` ではなくディレクトリそのもの**である。比較元は `ls-tree -r`、HEAD は `iterdir` で**独立列挙**する。**定数から外してからファイルを消す順序は通らない。**

**ただし条文上、ファイルを残す道がある**: 条文 `:574-576` は「**対応が残るときは、基準の宣言を残し、外した対応だけを取り除く**」と定める。**PR B で消えるのは「暫定的な値」であって「凍結する対象」ではない。** **`runtime-authz-contract.json` を残したまま `frozen_projection` を製品資産へ向け直す形は tombstone ではなく「対応が残るケース」の正規の扱い**で、`:577` に当たらない。**採否は TSK-443 の計画レビューと人間の判断。**

### D6(識別値母集団の是正)を送り出した

**`previous_baseline_identifiers` が `sorted(head_components)` で作られ、比較元にあって HEAD に無い資産を母集団から落とす**(条文 `:588` に違反する)。

**ただし本 PR の本番経路では到達しない**(`load_contract` か削除拒否が先に落ちる)。**到達不能な変更をコア領域の PR に入れない**という判断で **TSK-452 へ送った**。**本 PR は `frozen_history.py` を 1 バイトも変えない。**
