## 決定

### PO 裁定(2026-09-12・山田正輝)

**3 件とも推奨どおり。条文化の乗り物も決まった。**

| 裁定 | 決定 | 不採用案とその不採用理由 |
| --- | --- | --- |
| **A** 適用単位 | **経路単位** — 12-4 のゲートは**当該 PR が開く経路について**判定する。対象横断の `NFR-019(b)` 網羅と「`NFR-010` 適合」の宣言は**リリース候補時の受入**(要件書 `:957`)で行う | **「対象横断のまま」を不採用**。採ると最初の 1 本が永久に条件を満たせず、循環が解けない。別の手(例外規定・段階化)が必要になり、いずれも確定ゲートを伴う |
| **B** 測定経路 | **同一 PR に含める** — 「アプリ経路だけの検証では通過にしない」は、**HTTP 経路を開く PR がその経路の直叩きテストを同一 PR に含める**ことをもって充足とする。**HTTP 経路を開かない PR には空の要求として掛かる** | **「全経路の網羅を要求」を不採用**(`data-model.md:246` の読み)。採ると API が無い現在は通過できず、最初の 1 本を通すのに例外規定か段階化が別途必要になる |
| **C** 所有者 | **各 FR の実装タスク**が自経路の HTTP 越境テストごと持つ。**TSK-217 は対象横断の判定とハーネスの所有者として残し**、前提「FR-041 の実装が先。実装がないと構成できない」を**「FR-041 の実装 PR と同一変更」へ訂正**する | **「単一の API 実装タスク」を不採用**。契約の一貫性は 1 タスクで担保できるが、**そのタスク自身が最初のゲート通過の当事者になり、A・B が否決されると詰まる**。今回は A・B が通ったので致命ではないが、**per-PR の裁定 A と揃う方が構造が単純**である |
| **条文化の乗り物** | **⑦ ADR-004 の新設 + 12-4 の追随を同一の確定ゲートで通す** | **② 12-4 の単独改訂を不採用**。確定ゲートの回数は同じ 1 回だが、**ADR は 7.2 の表で「必須(軽量版可)」**なのでレビュー面が小さい。加えて**裁定の理由が ADR という恒久記録に残る**(単独改訂だと変更履歴にしか残らない)。先例は ADR-003 の「本 ADR と**同一の確定ゲート**で要件書 v2.2 として改訂する」 |

**`S-4` の「12-4 節冒頭の旧文言の現況化」を同乗させる**(⑩ の却下で受け取り手が無いことが
判明したため)。

### 裁定の射程 — 今すぐ何かが動き出すわけではない

**通過条件①(RLS のポリシーとロールの DDL が実スキーマへ適用)は未充足**であり、
**その産出者は TSK-317(進行中)**である。**律速は裁定ではなく TSK-317。**
本裁定は**①が充足した直後に詰まらないための先回り**である。
