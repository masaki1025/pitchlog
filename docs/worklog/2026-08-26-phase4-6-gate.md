### systemd の `user@1000.service` が新規ディストリで failed のまま復帰しない(無害と判断・2026-08-27)

- 事象: 0 章で作成した `Ubuntu-26.04` の**初回起動**と **`wsl --terminate` 後の再起動**の両方で `wsl: Failed to start the systemd user session for 'ymdms'` が出る。`systemctl --failed` = `getty@tty1.service` + `user@1000.service`・`is-system-running` = `degraded`。`systemctl reset-failed` + `start` でも復帰しない(`unavailable resources`)
- **原因は基底イメージの systemd の版**: 新規 `Ubuntu-26.04` = `259.5-0ubuntu3` / 開発環境 `Ubuntu` = `259.5-0ubuntu3.4`。`/etc/wsl.conf`・`getent passwd 1000` は両者同一で、差は systemd の版のみ。journal は `Failed to spawn executor: Device or resource busy` → `Start request repeated too quickly`
- **onboarding 1 章は `apt upgrade` を含まない**(1-1 は `apt update` + `apt install` のみ)ため、**逐語実行ではこの版差は解消しない**
- **無害と判断した根拠**: (1) `getty@tty1.service` の failed は**開発環境にも出る WSL2 の常態**である (2) `user@1000.service` は `systemctl --user` 用で、onboarding のどの章も使わない (3) 1-5 の daemon 起動判定は `[ -d /run/systemd/system ]` であり `degraded` でも真になるため `systemctl start docker` 経路を通る = **合格項目 4・5 に影響しない**
- **対処せず逐語実行を続行**した(`apt upgrade` を足すのは**手順の変更**にあたるため行わない)。合格項目 4・5 の実測で影響がないことを確認する
- **申し送り**: onboarding 0 章へ「初回起動でこの警告が出ることがある・無害・`systemd` の版差が原因」の注記を追記すべき。本 PR では `onboarding.md` を触れない(失効対象パス)ため**別タスク**で反映する
