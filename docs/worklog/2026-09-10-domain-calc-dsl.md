### P0-1: `bootstrapDebt` が正本にない exit 0 例外を導入している
- 分類: 非起因 / **(A)**
- 典拠: 要件書「正解ベクタが未整備の間…不合格として扱う」/ `ADR-003` D-7「PR 必須」「マージ不可」/ design.md §3-2「未達…0」「債務…0」
- 何が問題か: 全体適合判定が、未登録対象・未整備ベクタ・既知の宣言外入口を抱えたまま green になる。
  「充足を宣言しない」だけでは、正本が要求する不合格・マージ不可を exit 0 へ変更できない。
- どう直すか: `未達`・`bootstrapDebt` を許す移行状態、許容期間、昇格条件を ADR-003 と要件書へ明記し、確定ゲートを通す。

### P0-2: `bootstrapDebt` の全件性を確認する前に封印している
- 分類: 非起因 / (B)
- 典拠: design.md §4-1「承認時点…1 件も省略せず」「債務の追加は…禁止」/ plan.md ステップ 4 で封印し、ステップ 25 で未宣言項目を債務台帳へ載せる
- 何が問題か: 実在入口収集器と表示経路解析器はステップ 23〜25 なのに、台帳はステップ 4 で封印される。
  漏れを後段で発見すれば追加禁止に違反し、発見できなければ不完全な台帳のまま green になる。
- どう直すか: 入口・表示経路の監査専用収集器を封印前へ移し、その実測集合と台帳を exact-set 突合する。
  全行と digest を計画レビュー時点で提示し、後段は追加ではなく封印済み集合の再照合だけにする。

### P0-3: 網羅性の証明が自己作成の要求集合で false green になる
- 分類: 非起因 / (B)
- 典拠: `ADR-003`「丸め境界(直前・一致・直後)× 符号(正・負)は直積で必須」/ plan.md ステップ 13「8 軸すべてに case」「負値の丸め境界一致が存在」
- 何が問題か: 合格条件は 6 通りの直積を要求せず、負の一致 1 件と各軸 1 件で通る。
  要求集合と証跡集合を同時に欠落させても集合差は空になる。**旧 P0-3 は解消していない。**
- どう直すか: 正本 ID と schema 軸から coverage obligation を独立生成し、少なくとも `{直前,一致,直後} × {正,負}` の
  完全一致を assert する。各組合せを 1 件ずつ削る負例と、有限直積・境界分割・pairwise・条件付き軸の各生成方式の合成 fixture を置く。
