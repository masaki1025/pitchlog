## 経緯 — なぜ切り出したか

**送り元は TSK-386(PR #63)。** 同タスクは「凍結基準を検査器のソースから追い出す」もので、
**正本の条文と実装を同時に動かしていた。**

**実装の敵対レビューで 3 周連続 `P0`**:

| 周 | 判定 | 要旨 |
| --- | --- | --- |
| 1 | 否決 `P0 3 / P1 1` | 3 指定が宣言に無い / `7.7-4` の必須項目欠落 / `F-5` が到達可能性を見ない / 更新経路の閉塞 |
| 2 | 否決 `P0 3 / P1 2` | **宣言を足しただけで実装が使っていない**(`identity` をでたらめにしても通る)|
| 3 | 否決 `P0 2 / P1 2` | **比較関数を no-op にしても「実行済み」を出力する** |

**3 周とも同じ形だった** — **実装に「使った」と言わせる設計**で、**いずれも no-op で通った。**

**効いたのは `R-1` 型だけ** — **「宣言の要素を変えると挙動が変わることを変異で示す」**。
**自己申告は証拠にならない。** これが後継タスクへの最大の申し送りである。

**あわせて develop が 104 コミット進み、`oracle_commit` が `24ef4fc…` と `b64fdef…` で食い違った。**
**版番号も衝突した** — **`v1.15` は TSK-355 が取得して develop へマージ済み**。
