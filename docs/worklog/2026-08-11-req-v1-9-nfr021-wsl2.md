## 決定

- **要件書 NFR-021 を WSL2 前提へ追随させる**(ハーネス設計者の了承 2026-08-11)。文言は設計書側の既定解釈(変更履歴 v0.11「WSL2 を含む Windows 11 上で完結」/ 論点C「セットアップ再現手順は onboarding.md が正」)に合わせる。Must 要件の文言変更にあたるため **v1.9 として確定ゲートを通す**
- **ゲート経路は要件書へ単独で /finalize-doc を回す**。要件書 v1.8 行(:18)は「ハーネス設計書の確定ゲートで一括検証する」と書くが、要件書の frontmatter は現在も `status: in-review` であり一括検証は行われていない。**根拠は「設計書のほうが後発だから」ではなく(両記録は同日 2026-08-07)、正本更新ゲートの唯一の決定表である設計書 7.6 と現在の in-review 状態**(計画レビュー 1 周目 P1-3 で訂正)。なお **v1.8 行は原文のまま保存**し、訂正内容は v1.9 行に記録する(変更履歴は遷移履歴であり過去行を書き換えない — 設計書 7.1-4)
- **win-setup のランナー選定は Phase 4 へ申し送る**。/research の結果、`windows-latest`(Server 2025)では WSL2 は動くが GitHub は入れ子仮想化を「experimental / at your own risk」= 公式サポート外と明記しており、必須の継続検証基盤には不適切。本タスクでは設計書 10.1 の win-setup 行を「**ランナー未決・Phase 4 で選定**」へ訂正する(`windows-latest` の固定指定を残さない — 計画レビュー 1 周目 P1-5 で訂正)。あわせて参照先を README → onboarding.md に直す。ランナー候補(ubuntu-latest 主 / windows-2025 を非必須併用 / self-hosted / 手動)と根拠は research.md に記録
- **要件書の測定方法は CI 方針に依存させない**: 他 NFR と同様「何を測るか」の粒度で書く(= 「WSL2 クリーン環境でのセットアップ再現」)。ランナー選定は設計書 10.1 の役割
- **開発 DB(PostgreSQL)の設置場所を WSL2 内へ統一**(人間の裁定 2026-08-11・計画レビュー 4 周目 P1-1)。「WSL2 必須」と裁定しながら要件書 NFR-021・7.1(`:739`)・改善台帳(`:58`)が「**Windows ネイティブ版** or Docker」を残しており、排他性が不十分だった。実装側の文書はすべて Docker 前提(設計書 `:209` 5.3「開発環境は docker-compose.yml」/ `:153` / `:676` / `AGENTS.md:33` / `onboarding.md:32`)で Windows ホスト上の PostgreSQL はどこも採っていない。**要件レベルでは「WSL2 内のネイティブ導入 or Docker」と許容幅を残し、Windows ホスト側だけを排除**する。設計書 5.3 の Docker 選択は変更しない。**改善台帳が 4 件目の影響正本**になる
- **改善台帳の該当箇所は「文言の書き換え」ではなく「要件書への参照に置換」する**(人間の裁定 2026-08-11・計画レビュー 5 周目 P1)。レビューは「I-6 の変更対象は pitchlog が許容する開発 DB 配置という方針そのものだから確定ゲートが必要」と指摘したが、構造を確認すると `:58` の「開発は Windows ネイティブ版 or Docker」は**要件書 NFR-021・7.1 の内容の複製**であり、docs 規約第 1 項「**1テーマ1正本・内容を複製しない**」に反している。I-6 の改善の核心は「SQLite/PostgreSQL 二重運用をやめ PostgreSQL に一本化」であって設置場所は付随記述。**参照化により方針を持たない形に変える**ことで、(a) 規約違反の重複が解消し (b) 今後 NFR-021 が変わっても台帳の追随が不要になり (c) 節更新(PR レビュー)として筋が通る。なお改善台帳は**変更履歴表を持たず版管理もしていない**(索引の版も「—」)ため、確定ゲートを回しても版繰り上げの概念が存在しないという事情もある
- **Windows ネイティブ開発は認めない — WSL2 必須に統一**(人間の裁定 2026-08-11・計画レビュー 3 周目 P1-2)。設計書 `:668`「WSL1 非対応のため**必ず WSL2**」・論点C の PO 決定・`onboarding.md` 0 章が WSL2 を必須項目化・Codex の bubblewrap が WSL1 非対応・実環境も WSL2 — の 5 点で整合。**論点C 改訂(ネイティブ継続 → WSL2 移行)前の前提が 3 箇所に残っていた**ため除去する: 設計書 `:418`・`:517` の「Windows sandbox 設定」言及と `setup-dev/SKILL.md:19` の「ネイティブ例外時のみ `[windows] sandbox = "elevated"` を提案」。NFR-021 の確定文「WSL2 を含む Windows 11 上で完結」はこの裁定と両立する
