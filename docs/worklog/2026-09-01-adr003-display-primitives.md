### 2 周目の P0 2 件(未反映 — 再開時に対応する)

| # | 内容 |
| --- | --- |
| 1 | **ステップ順序が機構的に成立しない** — ステップ 2 で母集合を追随しても、**確定ゲートで要件書の版・変更履歴・status が変わるため blob digest が必ず古くなる**。かつ**正本を編集した後で `approved → in-review` とする順序は 7.3 の状態遷移と逆**。**是正案**: ①両正本を先に `in-review` へ ②改訂と敵対レビューを完了 ③人間承認後に版・変更履歴・索引を確定したコミットを作る ④**その最終コミットの要件書 blob に対して母集合を追随** ⑤全 checker green。**あわせて甲-3 は「非推奨」ではなく選択不能**(P0 7 件を残した母集合を再封印するため) |
| 2 | **`(β)` の証跡モデルに収まらない** — SQL target は構造化数値まで / Python target は DB 集計経路を通らない / **製品経路の `SQL → Python表示` 全体と一致する直接 target がない**。**是正案**: `(β)①〜⑤` の direct target を「**生成 SQL → 型付き受け口 → 生成 formatter までを実行する 1 つの複合 target**」として D-11 で再定義し、**`directTargets[]` を単数参照から順序付き複数参照へ変更**する |

**1 周目 P0 の判定**: P0-1(完成表示値が確定しない)= **解消** / P0-2(`(β)` の生成先)= **部分的**。
