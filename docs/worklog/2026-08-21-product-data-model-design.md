## 決定

### 調査の裁定 2 件(原典で確認)

1. **旧資料のテーブル数の矛盾は矛盾ではなかった** — `data-layer.md:3` は 12 テーブル・`db-structure.md:17` は 13 個で `game_lineup_snapshot` の有無が食い違うが、**`db-structure.md:8` 自身が「88 列の実際の意味・値例・移行の罠は `research/data-layer.md` が正本。本書は構造の俯瞰図であり、移行変換層の実装は data-layer.md を正として行う」と優先関係を明記**していた。テーブル数の差は**対象リポジトリと時点が違う**ため(`C:/develop/baseball_system/` vs `Baseball_Scoring` develop HEAD `ed6a20f`)。`game_lineup_snapshot` は FastAPI 新 UI 期に追加されたテーブルで、**要件書 REQ:960 が既に「アーカイブ後に追加された領域」として未確定登録済み**
2. **「当時の値で表示」の対立も対象違い** — 遡及しないのは**背番号と適用規則**(4.0-2 が名指し)、遡及するのは**語彙の表示名**(4.0-3 が名指し)。**「試合ごとに語彙スナップショットを永続化する」という要求は要件書に存在しない**(全走査して 1 箇所のみ = NFR-019 のテスト入力面)。ADR-003 `:96` も「写像テーブルに焼き込むことは禁止」と明記

### Web 調査で設計を左右した事実(原典で確認)

**PostgreSQL 公式が「参照整合性検査(一意制約・主キー・外部キー参照)は常に RLS をバイパスする」と明記している**(`https://www.postgresql.org/docs/17/ddl-rowsecurity.html`)。テナント跨ぎの一意制約を置くと、**RLS を有効にしても制約違反エラーから他テナントの行の存在が推測できる**。要件書 REQ:823 は「**内容・存在を含め参照できない**」を要求しているため、**一意制約をテナント内に閉じる**必要がある。

あわせて確認: **RLS は PostgreSQL 9.5 からのコア機能**(Supabase 固有ではない)→ 要件の「標準 PostgreSQL の範囲」に適合 / バイパス経路は superuser・`BYPASSRLS`・**テーブル所有者(既定でバイパス)** / **transaction pooling では `set_config(..., true)`(transaction-local)をトランザクション内で発行する**(第 3 引数の意味も原典で確認)。

### 自分の判断ミス 4 件(1 周目で是正)

1. **テナント跨ぎの FK を一律禁止していた** — 一意制約の漏洩と FK 一般を混同。**FR-041 の制御資源は複数テナントに跨る関係を持つのが要件**(REQ:824「記録・集計とは別のクラス」)で、禁止すると要件が表現できない。→ 論点 2 を一意制約に限定し、**制御資源の表現を論点 12 として新設**
2. **ADR-003 が既に固定した切り分けを未決論点に戻していた** — 「プレイ行と操作イベントのどちらが正か」は ADR-003 `:93-104` が「確定イベントを持ち現在状態・成績は導く」と固定済み。決めてよいのは**永続化上の表現**だけ
3. **88 列対応表を移行仕様タスクへ送る根拠が誤っていた** — REQ:960 が送っているのは**カットオーバー日と追加領域の線引きだけ**。付録D-1(REQ:1180)は各列の意味欄に「新スキーマの行き先・変換規則」を要求している(原典で確認)。**受け皿の欠落は論理モデルの作り直しになる**ので (A) に格上げして本タスクに含めた
4. **成果物が宙に浮く構成だった** — 設計書 7.6-4 が `docs/features/<slug>/` を「活動中のみ意味を持つ一時ディレクトリ」と定めているのに、12 件の決定をそこに置いて閉じる計画だった。→ **成果物を「候補案」に降格**し、**正本化タスクの起票と相互リンクを DoD の必須項目**に(設計書 `:825` の 4-6 → `P4-後` と同じ形)

### 逆方向の是正 1 件

**事前集計の採否を (A) → (B)**。私は「後付けは NFR-003 の共有画面条件と衝突する」と考えていたが、**NFR-005(REQ:795)は事前集計の採用可を「毎球参照される画面に限り」と限定**しており、共有画面性能を理由に先に採ると**逆に許容範囲を踏み外す**。今決めるのは再計算可能性と 14 トリガーの無効化契約まで。
