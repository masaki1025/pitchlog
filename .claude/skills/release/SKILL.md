# リリース(設計書 6.4 / 要件書 8 章)

## 0. NFR-021 受入証跡ゲート(fail-closed — 設計書 10.1)

**他のどの手順よりも先に実行し、通らなければ即座に中断する。**

1. 証跡の機械検証器(`scripts/verify_nfr021_evidence.py`。**Phase 4 の成果物**)の存在を確認する
   - **存在しなければ中断**する。「NFR-021 受入証跡の検証器が未実装のため、プロダクトリリースは行えません(設計書 10.1・Phase 4 成果物)」と報告し、**以降の手順へ進まない**
   - ※ これは Phase 4 完了までの**暫定ゲート**であり、検証器の実装後は「検証器を実行し合格を確認する」に置き換える
2. 検証器がある場合は `候補 SHA(develop の HEAD)・ゲート種別 release・要求版 vX.Y.Z` を入力して実行し、**合格しなければ中断**する

> ハーネス確定ベースラインの `develop → main`(設計書 6.4 の 1 回限りの例外)は**リリース非該当**のため本ゲートの対象外。既に使用済み・失効している。

## 手順

1. **DoD チェック**: 要件書 8 章の判定基準 8 項目(Must充足 / CI全グリーン / 実戦リハーサル / 性能実測 / 移行完了 / バックアップ復元リハーサル / ドキュメント現行化 / 未決事項の決着)を 1 項目ずつ、根拠(テスト結果・文書リンク)付きで確認する。未達があれば**中断**して残作業を列挙する
2. 全項目 OK なら**人間にリリース可否の判定を明示的に求める**(判定者 = システム管理者。要件書 8 章)
3. 判定 OK 後:
   - `gh pr create --base main --head develop`(タイトル: `release: vX.Y.Z`)
   - CI 全グリーンと人間のマージを確認
   - `git tag vX.Y.Z` → `git push origin vX.Y.Z`(承認付き)
4. リリース記録を worklog と Notion に残す(日時・バージョン・DoD 根拠へのリンク)
