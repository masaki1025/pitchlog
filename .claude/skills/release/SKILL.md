# リリース(設計書 6.4 / 要件書 8 章)

## 0. NFR-021 受入証跡ゲート(fail-closed — 設計書 10.1)

**他のどの手順よりも先に実行し、通らなければ即座に中断する。**

**Phase 4 完了までは無条件で中断する。**「NFR-021 受入証跡の検証器が未実装のため、プロダクトリリースは行えません(設計書 10.1・Phase 4 成果物)」と報告し、**以降の手順(DoD チェック・人間判定・PR 作成・タグ)へ進まない**。

- **`scripts/verify_nfr021_evidence.py` の有無で分岐しない** — 作業ツリーに同名ファイルがあるだけで開く条件にすると、Phase 4 作業中の未コミット・スタブの検証器でゲートが開いてしまう(判定コード自身が候補 SHA の外にあれば fail-closed にならない)
- 本手順を検証器の実行へ置き換えるのは **Phase 4 の PR(レビュー付き)でのみ**行う。置換後の要件は設計書 10.1(検証器の契約・候補 SHA の固定)に従い、少なくとも **① `candidate_sha` を完全な commit OID で固定 ② 候補 SHA に収録された検証器と実行する検証器の blob 一致を確認 ③ `候補 SHA・ゲート種別 release・要求版 vX.Y.Z・evidence_path` を入力して実行し、合格しなければ中断**すること

> ハーネス確定ベースラインの `develop → main`(設計書 6.4 の 1 回限りの例外)は**リリース非該当**のため本ゲートの対象外。既に使用済み・失効している。

## 手順

1. **DoD チェック**: 要件書 8 章の判定基準 8 項目(Must充足 / CI全グリーン / 実戦リハーサル / 性能実測 / 移行完了 / バックアップ復元リハーサル / ドキュメント現行化 / 未決事項の決着)を 1 項目ずつ、根拠(テスト結果・文書リンク)付きで確認する。未達があれば**中断**して残作業を列挙する
2. 全項目 OK なら**人間にリリース可否の判定を明示的に求める**(判定者 = システム管理者。要件書 8 章)
3. 判定 OK 後(**SHA を固定して進める** — 設計書 10.1「候補 SHA の固定」):
   - `gh pr create --base main --head develop`(タイトル: `release: vX.Y.Z`)
   - **PR 作成直後**に `origin/develop` と PR head が手順 0 で固定した `candidate_sha` と一致することを再照合する。**動いていれば中断**し、新しい SHA で NFR-021 受入からやり直す
   - CI 全グリーンを確認 → **マージ直前にもう一度同じ再照合**を行ってから人間のマージを依頼する
   - マージ後、**main のマージコミットが `candidate_sha` を第 2 親に持ち、ツリーが `candidate_sha` と一致する**ことを確認する
   - `git tag vX.Y.Z <検証済みの main マージ SHA>`(**対象 SHA を明示する** — 現在 checkout 中の別コミットに付かないように) → `git push origin vX.Y.Z`(承認付き)
4. リリース記録を worklog と Notion に残す(日時・バージョン・DoD 根拠へのリンク)
