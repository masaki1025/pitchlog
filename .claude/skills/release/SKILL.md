**本手順が検証器の実行へ置き換えられるまでは無条件で中断する。**(**設計書 v1.7 で「Phase 4 完了までは」から改めた** — Phase 4 の完了と手順 0 の置換は**別の時点**であり、**完了しても置換前なら中断を続ける**。時点ではなく状態で判定する)**報告文は状況で使い分ける**: **検証器が未実装なら**「NFR-021 受入証跡の検証器が未実装のため、プロダクトリリースは行えません(設計書 10.1・Phase 4 成果物)」/ **検証器は実装済みだが本手順が未置換なら**「NFR-021 受入証跡の検証器は実装済みですが、`P4-後` による手順 0 の置換が未了のため、プロダクトリリースは行えません(設計書 13 章)」と報告し(**検証器実装後・`P4-後` 前の期間に「未実装」と誤報しないため** — v1.7・確定ゲート 7 周目 P2)、**以降の手順(DoD チェック・人間判定・PR 作成・タグ)へ進まない**。

## 手順

1. **DoD チェック**: 要件書 8 章の判定基準 8 項目(Must充足 / CI全グリーン / 実戦リハーサル / 性能実測 / 移行完了 / バックアップ復元リハーサル / ドキュメント現行化 / 未決事項の決着)を 1 項目ずつ、根拠(テスト結果・文書リンク)付きで確認する。未達があれば**中断**して残作業を列挙する
2. 全項目 OK なら**人間にリリース可否の判定を明示的に求める**(判定者 = システム管理者。要件書 8 章)
3. 判定 OK 後(**SHA を固定して進める** — 設計書 10.1「候補 SHA の固定」「残余リスク」):
   - `gh pr create --base main --head develop`(タイトル: `release: vX.Y.Z`)
   - **PR 作成直後**に、ローカル追跡参照ではなく **GitHub API から PR の `.head.sha` / `.base.sha` を再取得**し、手順 0 で固定した `candidate_sha` / `base_sha` と一致することを照合する。**動いていれば中断**し、新しい SHA で NFR-021 受入からやり直す
   - CI 全グリーンを確認 → **排他管理者(= 8 章の判定者 = リポジトリ所有者)に排他区間を宣言してもらう**: 最終照合からマージ完了まで、**当該リリース PR のマージ以外に `main`・`develop` を進める操作を一切行わない**(直接 push だけでなく **GitHub UI/API による他 PR のマージ**・Web エディタ編集・bot/Actions による更新を含む — UI マージは push ではないので「push 禁止」では不足)。**開始を当該 PR へコメントで記録**し、書込み権限を持つ関係者へ周知する(**ブランチ保護は 2026-09-19 に適用済みだが、保護は「最終照合からマージ完了までの間に base が動かないこと」を保証しない**ため、排他区間は機構では強制できない — 設計書 10.1 残余リスク)
   - **マージ直前にもう一度同じ再照合**を行い、**期待 SHA 付きで原子的にマージ**する: `gh pr merge --merge --match-head-commit <candidate_sha>`(base 側は拘束できない点に留意)
   - マージ後、**第 1 親 = `base_sha`・第 2 親 = `candidate_sha`・ツリー = `candidate_sha` のツリー**を確認する。**不一致なら未検証内容が main に入っている** — タグを打たず、直ちに人間へ報告する
   - **検査完了(または中断)をもって排他区間の解除を宣言し、当該 PR へ記録する**。時間切れ・照合不一致のときは解除したうえで NFR-021 受入からやり直す
   - `git tag vX.Y.Z <検証済みの main マージ SHA>`(**対象 SHA を明示する** — 現在 checkout 中の別コミットに付かないように) → `git push origin vX.Y.Z`(承認付き)
4. リリース記録を worklog と Notion に残す(日時・バージョン・DoD 根拠へのリンク)
