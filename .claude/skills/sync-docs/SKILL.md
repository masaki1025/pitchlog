# 正本への反映(設計書 7.6)

実装が /check に合格した後、/pr の前に実行する。正本が実装と乖離して腐るのを防ぐ必須ステップ。

## 手順

1. 計画書 3 節「影響する正本」の表を読む(**「反映なし」明記ならその根拠を再確認して終了** — 実装中にスコープが変わって正本影響が生じていないか差分を見て検算する)
2. 宣言された正本を**同じ feature ブランチ内で**作成・更新する:
   - **実装追随の節更新** → 本スキル内で更新し、**変更履歴表に必ず追記**する
   - **版繰り上げを伴う構造的変更**(アーキテクチャ・スキーマ・要件改訂) → /finalize-doc の確定ゲート(敵対レビュー → 人間承認)へ回す
   - **新設 ADR** → `docs/development/templates/adr-template.md` から作成し /finalize-doc へ
3. `docs/README.md`(索引)の該当行(状態・版・最終更新)を現行化する
4. 「宣言 → 実施」の対応表を報告する(/pr がこの突合を再確認する)

## 規律

- 正本の内容を feature 文書へコピーしない(1テーマ1正本)
- 宣言にない正本を勝手に書き換えない。必要が生じたら計画書 3 節を先に更新してから反映する
