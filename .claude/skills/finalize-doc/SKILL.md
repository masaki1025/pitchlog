# 正本確定ゲート(設計書 7.3)

**敵対レビューを経ずに approved にする経路は存在しない。** 規範(適用版・回数上限・終端遷移・重大度定義・レビュー範囲・依頼文規約・PO 裁定・残余リスク)の正は**設計書 6.3「レビュー回数の上限」と 7.3(7.3-1〜7.3-8)** — 本書は手順だけを定め、内容を複製しない。**適用版 = 初回敵対レビュー実行時点で approved の 7.3 の版**(7.3-1 の唯一の定義 — 7.3 自身の改訂ゲートでは改訂中の版が in-review のため自動的に直前 approved 版になる)。**版数と条文コミット SHA を手順 1 の in-review 化と同一コミットで worklog へ暫定記録し、初回敵対レビュー実行時点で異なっていれば更新してから開始する**。当該ゲートは適用版で最後まで運用し、途中で切り替えない。運用は**記録した適用版の条文**に従う — 本書の手順と条文が食い違う場合は**条文が優先**する(節番号の存否で判定しない。スキルを先に改訂しても未承認規則は自己適用されない — v1.13 以降も同じ)。

## 手順

0. **射程宣言の確認**(7.3-7): 射程宣言(「本書で確定する範囲/実装時に確定する範囲」)があることを確認する — **新設の正本は文書内の節・既存正本の改訂は当該改訂の変更履歴行(in-review)に記載**。なければ追加してから開始する
1. 対象(一括検証は全対象 — 単一ゲート・記録は 1 件)の変更履歴表/frontmatter を `in-review` に更新し、**適用版(7.3 の版数+条文コミット SHA)の worklog 暫定記録を同一コミットに含める**(7.3-1 — 初回敵対レビュー実行時点で暫定と異なれば更新してから開始する)
2. 敵対レビューを実行する: `python .claude/scripts/codex_run.py review adversarial -`(モデル・effort はラッパーが ADR-001「決定」節の「敵対レビュー・コア領域 PR・正本確定ゲート」行どおりに固定)。**回数は設計書 6.3「レビュー回数の上限」に従う — 1 回目 = 全文 / 2 回目 = 1 回目の反映差分と影響節 / 2 回目に P0 が残り 1 件以上採用したときだけ 3 回目 = P0 限定の差分(自動)/ それ以外の追加は PO 裁定 1 回につき 1 回(範囲は裁定で指定。続行指示は P0 限定で最大 N 回を包括可)**。依頼文は **7.3-5 の規約**に従う:
   - **冒頭に命令文**「実際にレビューを実施し、次周の依頼文を作らず、判定を返すこと」を置く。3 回目(P0 例外)は「P0 のみを判定し P1/P2 を報告しないこと」を命令文に含める
   - **本周の回数(N 回目 / 枠)と対象範囲(全文 / 反映差分 + 影響節 / P0 限定)**を明記する
   - **7.3-3 の重大度定義**を毎回組み込み、**反例・事実には典拠(ファイル:行)を付けること**を要求する
   - 2 回目以降は前周指摘の全文並記をしない(7.3-4)。終結済み一覧と未終結の不採用一覧(所在〔節・行〕つき・維持/取り下げの明示を要求)を添付する(7.3-5)。反映差分がない周の対象は未終結の不採用の所在箇所と影響節(7.3-4)
   - 応答様式(各指摘に `P0|P1|P2` + `起因|非起因` + `(A)|(B)|(-)`、最終行に判定行)を明記する(7.3-5)。**判定行のない応答・判定行と件数が矛盾する応答は周として数えず、同一周を再依頼する**
3. 指摘を「採用(反映内容)/不採用(理由)」に分類し、**採否記録を worklog へ周ごとに追記して当該周のコミットに含める**(7.3-2 の定義: 要旨・重大度・起因・(A)/(B)/(-)・採否と理由・(B) の送り先・反例の典拠確認 — 中断時にも採否と申し送りを復元できるようにする)。処理は **7.3-2 の終端遷移表に従う**((B) の扱い・**P0 を全件不採用にするときのその場の PO 判断**・対象が空の自動周の省略・上限到達時の終端を含む)。**作成者判断のみの不採用は終結ではなく、人間承認の場で PO が支持 / 採用指示を判断する**
4. **6.3 の上限内で 2〜3 を繰り返す**(基本 2 回・P0 例外で 3 回・PO 裁定分)。**採用反映を伴う** 1 周ごとに、**実行中 feature の plan.md** の frontmatter `確定ゲート周回` を +1 する(指摘なし・全件不採用の周は数えない。更新先 = 実行時 worktree の `docs/features/*/plan.md` で status が active|in-review かつ branch が worktree と一致するもの。一意に解決できなければ人間に確認 — 黙って省略しない。キーが無い旧 plan は `0` を追記してから更新する)
   - **反映周ごとに 1 コミットを作る**(設計書 6.1)。件名に **`反映<r>周目`**(`<r>` = 加算後のカウンタ値)を含め、**ステップ記法を付けない**。例: `docs: 確定ゲート 反映2周目 — 指摘 4 件を反映`。**`確定ゲート` を含むだけの件名は反映周コミットとみなされない**
   - **PO 裁定**(7.3-6): 作成者または PO はいつでも即時裁定を起動できる(起因の反復が見えた時点・射程変更の必要が判明した時点・P0 の全件不採用)。裁定の選択肢 = 追加レビュー(範囲指定・射程不変)/ 続行指示(P0 限定・最大 N 回)/ 射程縮小 / 範囲確定 / 取り下げ。裁定と範囲・N を worklog に記録する。**射程が変わった場合は変更範囲と理由を変更履歴と worklog に記録し、次周の範囲は裁定で指定する**(自動の全文は 1 回目のみ)
   - 上限到達・3 回目で P0 残存・P0 の全件不採用は、いずれも人間(PO)の判断へ上げる(7.3-2 の表)
5. 採用/不採用の一覧と、反映周コミットがある場合は**最終反映の差分(最後の `反映<r>周目` コミット — Codex の再レビューを受けていない)**を提示して**人間の承認を明示的に求める**(曖昧な同意で進めない。1 回目で指摘ゼロなら反映周コミットは無く、一覧のみを提示する — 7.3-2)。承認者は不採用の支持 / 採用指示、または追加レビュー(範囲指定)の裁定を行う(採用指示分の反映は再レビューしない — 7.3-8)
6. 承認後: 状態を `approved`・版数確定・変更履歴表に追記・`docs/README.md` 索引を現行化する
7. レビュー往復の要点(重要指摘と対応・警告/エスカレーションの発動有無)を worklog に記録する

- 判定行・起因フラグ・回数上限の遵守・PO 裁定の紐づけは**運用規律であり機械検証されない**(7.3-8 — 欠けても CI は green になり得る。手順で守る)。上限到達時の最終反映は Codex の再レビューを受けないため、承認時の差分確認で受ける
- 指摘反映で**コード修正**が必要になり、かつ実行中 feature の plan が `in-review`(PR 段階)の場合は、先に /pr の「差し戻しが発生したら」手順で `status: active` へ戻してから /implement する(`codex_run.py implement` は `active` 以外を拒否する — 設計書 6.1 差し戻しの往復)
